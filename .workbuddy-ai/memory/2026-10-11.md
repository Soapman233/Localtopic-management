- **🔴 实现期发现并修复 3 个真实缺陷（均已成回归测试）**：
  1. **MathType 填充空格泄漏**——`{ \rm{ k } }{ \rm{ g } }` 渲染成 `k g` 而非 `kg`；根因是 MathType 的填充空格是**记号分隔符不是真实空格**。**发现方式：渲染出来看**（单测测不出）。
  2. **`^` 错误绑定到空格**——`} ^ {` 导致 `sSup` 绑到空格、`10³` 丢失；根因是 **LaTeX 数学模式中空白不显著**，解析器须跳过纯空白 token。**发现方式：dump 实际 OMML 对比**。
  3. **单字符脚标贪婪吞掉后续 `^`**——`x_i^2` 错成 `sSub(x, sSup(i,2))` 而非 `sSubSup(x,i,2)`；根因是 `parse_script_arg` 无花括号分支误用 `parse_atom()`（会贪婪），应用 `parse_base()`。**发现方式：单元测试**。
  - **共同教训**：三个缺陷都不是"逻辑写错"，而是**对真实输入形态的假设错了**。语料是脏的（MathType 风格 / 损坏字符 / 非常规写法），**必须用真实数据测，不能只用自己构造的干净样例**。
