### 🔴 实现期发现并修复的 3 个真实缺陷
1. **打包后数据会写进临时目录（退出即丢）**：冻结后 `ROOT = Path(__file__).parent.parent` 解析到 **`_MEIPASS`**，`outputs/bank.db` 写进去退出即删。修：`DATA_ROOT` 由启动器钉到 exe 所在目录。
2. **首启被「库不存在→拒绝启动」挡住**：`webui/__main__.py` 原本要求用户"去命令行跑 `bank.cli init`"——**对老师是不可能完成的动作**。修：自动建库 + 引导文案。
3. **`with sqlite3.connect(...)` 不关闭连接**：该写法**只提交/回滚事务、不关闭连接**，句柄泄漏导致 Windows 上备份文件无法删除/覆盖（测试清理阶段直接 `PermissionError: Win32`）。生产上表现为**恢复操作被自己的旧句柄阻塞**。修：`contextlib.closing(...)`。

### 附带修复（前一轮遗留）
- **预览缓存 key 不含引擎维度**：缓存 key 由 `{content_digest, content_guard_revision, layout_revision}` 决定，**与引擎无关** → 切换 `QB_EXPORT_ENGINE` 后**继续复用旧引擎产物且从文件名/大小看不出差别**（实测踩过）。修：key 与 meta 并入 `export_engine`；`validate_meta` 对缺该字段的**旧缓存判过期**；补测试 `test_preview_cache_without_engine_is_stale` 固定该行为。
  - **⚠️ 测试坑**：`TestClient(app)` 默认 `raise_server_exceptions=True`，会把经通用 `Exception` 处理器映射的异常**重新抛出**；要断言 409 必须用 `TestClient(app, raise_server_exceptions=False)`（既有 `test_export_content_p0.py:149` 就是这么写的）。

## 🔴 热修：打包版「双击即崩」+ 验证盲区（用户反馈后修复）

### 用户报的问题（产品完全不可用）
```
AttributeError: 'NoneType' object has no attribute 'isatty'
  File "uvicorn\logging.py", line 42, in __init__
ValueError: Unable to configure formatter 'default'
  File "webui\__main__.py", line 141, in main
```

### 根因
`console=False` → exe 的 **PE 子系统是 `WINDOWS_GUI`**（实测 `Subsystem = 2`），
**任何启动方式都不分配控制台** → `sys.stdout`/`sys.stderr` 为 `None`
→ uvicorn 配日志时执行 `sys.stdout.isatty()` → **崩溃**。

### 🔴 我的验证为什么没发现（**方法论问题，比 bug 本身更重要**）
**我确实「验证过」打包版**——启动 exe、探接口、跑完整 13 项端到端，**全绿**。
**但每次启动都经由 shell / 后台任务，进程继承了有效输出句柄**，`sys.stdout` 不为 `None`，
于是**双击路径根本没被覆盖**。
> **失败模式**：不是"没验证"，而是**验证条件与真实使用条件不一致**。「能启动」≠「用户那样启动也能启动」。

### 反证过程也踩了一次坑（二次教训）
第一版复现脚本传了 `stdout=subprocess.DEVNULL` —— **等于给了它有效句柄**，旧 exe 照样跑，反证失败。
去掉后（`DETACHED_PROCESS` + `close_fds=True` + **不传任何 std 参数**）才复现出崩溃。
> **教训**：构造反例时，**"模拟条件"本身也要被验证**，否则会得出"没问题"的错误结论。

### 修复（`editions/local/portable_main.py`）
1. **`_ensure_streams()`**：`stdout`/`stderr` 为 `None` 时接到 `<数据根>/outputs/webui/start.log`
   （`buffering=1`）。**必须在 `main()` 最先执行，早于 `import webui`/uvicorn**。
   顺带解决了 Phase 3 交接里标记为风险的「首启无日志」。
2. **`_fatal()`**：致命错误写日志 + **MessageBoxW 弹窗**告知用户 + 日志路径；
   `main()` 用 `try/except BaseException` 包住整个启动流程（不再静默退出）。
3. 排查：全项目 `isatty`/`sys.stdout` 依赖已 grep，其余为 `print(..., file=sys.stderr)`（对 None 安全）。
