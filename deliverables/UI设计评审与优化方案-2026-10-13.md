## 2. 本轮新发现（按严重度）

### 🔴 F1 — 深色模式「白底白字」，内容完全不可见

**证据（实测）**：
- 位置：`/manage/formula-review` 右侧详情面板内的公式预览容器。
- 探针实测：该元素 `color: rgb(255,255,255)`，最近不透明祖先背景 `rgb(255,255,255)` → **对比度 1:1**；字号 16px，`rect = [606, 584, 702, 105]`（在 1366×768 视口内）。
- 截图：`1366x768-dark/06-manage-formula.png` 中该区域是一块**纯白矩形、无可见文字**；同位置在 `1366x768-light/06-manage-formula.png` 里正常显示预览图与说明文字。

**根因（一行）**：
```tsx
// frontend/src/pages/FormulaReviewPage.tsx:64
<Box sx={{ mt: 1, p: 1, bgcolor: '#fff', border: '1px solid', borderColor: 'divider', borderRadius: 1 }}>
```
硬编码 `#fff` 不随主题切换；深色模式下 `text.primary` 变白 → 白底白字。

**同类排查**：全库仅 2 处硬编码浅色底——
- `FormulaReviewPage.tsx:64` `#fff` → **缺陷**（本条）
- `PreviewViewer.tsx:64` `#EDEFF2` → **不是缺陷**（A4 预览画布底衬，容器内只有白色纸面，无主题色文字）

**修法**：`bgcolor: '#fff'` → `bgcolor: 'background.paper'`（或 `'action.hover'`，视设计意图）。
**验收**：深色模式下对该 Box 断言「文字色 ≠ 背景色」且对比度 ≥ 4.5:1。

### 🔴 F2 — 主色回落旧值 `#3370FF`，系统性不达 WCAG AA

**证据（实测 5 页 × 2 主题）**：真实渲染文本中不达标的组合，**全部**指向同一个颜色 `rgb(51,112,255)` = `#3370FF`：

| 前景 | 背景 | 实测 | 需要 | 命中元素（示例） |
|---|---|---|---|---|
| `#FFFFFF` | `#3370FF` | **4.28:1** | 4.5 | AppBar 标题「初中物理 · 题库与组卷」(20px/500)、「试卷管理」、「加入」 |
| `#3370FF` | `#FFFFFF` | **4.28:1** | 4.5 | 「详情」(13px)、「标注」(12px)、「不支持」(14px)、「去处理 →」 |
| `#3370FF` | `#F5F6F8`（页面底） | **3.96:1** | 4.5 | 「筛选」、「题库统计」、「公式复核」、「来源文件」 |
| `#3370FF` | `#1E1E1E` | **3.89:1** | 4.5 | 深色下「详情」「不支持」「去处理 →」 |
| `#3370FF` | `#121212` | **4.37:1** | 4.5 | 深色下「筛选」「题库统计」「来源文件」 |

**根因**：`outputs/webui/settings.json` 存着 `"theme": { "primary": "#3370FF" }`，而 `theme.ts` 的 `buildTheme()` 对合法 hex **原样采用**：
```ts
const primary = /^#[0-9a-fA-F]{6}$/.test(color) ? color : tokens.primary
```
→ token 里精心下调过的 `#2F63EA`（白字 5.13:1 / 白底 5.13:1 / 页面底 4.74:1，见 `theme.ts` 注释）**从未生效**。

**⚠️ 诚实标注**：这**不是漏检**——`frontend/tests/visual/contrast-pairs.json:199-202` 已记录此条，并明确选择「**不做自动迁移**」（理由：无法区分旧默认值与用户主动选择）。但**本机安装正在生效**，属于「已知但未收口」的状态。对比度门禁 `check-contrast.mjs` 校验的是 **token 配对表**，**测不到运行期存值** —— 这是门禁的覆盖盲区。

**修法（设计侧，不动用户数据）**：
1. 设置页主色选择器把「当前值不达标」显式标注，并给出**一键切到推荐主色**（`#2F63EA`）的动作；
2. 或 AppBar/主色文字改用 `primary.dark` 等保证白字对比度的派生值，使任意合法主色都达标。
**验收**：在 `settings.json` 保持 `#3370FF` 的前提下，重跑对比度探针，上述 11 类元素全部 ≥ 4.5:1。

### 🟠 F3 — 计数徽章：同一数字渲染两次 + 语义色滥用

**证据（实测 4/4 行）**：`/manage/knowledge` 每个标签行同时渲染——
- 左侧 `关联 2,378 条`（带千分位）
- 右侧橙色**填充**徽章 `2378`（裸数字，无单位）

```
压强 关联 2,378 条  [2378]      ← 同一数值两处
重力 关联 1,849 条  [1849]
质量 关联 1,480 条  [1480]
浮力 关联 1,368 条  [1368]
```

**同类（全站至少 6 处）**：`/manage/stats`「待复核 32,936」「不支持 130」「未提取到内容 2」；`/manage/sources`「元数据缺失 174」；`/export`「无答案 4」；`/manage/formula` 左列**每行**一个橙色「不支持」（130 个同值徽章堆叠）。

**为什么是设计问题**：`tokens.warning`/`error` 在 `theme.ts` 里被明确拆成「填充值」与「文字值」两套，是为**语义**服务的。把中性计数染成警告橙，会让**真正的警告脱敏**——用户会学会忽略橙色。

**修法**：计数徽章改用中性色（`text.secondary` / `action.selected`）；只有真正的状态（待复核/失败）才用语义色。知识点页**删掉右侧重复徽章**，保留左侧带单位文案。

### 🟠 F4 — 单题详情：同一内容渲染三遍；检索列表直接铺答案+解析

**证据（数据层实测 `GET /api/questions/3521`）**：
| 字段 | 长度 | 内容 |
|---|---|---|
| `text` | 296 | 题干 + **`【答案】D 【详解】A．…故选D。`**（答案与详解已内嵌在题干里） |
| `answer` | 1 | `D` |
| `analysis` | 188 | `A．…故选D。`（**与题干内 `【详解】` 是同一段**） |

**UI 后果**：详情页依次渲染 `题干`（已含答案+详解）→ `答案`（D）→ `解析`（同段）＝ **同一份内容出现三次**。
**并且**：`/search` 结果卡片把 `【答案】D【详解】…` **整段**铺在列表里（见 `1366x768-light/02-search.png` 题 6 卡片）。

**修法**：
- 列表卡片：题干只保留「题干 + 选项」，剥离 `【答案】/【详解】/【解析】` 之后的内容（渲染期剥离即可，**不动数据**）；
- 详情页：题干区同样剥离，答案/解析只在各自区块展示；或把题干内嵌部分折进「更多信息」。

### 🟠 F5 — 来源文件表 209 行无分页/虚拟化

**证据（实测页高）**：`/manage/sources` → 1366 下 **9,788px**，1024 下 **13,009px**（全站最高，是第二名的 5.8 倍）。表内 209 行全量渲染。
**附加噪音**：「元数据状态」列 **174/209 行同值**（83% 都是「待补充元数据」）——一列几乎恒定的值不提供信息。
**修法**：分页或虚拟滚动（默认 20–50 行）；「元数据状态」列改为**行级视觉标记**（缺失处 `—` 已有）+ 顶部「仅看缺失」筛选（已有），去掉逐行徽章。

### 🟠 F6 — 设置页 1024 宽度横向溢出 5px

**证据（实测）**：`/settings` @1024 → `scrollWidth 1029` vs `clientWidth 1024`。元凶精确定位到**「默认模板」Select**：`right = 1029`、`width = 756`。
**这是 30 次采集里唯一一处横向溢出**（其余 29 次全部 `scrollW == clientW`），说明它是个**孤立**的宽度约束缺陷，不是系统性布局问题。
**修法**：给该 Select 的容器加 `minWidth: 0` / 用 `fullWidth` + 受控宽度。

### 🟡 F10 — 重复 CTA 稀释主操作层级
`/builder` 一屏 **65 个 `button`**，每张题卡都有一个蓝色 **filled**「加入」按钮。全站最高频页面里，最强的视觉权重被 8+ 个同权按钮平分。
**修法**：卡片默认用 `outlined`/`text`，仅在 hover/选中态升为 filled；或改为整卡点击 + 单一「加入所选」批量条（B2 已做批量条，可复用）。

### 🟡 F11 — 设计系统缺口（本轮新增，非回归）
`theme.ts` 的 `tokens` 目前只有**颜色 + 圆角**：
- **无间距 token**（全靠 MUI 默认 spacing，无 8pt 栅格约束）
- **无高度/阴影 token**（`MuiPaper` 直接 `backgroundImage: none`）
- **无动效 token**（`src` 内 transition 极少，无 `duration`/`easing` 约定）
- `fontSize` 明确标注「**不参与构建**」——字号尺度只存在于注释里，无强制力
- `neutral` token 标注「暂无消费方」

**并且**：上一轮计划的 B5「动效与收尾」**在本轮评审时尚未实施**（`git log` 到 `f9ae867` 为止无对应提交）——
⚠️ **已勘误**：B5 于同日 11:03 落地（`2b22c78`），见 §0 勘误条。**token 缺口的结论不受影响**：`theme.ts` 的 `tokens` 至今仍只有颜色 + 圆角，**无 spacing / motion 命名令牌**（B5 的动效以字面量落地，未先建令牌）。
**建议**：把 spacing / motion 两组 token 补进 `theme.ts` 并接线，否则后续动效会以魔法数字散落各处。

## 5. 经复核**不成立**的发现（反证留痕）

按项目铁律，放宽/收紧判定后必须构造反方向反例。本轮有 2 项候选发现经复核**撤回**：

1. **「深色模式多处白底白字」** —— 初版探针报 `/manage/formula-review` 有 5 处 `rgba(255,255,255,0.7)` 落在 `rgb(255,255,255)` 上。
   **复核**：逐元素追溯祖先链，其实际背景为 `rgb(30,30,30)` / `rgb(18,18,18)`（MUI 深色 `text.secondary` 的正常组合，≈9.7:1）。**属探针取背景的缺陷导致误报**。
   → **只有 1 处**（F1，`color: rgb(255,255,255)` 落 `bgcolor: #fff`）是真的，已在截图上肉眼确认。

2. **「组卷页『导出』按钮对比度 1.88:1 不达标」** —— 探针实测 `rgba(0,0,0,0.26)` on `#F5F6F8`。
   **复核**：该按钮 `disabled: true`（实测 `button.disabled === true`）。WCAG SC 1.4.3 **明确豁免禁用态控件**。
   → **不是缺陷**，已从清单剔除。

> 教训（沿用项目既有条目）：**探针写「元素缺失/不达标」断言前，必须先确认元素处于什么状态**（禁用态？空态？哪个 Tab？）。本轮两个误报都源于此。
