## 二、🔴 顺手抓到的真实缺陷：MUI Button 键盘焦点不可见

**发现方式**：L3 键盘 e2e（真实浏览器逐次 Tab）——初版报「3/45 个元素聚焦无样式变化」。

**根因（代码级定位，非猜测）**：

```
@mui/material/Button/Button.js:114   &.Mui-focusVisible { boxShadow: shadows[6] }        ← 默认
@mui/material/Button/Button.js:176   &.Mui-focusVisible { boxShadow: 'none' }            ← disableElevation 分支
@mui/material/ButtonBase/ButtonBase.js:51   outline: 0
```

本项目主题设了 **`MuiButton: { defaultProps: { disableElevation: true } }`**（为了视觉扁平），
于是焦点样式落到 `boxShadow: 'none'` 分支；而 `ButtonBase` 又设了 `outline: 0`。
**两者叠加 ⇒ 所有 MUI Button 的键盘焦点完全不可见**（实测 `outline: none 0px`、背景与阴影均无变化）。

**这不是 MUI 的 bug，是我们的主题设置副作用。**

**修复**：在 `theme.ts` 的 `MuiButton.styleOverrides.root` 补回焦点环
（用 `outline` 而非 `box-shadow`，不受 `disableElevation` 影响，且不占布局）。

**验证**：45 个可聚焦元素中「无可见焦点反馈」由 **3 → 0**。

> 这条也印证了「必须真实浏览器实测」——jsdom 与源码阅读都发现不了它。

## 六、如实声明：没做 / 做不到

1. **L4 的阶段是「前端推断」**：后端 `webui/jobs.py` 只上报 `status` 与粗进度（0/0.1/1.0），
   **不返回阶段名**。阶段名由前端按已知调用步骤 + 已用时长推断，源码注释已写明；
   后端补字段后应改为消费真实字段。
2. **L6 的残留**：若老师**从未打开过组卷页**、只在检索页加入题目，陈旧 `targetSectionId` 不会被清。
   该场景很窄，且后端会返回错误、现在会经全局 toast 提示。
3. **T3-1 未做真机验证**：所有分辨率数据来自 Playwright 模拟视口（1366/1280/1440/1920），
   **非真机**。1366×768 是主流笔记本分辨率，但未在物理设备上确认。
4. **右栏在 1366 下 A4 预览仍会横向滚动**：右栏 464px < A4 内容宽（约 572px），属既定取舍
   （右栏内部滚动，不影响页面整体）。
5. **视觉基线只覆盖 1366×768**：窄屏（<1200）与超宽（1920+）**未纳入基线**；也不覆盖深色模式与交互态。
6. **键盘 e2e 只覆盖组卷页**：其它页面的 Tab 序列未逐页验证。
7. **`spike/a4-preview/tools/_gate_expression_verify.mjs`** 已按我的要求删除（一次性脚本）。
