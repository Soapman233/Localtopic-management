## 一、性能：路由级代码分割（P5-1）

| 指标 | 改前 | 改后 |
|---|---|---|
| 入口 JS | 1,122,295 B | **24,372 B** |
| 主 CSS | 32,834 B | 29,894 B |
| **首屏合计** | **1,155,129 B** | **734,606 B（−36%）** |
| `vendor-katex`（261 KB） | 在首屏 | **懒加载，不在首屏** |

**首屏口径**：`index.html` 的 `<script src>` + 所有 `<link rel=modulepreload>` + `<link rel=stylesheet>`。
改后 preload 恰为 4 个 vendor，**不含 vendor-katex**。

**两个值得记的判断**：

1. **`Suspense` 放在 `Outlet` 外层**（而非 router 根）：放 router 根会让**顶栏/侧栏/试卷切换器
   在每次懒加载时整体卸载重挂**（闪动 + 导航态丢失）；放 Outlet 外层则外壳常驻，仅内容区显示加载态。
2. ⚠️ **CSS 不能参与 vendor 分包**：`main.tsx` 只 import 了 katex 的 **CSS**。若让该 CSS 归属
   `vendor-katex`，入口会因这个静态 import **连带预加载 258 KB 的 KaTeX JS** 进首屏。

### 我修的连带问题：构建产物堆积

代码分割后 assets 下 js/css **从 2 个涨到 125 个**。旧清理脚本按「是否被 `index.html` 引用」判断——
但**懒加载 chunk 不在 `index.html` 里**（运行时动态 import），按旧口径会**误删正在使用的 chunk → 点进页面即 404**。

**修法**：启用 `build.manifest`，用构建清单判定本次构建的完整产物集；只删 `.js`/`.css`
（KaTeX 字体由 CSS 间接引用，绝不能删）；分批删除避开沙箱批量删除拦截。

```
[prune] 清理 50/50 个过期产物，释放 1517 KB（保留 86 个，判定依据：Vite manifest）
```
实测 **77 → 27** 个 js/css，**幂等**（二次构建报「无过期产物」），且所有页面 chunk 均保留。

## 二、对比度：全部达标 WCAG 2 AA（P5-2）

**审计发现的起点**（我用 `web-accessibility` 技能的校验器实测，非目测）：
**15 组里 11 组不达标** —— 根因是徽章用 `Chip variant="outlined" color="success|warning|error"`，
**描边与文字都用语义色本身**（鲜艳的绿/橙/红直接当文字）。

**修复结果**：`npm run contrast` → **65/65 通过**（浅色 + 深色两套）。

| 用途 | 原 | 新 | 实测 |
|---|---|---|---|
| 主色 | `#3370FF` | `#2F63EA` | 白字 5.13 / 页面底作文字 4.74 |
| 成功·文字 | `#22C55E` | `#15803D` | 白底 5.02 / 页面底 4.64 |
| 警示·文字 | `#F59E0B` | `#B15008` | 白底 5.22 / 页面底 4.83 |
| 错误·文字 | `#EF4444` | `#D32222` | 白底 5.22 / 页面底 4.83 |
| 中性灰 | `#9CA3AF` | `#667085` | 白底 4.97 / 页面底 4.60 |

**两个隐蔽的坑**（都已记入代码注释）：

1. **MUI `getContrastText` 阈值是 3:1**：把 `main` 改深后，filled 徽章的文字色会被**自动推成深色**
   （`#15803D` 上深字仅 4.18:1）→ **必须显式钉死 `contrastText: '#FFFFFF'`**。
2. **深色删除按钮原值在白纸上仅 2.15:1**：它压在**恒白的纸张**上，而不是深色面板上——
   按深色底算就会漏掉。

> 值得一提：contrast-dev **没有照抄我给的候选值**，而是实测发现它们在页面底色上仍不够
> （`#3268F5` 仅 4.38、`#6B7280` 仅 4.47），自行再下调一档。**我给的是候选，不是结论。**

### 门禁已接入构建

技能原话：「**跑一次是审计；接进 `npm run build` 并在失败时非零退出，才是保证**」。

```
"build": "tsc --noEmit && npm run contrast && vite build && node scripts/prune-stale-assets.mjs"
```

- 校验器**vendored 进仓库**（`frontend/scripts/check-contrast.mjs`，MIT，零依赖）→ 门禁**不依赖本机技能目录**。
- **对门禁本身做了反证**：喂不达标配色 → **exit=1**；达标配色 → exit=0。

## 三、无障碍语义（P5-3）

| 项 | 结果 |
|---|---|
| **skip-link** | 新增「跳到主内容」。⚠️ **HashRouter 下 `href="#main-content"` 会改写 hash 从而触发路由跳转** → 拦截 `onClick` 改用 `focus()+scrollIntoView()`；实测 hash 未被改写 |
| **地标** | `<main id="main-content" role="main">` + `<nav aria-label="主导航">` |
| **当前页** | 导航项加 `aria-current="page"` |
| **抽屉可访问名** | **5 处 `<Drawer>` 补 `aria-labelledby`**（MUI 的 `Dialog` 经 `DialogTitle` 自动派生，**`Drawer` 不会**） |
| **图标按钮** | 8 处 `IconButton` 中 2 处缺名已补（其余 6 处已有中文名） |
| **toast 播报** | 查证 notistack v3 默认内容组件**已输出 `role="alert"`**（`notistack.esm.js:1247`）→ 未改 |
| **触达尺寸** | 拖拽把手 20×20 → **24×24**（content-box + padding，图标尺寸不变、零视觉变化） |
| **动效** | `@media (prefers-reduced-motion: reduce)` |
| **页面标题** | 路由变化同步 `document.title` |

### 标题层级（发现的问题比预想严重）

- **9 个页面原先全无 `<h1>`**；
- **MUI 的 `variant="subtitle1/2"` 默认渲染成 `<h6>`** → 把区块小标题和**表单标签**塞进标题层级，
  造成页内 **h1→h6 跳级**（对读屏用户是导航噪音）；
- 还有 `variant="h5"` 被用作**数据展示**（统计卡数值）。

已修 **15 处**，其中一处是 **`EmptyState` 用了动态 variant**（`dense ? 'body2' : 'subtitle1'`）
导致**静态 grep 漏掉**，靠实际渲染核对才发现。

**实测：9/9 页恰好 1 个 `<h1>` 且无跳级。**

## 五、如实声明：没做 / 做不到 / 待你决策

### 未做

1. **未用真实读屏软件验证**（NVDA/VoiceOver）。技能明确说自动化只能覆盖约 1/3–1/2 的 WCAG 失败，
   因此**只声明「这些具体项已验证」，不声明「产品已无障碍」**。
2. **未做真机验证**：所有分辨率与交互均为 Playwright 模拟视口/真实浏览器，非物理设备。
3. 视觉基线仍**只覆盖 1366×768**（窄屏/超宽/深色模式未纳入基线）。

### 待你决策（3 项）

| # | 事项 | 我的建议 |
|---|---|---|
| 1 | **深色模式 `color="primary"` 作文字仅 3.52:1**（既有遗留，非本轮引入）。单值数学上无法两全（白字可读需亮度 ≤0.183，深底作文字需 ≥0.232）。正确修法是深色模式取主色浅化值，但会**把顶栏由深底变浅底 + 实心按钮改深字**——属产品视觉身份决策 | 建议下一轮单独做，并同步更新深色基线 |
| 2 | **已保存的旧主色**：`settings.json` 里存着 `#3370FF` 的既有安装不会自动迁移（无法区分"旧默认"与"用户主动选过"，静默改写用户配置更糟） | 在设置页重选一次，或删除 `outputs/webui/settings.json` 回落新默认 |
| 3 | **`tokens.difficulty` / `palette.badge` 零消费方**（阶段 2 加的 token 无使用方，`StatusBadges` 用的是 MUI `success\|warning\|error`）。**这是个陷阱**：有人改 `tokens.difficulty` 会以为生效了 | 建议**删除**而非接线——因为 `tokens.difficulty` 存的是**鲜艳色**，一旦接线给徽章会**重新引入对比度失败** |

### 已知限制

- **`.lp-qhandle` / `.lp-score-chip` / `.lp-qdel` 在 `scale(0.72)` 预览内渲染命中区 ≈17px < 24**。
  未改：要让渲染 ≥24 需固有 ~34px，会与相邻控件重叠、引入误触。
  **功能未对键盘/触控用户关闭**——同样操作在「清单视图」（`PaperPanel`）有 ≥24px 的合规入口。
- **禁用态 `text.disabled`（2.68:1）**：SC 1.4.3 明确豁免 disabled 控件。

## 六、阶段 4（两版适配）的现状

阶段 4 的**前端接口位**（`AuthProvider` / `RequireAuth` / `usePermission` / `<Can>` / 只读态）
**未做**，因为它依赖**后端的用户与权限体系**——当前后端只有可选的共享令牌（`QB_AUTH_TOKEN`），
**没有用户表、没有角色、没有登录接口**。单独做前端会得到一个"有登录页但没有后端"的空壳，
因此**建议与后端一并做**。
