## 1. 总体实施顺序

分为 **6 个批次**。第一项先修裸 Markdown，其次关闭默认调试信息；导航重组紧随其后，但独立提交，便于定位路由问题。

| 批次 | 目标 | 主要内容 | 验收点 |
|---|---|---|---|
| **B0 文案与加固** | 消除明显错误 | 三处裸 Markdown、调试泄漏、技术词补漏、登录加载边界 | 指定文案不再裸露；debug 可用；登录延迟加载不白屏 |
| **B1 信息架构** | 落实 3 + 1 导航 | 导航/路由解耦、维护页四 Tab、旧链接、统一试卷管理 | 新旧路径全通；当前导航正确；只挂载当前 Tab |
| **B2 找题与详情** | 首屏突出题目 | 覆盖率摘要、条件批量条、筛选帮助、详情单栏 | 检索语义不变；详情完整；编辑和历史仍可达 |
| **B3 组卷与导出** | 收回横向与纵向空间 | 默认双栏、右栏工具条、诊断状态、唯一导出抽屉 | 1366 双栏；所有内容变更重新锁定；迟到响应不误解锁 |
| **B4 维护与设置** | 低频功能渐进披露 | 四个维护 Tab、统计展开、设置外观/高级 | 数据口径不变；批量预检不丢；高级默认只读 |
| **B5 动效与收尾** | 轻动效与完整验收 | 找题试点、路由过渡、体积检查、视觉回归 | reduce 降级有效；首屏预算通过；人工确认新基线 |

### 必须先完成的依赖

1. **路由与导航解耦 → 精简侧栏。**  
   当前 `frontend/src/router.tsx:64` 根据 `NAV_ITEMS` 生成路由。直接删除导航项，会一起删除导出和维护页面路由。

2. **维护页标题契约 → 四页嵌入。**  
   父页使用 h1，Tab 内页面使用 h2，内部区块相应调整；不能同时留下五个 h1。

3. **统一试卷管理能力 → 删除工作台旧抽屉。**  
   当前全局抽屉只负责切换/新建，工作台抽屉还提供删除、确认、撤销，必须先迁移能力。

4. **诊断摘要组件 → 工作台右栏瘦身。**  
   先提供带文字和处理入口的紧凑状态，再收起原诊断面板，避免隐藏阻断问题。

5. **布局稳定 → 动效 → 更新视觉基线。**  
   动效单独验收，不与布局变更同时接受截图基线。

## 2. 信息架构重组的具体实现

### 2.1 导航改法

真实代码并非 10 个侧栏链接：`App.tsx:72` 的 `NAV_GROUPS` 包含日常 3 项、维护 4 项，另有设置，共 **8 个链接**；10 是页面组件数。

调整位置：

- `frontend/src/App.tsx:72`：`NAV_GROUPS`
- `frontend/src/App.tsx:94`：`SETTINGS_ITEM`
- `frontend/src/App.tsx:107`：`NAV_ITEMS`
- `frontend/src/App.tsx:132`：`NavListButton()`
- `frontend/src/App.tsx:333`：分组渲染

新的逻辑导航项：

```text
日常
  builder   组卷工作台
  search    找题

数据维护（低频分组，默认折叠）
  manage    数据维护

底部
  settings  设置
```

`NAV_ITEMS` 只包含上述四项。侧栏不再列出四个维护页面，四个入口仅存在于维护页 Tab 内。

“默认折叠”落实为侧栏低频分组使用 MUI `Collapse`：

- 默认关闭；触发器设置 `aria-expanded`、`aria-controls`。
- 直接访问 `/manage/*` 自动展开并高亮“数据维护”。
- 维护页内四个 Tab 始终可见，不再折叠一次。
- 导航说明不再占每个链接第二行，退到帮助。

选中规则：

| 当前地址 | 选中导航 |
|---|---|
| `/builder` | 组卷工作台 |
| `/search`、`/question/:id` | 找题 |
| `/manage`、`/manage/*` | 数据维护 |
| `/settings` | 设置 |
| `/export` | 组卷工作台，作为其全屏预览辅助页 |

路径匹配使用完整路径或分段前缀，避免 `/search-other` 被错误选中。

### 2.4 组卷内嵌导出

代码已经具备：

- `PaperBuilderPage.tsx:172`：`exportOpen`
- `:533`：主导出按钮
- `:716`：`ExportDrawer`
- `ExportDrawer.tsx:84`：共享 `useExportGate()`

因此只调整界面和入口，不重写导出业务。

目标：

- 工作台保留一个主“导出”按钮。
- 抽屉内一个预览动作、一个导出动作。
- 模式、模板、格式、诊断、过期、降级确认仍由现有共享逻辑控制。
- 当前导出结果留在抽屉。
- `/export?paper_id=X` 保留为全屏预览辅助页，取消导出提交与写入型修订操作。

**不保留“导出历史”承诺。**当前 `useExportGate()` 的结果是组件局部作业状态；移除辅助页导出提交后，也不能声称辅助页能查看抽屉的“本次结果”。

辅助页返回工作台打开指定卷时，使用一次性路由 state：

```text
{ openExportForPaperId: X }
```

工作台消费后：

1. 选中 X。
2. 清除目标大题。
3. 打开 X 的抽屉。
4. `replace` 清除该 state，保留现有查询参数。

不用 `export=1` 查询参数，避免被 `useQuestionFilters.ts:84` 的 URL 同步覆盖。保留抽屉 `key={paperId}`，防止卷 A 的局部状态进入卷 B。

## 5. 动效方案

### 首批试点：找题页

选找题页，因为题卡具有稳定 ID，增删变化可见，并且不涉及纸面测量、分页引擎或 DnD transform。

### AutoAnimate 接入点

| 容器 | 接法与边界 |
|---|---|
| `SearchPage.tsx:390` 题卡列表 | 增加稳定外层容器，直接子项继续以 `item.id` 为 key |
| `SearchPage.tsx:359` 批量条外层 | 只过渡工具条显隐，不对整页正文动画 |
| 拟新增试卷管理抽屉列表 | 试点通过后加入新建/删除过渡 |
| `KnowledgeReviewPage.tsx:333` 关联清单 | 后续用于人工决定后的少量项移除 |

首批加载、整页翻页、大量结果替换关闭列表动效；同页少量增删才播放。

**禁止接入：**

- `.lp-measure`
- 缩放纸面和 `PageView`
- DnD 控制 transform 的同一节点
- 每个公式或题干段落

依赖只新增 AutoAnimate。报告的约 2.5KB 是估值，实施后报告实际原始/gzip 增量。`vite.config.ts:63` 为其单独分包，核实不因落入入口已有 `vendor-misc` 而被预加载。

AutoAnimate 提供启用/禁用控制，并默认尊重系统减少动效偏好；仍应显式响应偏好变化。[官方文档](https://auto-animate.formkit.com/)

### View Transitions 接入层

本机实际安装 `react-router-dom 6.30.6`，类型支持：

```tsx
navigate(path, { viewTransition: true })
```

不升级路由库，不用 `unstable_` 名称，不另写 `startViewTransition(() => navigate())` 假定 React 已同步提交。[React Router 文档](https://reactrouter.com/how-to/view-transitions)

接入位置：

- `App.tsx:442` 的 Outlet 外包页面容器。
- 为该容器设置唯一 `view-transition-name: route-content`。
- 导航、维护 Tab 和明确页面跳转通过统一导航 helper 接入。
- 约 120ms 淡入淡出。
- root 过渡关闭，AppBar、侧栏、全局 Drawer 不做整壳动画。
- 首次冷 lazy 加载可走普通导航；已加载页面间再增强。
- 不给 Outlet 加随机 key，不因动效强制重挂载页面。

### `prefers-reduced-motion` 降级

拟新增轻量 `useReducedMotion()`：

- 读取并监听 `matchMedia`，卸载时移除监听。
- reduce 时显式禁用 AutoAnimate。
- reduce 或不支持 `document.startViewTransition` 时普通 `navigate()`。
- 保留 `index.css:43` 全局 reduce 块。
- 为 View Transition 伪元素另加 reduce 样式。
- 业务逻辑不依赖动画结束事件。

验收：浏览器模拟 reduce 和不支持 API，找题、勾选、切页、开关抽屉的结果相同；动画期间操作不丢焦点、不重复提交。

## 6. 风险与回滚

### 最大三个风险

| 风险 | 防护 |
|---|---|
| **精简导航时删掉路由或能力** | 路由先解耦；旧路径保留；统一抽屉能力迁完后再删旧 UI |
| **布局/动效破坏导出门禁与测量** | 不改导出内核与共享安全判断；动画远离测量层；构造迟到、stale、环境失败、内容阻断反证 |
| **界面简化掩盖数据事实，或首屏/无障碍回退** | 状态带文字和行动；口径保留；新增配色入表；检查入口及首屏总量；不编造健康分、自动复核能力 |

“安静的状态点”不意味着只靠颜色。正常状态可收敛；操作失败、内容阻断、当前筛选漏题和文件级影响仍须有可读事实及行动。

### 回滚策略

- 每批独立提交，按依赖反序回滚。
- **B1 整批回滚**：导航、路由、维护父页、兼容测试必须一起回滚。
- B2、B4 可按页面回滚；共享组件与消费方一起处理。
- B3 的导出入口与辅助页调整作为同一提交组，避免回滚后没有导出入口。
- B5 独立回滚动效 hook、导航配置、CSS、依赖及锁文件。
- 本方案无数据库迁移，不需要交付库数据回滚；副本测试数据不写回交付库。

### 自动测试覆盖不了、必须人工检查的部分

- 1366 下题卡、纸面和按钮的实际可读性。
- 固定顶栏是否遮住抽屉标题与关闭按钮。
- 720px 正文的长公式、图片、长答案布局。
- 深色模式中状态、边界、白底源图的实际观感。
- 动效是否跳动、干扰阅读或造成焦点迷失。
- NVDA 实际朗读与 Tab/Drawer 焦点恢复。
- 触及文档排版或公式渲染时，当前新导出渲染和 Word/WPS 内部改字符、保存、重开验证。

- `pct_gt32 < 0.5%`

## 7. 工作量与批次建议

以下范围包含源码、测试、配置及视觉机制文档，不含 PNG、构建产物和数据。共享文件跨批重复，不能直接求和。

| 顺序 | 批次 | 文件范围 | 页面范围 |
