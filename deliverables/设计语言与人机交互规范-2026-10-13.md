# 设计语言 · 人机交互 · 前端设计规范

**版本**：v1.0（2026-10-13）
**效力**：本项目**唯一**的设计规范性文件。与本文件冲突的既有做法以本文件为准；要改必须先改本文件。
**适用**：`frontend/`（React 18 + TS + MUI 5 + KaTeX）、`webui/static` 托管产物，以及规划中的 `editions/desktop/`（pywebview 客户端外壳）。
**关系**：本文件**取代**分散的约定，但**不推翻**既有技术决策（零 Tailwind、MUI 保留、token 单一来源、四态组件、术语唯一来源）。

---

## 0. 一句话

> **这是给中学物理老师用的"出卷工具"，不是给工程师用的"管理后台"。**
> 规范的全部取舍都服从一件事：**老师打开它，是为了拿到一张能打印、能在 Word 里继续改的卷子。**

## 1. 设计语言：**纸面优先（Paper-first）**

### 1.1 为什么是这个名字

本项目的产物是**纸**——A4 试卷。而绝大多数同类工具的产物是**屏幕**（在线答题、网页预览）。这个差异决定了全部视觉取舍：

| 常规 Web 应用 | 本项目 |
|---|---|
| 页面是主角 | **纸是主角**，页面只是纸的容器 |
| 用颜色/动效表达"活跃" | 用**克制**表达"可信"——老师要交出去的卷子不能有花花绿绿 |
| 状态用横幅广播 | 状态用**安静的状态点** |
| 数据在库里 | 数据**自带出处**，出处必须可点 |

### 1.2 五条原则（**规范性**，冲突时按序号优先）

| # | 原则 | 含义 | 反面（禁止） |
|---|---|---|---|
| **P1** | **纸是主角** | 组卷页的 A4 预览是唯一"所见即所得"的真相；其余一切都是它的注脚 | 右栏堆 6 层 chrome 把纸挤到折叠线下 |
| **P2** | **一屏一事** | 高频三页（组卷/找题/导出）各只有**一个**主任务、**一个**主操作 | 一屏 65 个按钮、每张卡一个蓝色主按钮 |
| **P3** | **安静的状态** | 系统状态用**状态点 / 一行 caption**；**只有需要立刻行动**才用语义色 | 永久性说明用橙色告警条；"检查通过"用绿色横幅 |
| **P4** | **出处可点** | 任何题 / 公式 / 标签，都能点回它的**来源文件与位置** | 把来源写成一个不可点的灰字 |
| **P5** | **教师语言** | 界面不出现技术字段；术语唯一来源 `lib/glossary.ts` | 屏幕上有 `has_answer`、`embeddings`、`快照锁定` |

### 1.3 视觉基调

- **平面优先**：不用阴影表达"重要"，用**位置与留白**。elevation 只用于表达**层级**（谁盖住谁），不用于装饰。
- **色彩节制**：一屏**最多一处**彩色强调（主色或一个语义色），其余走中性灰。
- **中文优先排版**：行高比英文松（正文 1.6–1.7）；不用全大写；数字用等宽对齐。
- **深色是等价一等公民**：不是"顺便支持"，任何新组件**必须同时验证 light 与 dark**。

### 1.4 与竞品的差异定位（设计层面）

| 对标 | 它们的视觉语言 | 本项目必须不同在哪 |
|---|---|---|
| 学科网 / 组卷网 | 信息密度极高、广告位多、彩色标签泛滥 | **做减法**：老师 90% 时间只做三件事 |
| 国家平台 AI 组卷助手 | 官方、朴素、通用 | **做深**：把"我自己的存量资料"作为主角，而非公共题库 |
| Notion / 飞书 | 文档编辑器、协同光标 | **不做协同**：单人/小团队，界面不该有"在线状态"类元素 |

## 2. 设计令牌（Design Tokens）

**唯一来源**：`frontend/src/theme.ts` 的 `tokens` 常量（纯数据、`as const`、可被测试直接加载）。
**铁律**：组件**只允许**通过 `useTheme()` / `tokens` 取色取值，**禁止内联 hex / rgb / 魔法数字**（见 §5.3）。

### 2.1 颜色

#### 语义色**双轨制**（本项目最重要的颜色约定）

鲜艳色作**填充**够用，作**文字**不达标。因此每个语义色拆成两个值：

| 角色 | 令牌 | 浅色值 | 深色值 | 允许用途 |
|---|---|---|---|---|
| 成功·**填充** | `tokens.success` | `#22C55E` | 同 | 仅作 filled 徽章**底**（深字压鲜艳底 9.22:1） |
| 成功·**文字** | `tokens.successText` / `successTextDark` | `#15803D` | `#4ADE80` | 文字 / 图标 / 描边 / Alert |
| 警示·填充 | `tokens.warning` | `#F59E0B` | 同 | 仅填充 |
| 警示·文字 | `tokens.warningText` / `warningTextDark` | `#B15008` | `#FBBF24` | 文字 / 图标 |
| 错误·填充 | `tokens.error` | `#EF4444` | 同 | 仅填充 |
| 错误·文字 | `tokens.errorText` / `errorTextDark` | `#D32222` | `#F87171` | 文字 / 图标 |

> MUI `palette.<color>.main` **统一取文字安全值**（因为 outlined 徽章、图标、Alert 共用该槽位）；filled 徽章的底色由 `MuiChip.styleOverrides` 回填鲜艳值。

#### 品牌与中性

| 令牌 | 值 | 说明 |
|---|---|---|
| `tokens.primary` | `#2F63EA` | **文字安全值**。白字 5.13:1 / 白底 5.13:1 / 页面底 4.74:1 |
| `tokens.primaryBrand` | `#3370FF` | ⚠️ **历史留痕，禁止消费**（白字仅 4.28:1） |
| `tokens.bg` | `#F5F6F8` | 页面底 |
| `paper` | `#FFFFFF` / 深色 `#1E1E1E` | 卡片底 |
| `background.default` | `#F5F6F8` / 深色 `#121212` | — |
| `tokens.neutral` | `#667085` | 中性灰文字（白底 4.97:1） |
| `tokens.neutralDisabled` | `#9CA3AF` | 禁用态（SC 1.4.3 豁免） |

#### 🔴 颜色铁律（**MUST**）

1. **禁止硬编码颜色**。任何 `bgcolor: '#fff'`、`color: 'white'`、`#EDEFF2` 之类**一律禁止**——用 `background.paper` / `text.primary` / `divider` 等语义槽位。
   *（根因：`FormulaReviewPage.tsx:64` 硬编码 `bgcolor: '#fff'` 导致**深色模式白底白字、内容完全不可见**。）*
2. **语义色不得用作中性计数**。数字徽章、统计计数一律用中性色。语义色只表达**状态**。
   *（根因：全站 ≥6 处把中性计数渲染成橙色警告徽章 → 语义脱敏。）*
3. **一屏最多一处**彩色强调。
4. 新增任何前景/背景组合，**必须**登记进 `frontend/tests/visual/contrast-pairs.json`。

### 2.2 字体与字号

| 令牌 | 值 | 用途 |
|---|---|---|
| 字族 | `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', Roboto, Arial, sans-serif` | 全站唯一 |
| 等宽 | `Consolas, Menlo, monospace` | 仅 LaTeX 源码 / 调试信息 |

| 级别 | 值 | 用途 | 字重 |
|---|---|---|---|
| `micro` | 11px | 仅密集表格 / 徽章内文字 | 400 |
| `caption` | 12px | 辅助说明、时间戳、字段标签 | 400 |
| `body` | 14px | **默认正文**（MUI body2） | 400 |
| `subtitle` | 16px | 卡片标题、表单值 | 400/500 |
| `title` | 20px | 区块标题（MUI h6） | 500 |
| `display` | 24px | 页面主指标数字 | 500 |

**行高**：正文 1.6–1.7（中文长文本，如题干/解析）；标题 1.3；表格 1.4。
**字重**：**只有 400 / 500 两档**。禁止 600/700（中文粗体在 1366 屏上糊）。

### 2.3 间距

**基准 8px**，MUI spacing 单位 = 8px。**只允许**下列取值：

| 令牌 | MUI 写法 | 像素 |
|---|---|---|
| `space.0` | `0` | 0 |
| `space.half` | `0.5` | 4 |
| `space.1` | `1` | 8 |
| `space.2` | `2` | 16 |
| `space.3` | `3` | 24 |
| `space.4` | `4` | 32 |
| `space.6` | `6` | 48 |
| `space.8` | `8` | 64 |

**禁止** `5 / 7 / 9 / 11` 等非标值（现状抽样：1/2/0 占 279 次，3/4/8 共 7 次——**基本已合规，需靠 lint 固化**）。
**卡片内边距**：统一 `2`（16px）；**卡片间距**：统一 `2`（16px）；**区块间距**：`3`（24px）。

### 2.4 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `radius.sm` | 4 | 内联代码、公式降级块 |
| `radius.md` | 8 | 按钮、输入框、Chip |
| `radius.lg` | **10**（`tokens.radius`，接入 MUI `shape.borderRadius`） | 卡片、Paper |
| `radius.pill` | 999 | 胶囊徽章、状态点 |

**禁止**同一页面出现两种以上卡片圆角。

### 2.5 高度（elevation）

本项目**刻意扁平**（`MuiPaper.backgroundImage: none`、`disableElevation`）。

| 级别 | 用途 |
|---|---|
| 0 | **默认**：所有卡片、面板、表格 —— 用 `1px` 边框而非阴影 |
| 1 | 悬浮层：Drawer、Popover |
| 2 | 模态：Dialog |
| 8 | 仅 AppBar 与内容的分隔 |

### 2.6 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `motion.fast` | **120ms** | 路由切换、hover/focus 反馈、状态点变化 |
| `motion.base` | **180ms** | 列表增删（AutoAnimate） |
| `motion.slow` | **240ms** | 抽屉、对话框 |
| `motion.ease` | `cubic-bezier(0.2, 0, 0, 1)` | 标准 |
| `motion.easeOut` | `ease-out` | 进入 |
| `motion.easeIn` | `ease-in` | 退出 |

**动效铁律（MUST）**：
1. **`prefers-reduced-motion: reduce` 必须完全降级**（`index.css` 已有全局 reduce 块；路由过渡另有 `routeTransitions.css` 覆盖）。**业务显隐不得依赖 `transitionend`**。
2. **动效不得让首屏回退**：`@formkit/auto-animate` 必须**懒加载**（现状已如此），不得进首屏。
3. 动效**只用于**表达"东西从哪来/到哪去"，不得用于装饰。
4. **取消的动画必须清理移除节点**（已发现缺陷：`AnimatedList.tsx:17` 取消动画未清移除节点 → 0 勾选仍显示 1 条）；**卸载必须 `destroy()`**（`AnimatedList.tsx:42` 仅 disable，观察器 2→4→6 泄漏）。

### 2.7 层级（z-index）

沿用 MUI 默认：AppBar `1100` / Drawer `1200` / Modal `1300` / Snackbar `1400`。
⚠️ **本项目已知坑**：AppBar 的 zIndex 被设为 `drawer+1` → **Drawer 顶部内容会被 AppBar 遮挡**。**规范**：任何 Drawer 内容顶部**必须**放 `<Toolbar variant="dense" />` 占位。

### 2.8 断点与响应式

| 名称 | 阈值 | 布局 |
|---|---|---|
| `lg` 及以上 | **≥ 1200px** | **双栏**（组卷页：左题列表 + 右 A4 纸面） |
| `md` | 900–1199px | 单栏 + 抽屉（右栏折叠为「试卷面板」按钮） |
| `sm` 及以下 | < 900px | 单栏 |

**主目标分辨率 1366×768**（老师办公机）。**1200 是双栏阈值**，不得因为"看着挤"就把 1366 默认折叠。
**禁止**在 <1200 时用常驻 Alert 提示"请拉宽窗口"——改为一次性可关闭的提示（见 §3.3）。

## 3. 人机交互规范（HCI）

### 3.1 交互五律

| # | 规则 | 说明 |
|---|---|---|
| **I1** | **每个异步动作必须有可见的进行中状态** | 长任务（导出/导入/预览）用 `ProgressStages`，不用裸 spinner |
| **I2** | **迟到响应必须被拒绝** | 任何异步结果落状态前，**必须**校验请求标识/目标与当前上下文一致；不一致则丢弃 |
| **I3** | **可逆操作给撤销，不可逆操作给确认** | 删题 → 撤销；删试卷 → `ConfirmDialog` |
| **I4** | **危险确认必须写明影响范围** | 「将影响该来源文件下的**全部 N 题**」，不能只写"确定吗" |
| **I5** | **失败必须给出下一步** | 错误态三件套：发生了什么 + 为什么 + **现在做什么** |

> **I2 是真实缺陷换来的规则**：已发现 `KnowledgeReviewPage.tsx:519` 在切换标签后，**迟到的预检结果覆盖了新标签的写入目标**（弹窗显示 2 条、实际写入 4 条）。**任何"先请求、后应用"的交互都必须绑定目标。**

### 3.2 页面状态模型（**七态**，每页必须显式设计）

| 状态 | 何时 | 表现 |
|---|---|---|
| **加载中** | 首屏 / 切页 | `<LoadingState />`（骨架或文案，**不用裸 spinner**） |
| **空态** | 无数据 | `<EmptyState />`，**必须给下一步引导**，不能只写"暂无数据" |
| **有数据** | 正常 | — |
| **错误** | 请求失败 | `<ErrorState />`，含重试 |
| **锁定态** | 前置条件未满足（如导出未生成预览） | **内联说明 + 唯一解锁动作**，不用横幅 |
| **只读态** | 权限不足 / 高级项未解锁 | 控件 `readOnly`/`disabled` + **显式解锁入口**（现状：设置页高级 Tab 默认只读，点「编辑高级设置」解锁 ✅） |
| **窄屏态** | 视口 < 1200 | 折叠为抽屉，**不用常驻横幅** |

**铁律**：**任何"元素不存在"的判断必须先确认页面处于哪个状态**。
*（本项目已两次因此误报：探针在空态下找不到"检查通过"、在默认 Tab 下找不到高级字段。）*

### 3.3 反馈通道选择（**唯一权威表**）

| 场景 | 用 | 不用 |
|---|---|---|
| 操作成功（瞬时） | Snackbar（`NotifierBridge`） | Alert 横幅 |
| 操作成功（需要复核） | 内联状态点 | 绿色横幅 |
| **永久性数据说明**（覆盖率、口径） | **一行 caption + 「?」展开** | ⚠️ **橙色 Alert**（禁止） |
| 需要**立刻行动**的告警 | Alert（warning/error） | Snackbar |
| 长任务进度 | `ProgressStages` | 不确定进度条 |
| 阻塞性确认 | `ConfirmDialog` | 浏览器 `confirm()` |
| 表单校验失败 | 字段下方内联文字 | 全局提示 |

**禁止**：把永久性说明渲染成彩色横幅。
*（现状违规：检索页「数据完整度」橙色告警条、导出页绿色「检查通过」条、组卷页窄屏蓝色条——三处都要降级为状态点/可关闭提示。）*

### 3.4 反馈文案规范

1. **主谓宾、口语、不用术语**。「已把 3 道题加入试卷」而不是「批量加入成功」。
2. **不输出裸 markdown**（`**加粗**` 不得上屏）——需要强调用真实排版。
3. **不自相矛盾**。反例：`当前模式内容检查通过：0 个阻断条目` 紧跟 `导出前需要处理的问题仍需逐项核对`——**通过就是通过**。
4. **术语唯一来源 `lib/glossary.ts`**，调用处只引用 key（如 `GLOSSARY.lockedSnapshot`），**禁止内联中文字符串**。
5. **技术字段默认不渲染**，仅 `?debug=1` 或 `localStorage.qb_debug=1` 可见。

### 3.5 键盘与无障碍

| 项 | 规范 |
|---|---|
| 焦点可见 | **所有**可聚焦元素必须有可见焦点环（`theme.ts` 已为 MUI Button 补 `outline`；新组件同样要求） |
| Tab 顺序 | 与视觉顺序一致；skip-link 直达主内容（HashRouter 下须拦 `onClick`） |
| 对话框 | 打开后焦点陷阱；`Esc` 关闭；关闭后焦点回到触发元素 |
| 标题层级 | **每页恰好 1 个 `h1`**；维护页父级 `h1` + Tab 内 `h2` |
| 图标按钮 | 必须有 `aria-label` |
| 动态内容 | 用 `role="alert"` 播报 |
| 触控目标 | ≥ 44×44px（1366 鼠标场景可放宽到 32，但**主操作不得小于 36**） |
| 对比度 | **正文 4.5:1 / 大字号与图标 3:1**（门禁见 §5.2） |

## 4. 前端设计规范

### 4.1 布局

| 类型 | 规则 |
|---|---|
| **阅读型**（单题详情） | 内容居中，`maxWidth: 720px` |
| **工具型**（组卷/找题/维护） | 全宽，`padding: 24px`，**不设 maxWidth** |
| 栅格 | 12 列；卡片区用 `Grid`/`Stack`，**不用手写 flex 百分比** |
| 页面留白 | 内容区左右 `24px`；区块之间 `24px`；卡片之间 `16px` |
| 滚动 | **页面级滚动为主**；只有 A4 预览、代码块允许内层滚动 |

### 4.2 组件规范（**只列有约束的部分**）

#### Button 层级（**一屏一个主操作**）
| 层级 | 用法 | 约束 |
|---|---|---|
| `contained` primary | **页面唯一主操作** | **一屏 ≤ 1 个** |
| `outlined` | 次级操作 | — |
| `text` | 行内动作（详情、更多） | 表格/卡片行内**只能用 text** |
| `disabled` | 前置未满足 | 必须有 Tooltip 说明**为什么**禁用 |

> **禁止**：列表里每张卡都放一个 `contained` 主按钮（现状：组卷页一屏 65 个按钮）。批量场景用**顶部批量条**（选中后才出现）。

#### Chip（徽章）—— **语义色铁律**
| 用途 | variant | color |
|---|---|---|
| **状态**（待复核 / 失败 / 已完成） | `outlined` | 语义色（走文字安全值） |
| **状态强调**（需立刻注意） | `filled` | 语义色（底色回填鲜艳值，深字） |
| **中性计数 / 分类**（题数、章节、题型） | `outlined` | **`default`（中性）** |
| **纯数字计数** | **不要用 Chip** | 用一行 caption 文字，**且同一数值全页只出现一次** |

> 现状违规：知识点复核页每行「关联 2,378 条」+ 橙色徽章「2378」——**同值渲染两次，且用了警告色**。

#### Alert —— **有门槛**
- **只有"需要立刻行动"才用**。永久性说明**禁止**用 Alert。
- 一屏 **≤ 1 个** Alert。
- 计数为 0 时**不得**渲染（现状违规：导出页「逐条问题与来源（0）」仍占位）。

#### Table
- **行数 > 50 必须分页或虚拟滚动**（现状违规：来源文件表 209 行 → 页高 9,788px）。
- **某列取值同值率 > 60% 时，该列不应作为逐行徽章**，改为顶部筛选 + 行级标记。
- 数字列右对齐、等宽字体。

#### Drawer / Dialog
- Drawer 内容顶部**必须**放 `<Toolbar variant="dense" />`（见 §2.7）。
- Dialog 宽度：`sm` 确认框 / `md` 表单；**不用 `fullScreen`**（1366 屏不需要）。

#### 四态组件（**强制复用**）
`<LoadingState />` / `<EmptyState />` / `<ErrorState />` / `<ProgressStages />` —— **禁止**在页面里手写第二套。

| **token 消费** | 颜色/圆角/间距/动效**只能**来自 `theme.ts` 或 `useTheme()` |

### 4.4 性能预算（**回归即失败**）

> **⚠️ 修订（2026-10-13，R06 = ③「两者同时卡」）**：入口 chunk 预算由 **30 KB 改为 54 KB**，
> 并**新增三项同时卡**。改的是**数字**，不是**原则**——「防游戏指标」那条仍然生效，而且更硬了。
>
> **为什么原值不成立**：30 KB 是在 `main` 线的架构下定的（那边入口 21.8 KB）。
> 本线入口 49.9 KB，但**首屏 JS 总量 762 KB / 5 请求**，而 `main` 是 **1,058 KB / 15 请求**
> —— **本线两项都明显更好**。两线只是「什么时候下载什么」的策略不同：
> 本线把更多东西放进懒加载 chunk，于是入口偏大、首屏总量偏小。
>
> **单看入口会同时误判两个方向**：既误判本线「超标」，也**放行**「把代码挪进预加载 vendor」
> 那种假优化（入口小了、首屏反而更大）。规范原文自己写的「入口变小不等于变好」正是这个意思。
>
> **入口 54 KB 的构成（都是首屏必需，不可再拆）**：
> `theme.ts` 样式覆写 ≈10 KB（必须在首帧前应用）· `App.tsx` 外壳 JSX ≈9 KB ·
> `glossary.ts` 术语唯一来源 ≈5 KB · 9 个侧栏图标 ≈4 KB · 路由/store/api/基础组件 ≈22 KB。
> 要压回 30 KB 只能把其中一块拆成懒加载，代价是**首帧闪烁或侧栏延迟**，而**收益为零**（本机 HTTP）。
> 54 KB = 实测 + 约 10%，作为**棘轮**：不假装 30 KB 可达，但挡住**趋势性增长**
> （每次改动涨 1 KB，一年后就是 +100 KB——这才是真正要防的）。

| 指标 | 预算 | 本线实测（2026-10-13） |
|---|---|---|
| 入口 chunk | **≤ 54 KB** | 49,856 B ✅ |
| 首屏 JS 总量 | **≤ 1.1 MB** | 762 KB ✅ |
| 首屏 JS 请求数 | **≤ 16** | 5 ✅ |
| `auto-animate` | **不得进首屏** | 懒加载 ✅ |
| 单页 `pageerror` | **0** | 0 ✅（30 次采集） |

**防游戏指标规则**：**入口变小不等于变好**——必须同时看首屏请求数与总量。
曾出现"入口 30,790→23,569B"实为把代码挪进预加载 vendor 的假象。
**门禁**：`frontend/scripts/check-budget.mjs`（已接入 `npm run build`，**三项同时卡**）。

### 4.5 客户端外壳（`editions/desktop/`，规划中）附加规范

客户端化方案确定走 **pywebview + 系统 WebView2**（外壳层 +3–8MB），因此新增以下**交互契约**：

| 项 | 规范 |
|---|---|
| 窗口 | 无地址栏、无黑窗；**单实例**（重复双击聚焦已有窗口） |
| 关闭 | 点 × **最小化到托盘**（不是退出） |
| **自动保存明示** | 常驻一行「**已自动保存 · 上次编辑 X 分钟前**」——现状**从不显式告知**，导致老师误以为丢数据 |
| 恢复入口 | 提供「**继续上次的卷**」（`currentPaperId` 已持久化，只是没有入口） |
| 首启引导 | 一次性，指向"导入 → 找题 → 组卷 → 导出"四步 |
| 状态库 | 客户端 UX 状态放 `outputs/webui/client_state.db`，**绝不写进 `bank.db`** |
| 主题 | **必须跟随系统深色**（客户端没有浏览器地址栏作参照，深色不一致会更刺眼） |

## 7. 明确不做 / 已知局限

1. **不做**：实时协同编辑、在线答题/阅卷/学情分析、音视频形态、多语言、移动端原生、Mac/Linux 客户端（导出硬依赖 Windows）。
