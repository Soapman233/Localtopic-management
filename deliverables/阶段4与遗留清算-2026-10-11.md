## 一、① 真实读屏（NVDA 2026.2）实测

### 方法：hook「所有语音必经的单一漏斗」

真实读屏的难点是**捕获 NVDA 到底念了什么**。做法是写一个 NVDA **add-on 全局插件**，
hook `speech.manager.SpeechManager.speak` —— NVDA 内部**所有**语音（焦点播报、live region、
对象导航）最终都汇集到它。因此捕获到的是 **NVDA 真正决定要念的内容**，
而不是「浏览器无障碍树」。

**hook 有效性证明**：插件 `__init__` 主动念一句自检语 `SRVERIFY SELFTEST 12345`，
该句出现在日志中 → 链路通畅。

### 实测原文（节选，`MGR` 行 = 实际播报）

```
组卷工作台  初中物理题库  Google Chrome for Testing  窗口
可点击  相同页  链接  跳到主内容                      ← skip-link
横幅区 路标  初中物理  题库与组卷
主导航  导航区 路标  列表  4 项  日常备课              ← nav 地标
按钮  当前页  组卷工作台边找题边组卷,左题库右试卷      ← aria-current
主要内容区 路标  标题 1 级  组卷工作台                ← main 地标 + h1
警告  题库中「 难度 」尚无标注数据(覆盖率 0 百分号 )…
```

| 3 | Tab 到侧边导航 | ✅ 通过（`主导航 导航区 路标` + `按钮 当前页`） |
| 4 | 打开「切换试卷」抽屉 | ⚠️ **部分**——名字与内容正确，但 **NVDA 未念出「对话框」角色词** |
| 5 | 抽屉内关闭按钮 | ❌ **未验证**——DOM 有 `aria-label="关闭"`，但未捕获到播报 |

| 8 | 路由改 `document.title` | ✅ 通过（导航后播报 `找题 … 窗口`） |

### 关于「NVDA 不念对话框」——做了对照实验才下结论

DOM 有 `role="dialog"`，CDP 无障碍树确认**计算角色就是 dialog**；但 NVDA 只念名字。

于是写了**最小参照页**（`<div role="dialog" aria-labelledby tabindex="-1">`）做对照，
NVDA 对它的处理**与本项目抽屉完全相同**（念名字、不念角色词）。

→ **判定：抽屉语义已正确暴露，NVDA 的处理与标准参照 ARIA dialog 等价。**
但因此**不能声称「NVDA 会念出对话框」**。若验收方要求念出角色词，需另议机制（本轮未验证）。

### NVDA 工程踩坑（已进项目记忆，以后不用再踩）

1. `nvda.exe` 启动器受**残留单实例互斥量**影响会**静默退出**、不产生日志 → 须用 `nvda_noUIAccess.exe`
2. add-on 的 `manifest.ini` 里 `description` **含英文逗号会被 configobj 解析成 list** → NVDA 报错并**静默跳过**
3. 中文 argv 经控制台代码页会损坏 → 窗口匹配必须用 **ASCII 标记**
4. **捕获依赖浏览器持有 OS 前台**；本机共享且有人在用，他人抢前台会导致片段丢失

### 局限（如实声明）

**这不等于「产品已无障碍」**。未做：NVDA 浏览模式整页朗读、按地标/标题跳转实测
（Playwright 合成按键**不经过** NVDA 键盘钩子）、VoiceOver/Narrator、深色/窄屏/登录流程。

## 三、③ 阶段 4「两版适配」

### 3.1 后端用户与权限体系（423 项测试全绿）

**最关键的决策：鉴权数据放独立的 `outputs/webui/auth.db`**，
**绝不往交付数据 `bank.db` 里加表**——否则会污染交付库、改变其 sha256。

| 项 | 实现 |
|---|---|
| 角色 | `viewer`(read) / `editor`(read+write) / `admin`(全部) |
| 密码 | `pbkdf2_hmac(sha256)` + `hmac.compare_digest`，**纯标准库**、`iterations` 存表 |
| 会话 | 优先 `Authorization: Bearer`，**同时接受 Cookie** `qb_session`（可逆设计） |
| CLI | `python -m webui.auth user add\|list\|set-password`（`getpass`，不明文入命令行） |

**本地版零影响**：仅 `QB_EDITION=online` **且库中有用户**时才启用鉴权；否则单机全权。

**一处契约偏离的处置**：worker 返回 `auth_mode`（`off/token/session/token+session`）而非我锁定的
`auth_enabled`。我**没有让它改回**，而是在响应里**补一个派生字段**，两边都满足，并补断言守护。
顺带发现：`token` 模式（仅共享令牌、无用户）下**浏览器端无法登录**，故定为 `auth_enabled: false`
并写明该模式仅适用于 API/自动化。

### 3.2 前端两版适配（240 项测试全绿）

`VITE_DEPLOY_MODE`（**缺省 `local` 是安全默认**）、`AuthProvider`、`RequireAuth`（本地版**恒真透传**）、
`LoginPage`（懒加载）、声明式权限表 + `usePermission`/`Can`、顶栏用户与只读提示（**本地版渲染为空**）。

**三个刻意的设计选择**：

1. **令牌在 `api/client.ts` 全局自动附加** —— 若让每个 api 函数各传 header，
   新增端点时**漏一个就出洞**。
2. **`useAuth` 缺 Provider 时抛错，不静默兜底** —— 静默兜底会让"忘了套 Provider"变成**静默放行**
   （`RequireAuth` 直接透传），是**安全相关的失败模式**。测试侧改为补上生产同款 Provider。
3. **`CodeSplitting` 的断言从「数量=9」改为结构性不变量** —— 新增 `LoginPage` 后它失败了，
   但**"数量"根本不是要守的性质**（改为"不得存在对 `./pages/` 的同步 import"）。

**最强的验收证据**：视觉回归 **8 页全部 0.00（像素级一致）**——阶段 4 对本地版**零影响**。

## 四、顺带修掉的 2 处真实缺陷

### 4.1 builder 页 248px 横向溢出（**阶段 5 引入**）

- **现象**：`documentElement.scrollWidth 1614 > clientWidth 1366`
- **根因**：sr-only `h1` 写了 `width: 1`，但 **MUI 的 `sx` 把数字当 spacing 乘数** ——
  实测产出 `width: 1366px`（= 视口宽），该 h1 恰好撑出等于侧栏宽的 248px
- **修法**：改显式 `'1px'` 字符串 + 锚定 `top/left`
- **实测**：h1 现为 1×1，`overflowX` **0**

### 4.2 窄屏抽屉「关闭」按钮被固定顶栏遮挡

- **根因**：项目把 AppBar 的 `zIndex` 设为 `drawer + 1`（为压住常驻侧栏），
  于是固定顶栏盖住了**临时抽屉的顶部**（Esc / 点遮罩仍可关，但那是"能关"不是"好关"）
- **修法**：按 MUI 惯例在抽屉内容顶部放 `<Toolbar variant="dense" />` 占位（**4 处**）
- **实测**：关闭按钮移到 `y=60`，`elementFromPoint` 命中按钮自身（`clickable=true`）

### 4.3 视觉回归机制的重要修正

实测发现：**同一份代码、同一视口，两次采集的截图字节并不完全一致**
（`builder` 约 40px，`mean ≤ 0.0017`）。→ 已写进 README：

> **判定一律以像素阈值（`mean_diff` / `pct_gt32`）为准；不要用 `sha256` 判断基线是否被换过。**
