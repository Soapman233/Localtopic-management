## 三、手机 / 电脑互通 —— **确实是缺口，而且项目文档早有记录**

### 3.1 现状（实测）

当前便携版**默认只监听 `127.0.0.1`**——**只有本机能访问**，
手机、平板、同事的电脑**都打不开**。

项目文档对此**早有明确记录**，不是新发现：

| 出处 | 原文 |
|---|---|
| `outputs/前4阶段验收报告.md:229` | 「**无异地访问**（阶段5 未开始）→ 老师**在家无法使用**」 |
| `AGENTS.md:442` | 「10 人团队可用性 ❌ 未达标（无界面权限体系、**无异地访问**、并发形态未解决）」 |
| `README.md:273` | 「**纯本地单机**：无账号体系、**无异地访问**」 |
| `outputs/webui/流程重构设计.md:453` | 移动端：「本系统以桌面为主……窄屏只需"能用"，**不做移动端专门优化**」 |

### 3.2 但"改一行就能局域网用"——已实测

我刚在本机验证过：把监听地址改成全网卡后，

```
TCP 0.0.0.0:8750  LISTENING
127.0.0.1:8750/api/health   -> 200
192.168.0.103:8750/api/health -> 200      ← 局域网可达
/api/papers  带令牌 -> 200
/api/papers  无令牌 -> 401                ← 鉴权生效
/api/papers  错令牌 -> 401
```

**即：`QB_HOST=0.0.0.0` + `QB_AUTH_TOKEN=<令牌>`，同一 WiFi 下手机浏览器就能用。**

### 3.3 三个选项（按投入从低到高）

| 方案 | 做法 | 能解决 | 代价 / 风险 |
|---|---|---|---|
| **A. 局域网访问** | 启动时设 `QB_HOST=0.0.0.0` + `QB_AUTH_TOKEN` | **手机/平板在同一 WiFi 下可用**（家里、办公室） | 极低。⚠️ **必须同时设令牌**，否则同网段任何人可读写题库 |
| **B. 异地访问**（原「阶段5」） | 云服务器 + 域名 + HTTPS（`editions/online/` 已有 Dockerfile / docker-compose / nginx.conf 骨架） | **在任何地方都能用**（含手机 4G） | 服务器费用 + 运维；需处理并发写（当前 JobManager 是单线程串行） |
| **C. 移动端专项优化** | 针对窄屏重做交互 | 手机上**好用**（而非只是"能用"） | 产品决策。现设计**明确降级**：窄屏只保证能用 |

### 3.4 我的建议

1. **先做 A**（几乎零成本）——老师最常见的场景是"在家/在办公室用手机看看题、微调一下"，
   局域网方案能覆盖其中相当一部分。**但必须默认开启令牌鉴权**，否则等于把题库裸奔在局域网上。
2. **B 是真需求但需要决策**：涉及费用与运维，且要解决并发写。
   注意 `前4阶段验收报告.md:229` 把"老师**在家无法使用**"列为**阻塞项**——如果老师确实要在家用，B 绕不过去。
3. **C 建议先不做**：现有研究没有支持"移动端深度使用"的证据，
   且手机屏上组卷（双栏拖拽）体验天然受限。先看 A/B 的实际使用数据。
