## 0. 一句话结论

> 当前前端是一个**工程质量偏高、产品可用性偏低**的内部工具：类型安全干净（tsc 通过、0 个 `@ts-ignore`）、状态设计克制（zustand 只存选择、后端为唯一真相）、关键安全路径（导出门禁）已抽为单一实现。但它**把"开发者视角的技术真相"直接暴露给了老师**（`scan index`、`snapshot_digest`、门禁、降级解锁、快照锁定），且**信息架构是"功能平铺"而非"任务流"**，在教师主流分辨率 1366×768 下核心的"边组边看"体验默认不可见。用户"面向大众可用性低、需大规模重构"的判断**成立**，但重构重点应是**信息架构 + 术语/交互 + 两版适配**，而**不是**推倒技术栈重写。

## 3. 技术债与风险

### 3.1 类型安全【确认——实际很好，与常见"债务"预期相反】

| 指标 | 实测 | 结论 |
|---|---|---|
| `npx tsc --noEmit` | **通过（exit 0）** | 类型干净 |
| `@ts-ignore` / `@ts-expect-error` | **0** | 无类型逃逸 |
| `: any` / `as any` | **2**（且均在 `livePreview.css:193-194` 的 `anywhere` 字符串，**误报**） | 实际 0 |
| `as unknown as` | **7** | 均为 `window.__debug` 挂载（`useExportGate.ts:366`、`PaperBuilderPage.tsx:342`、`LivePreviewPanel.tsx:274`）或 document.fonts 探测，属合理边界 |
| `eslint-disable` | **6** | **全部**为 `react-hooks/exhaustive-deps`（`useExportGate.ts` 占 4 处）→ 依赖数组治理有隐患，重构时须复核 |

**结论**：类型债务**不是**本项目的主要问题；不应以"类型安全"为由重写。

### 3.2 测试覆盖【确认——重大缺口】

- 前端测试仅 **2 个文件 / 470 行 / 26 项**（`tests/preview-and-theme.test.cjs` 233 行、`tests/frontend-fixes.test.cjs` 237 行）。
- 机制：`ts.transpileModule` + `node:test` + `react-dom/server`，**无 DOM、无 Testing Library、无 QueryClientProvider**（`frontend-fixes.test.cjs:11-13` 明确承认）。
- 后果：**含 `useQuery` 的页面无法挂载测试**，改为"**源码级字符串护栏**"（如断言"删除入口经确认框"靠读源码字符串），再配合人工验收。
- **风险**：§4 的重构会大量改动页面结构，**现有测试无法提供真正的行为回归保护**——字符串断言在重命名/换行后即失效或误报。

### 3.3 构建与性能

- 单 chunk **1,049 kB**（未 gzip 前），首屏需下载/解析全部页面（含 4 个低频治理页）。
- 无 `manualChunks` / 无路由级 `lazy`。
- KaTeX 字体 59 个文件随构建产物（`webui/static/assets/KaTeX_*`），体积不小但属必要。
- `vite.config.ts:20-28` `emptyOutDir:false`——旧产物无害残留（文件名哈希），但会累积。

## 4. 重构方案

### 4.1 目标与原则

**要达到的状态**：老师**零培训**能完成"搜『浮力』→ 组 8 题 → 导出学生版"；界面上**不出现开发者术语**；在 1366×768 上核心体验默认可见；为线上版预留登录/权限位。

**原则**：
1. **不推倒技术栈**——MUI + zustand + react-query 选型合理，保留。
2. **渐进式、每阶段系统可用**——不做大爆炸重写（见 §4.7）。
3. **后端为唯一真相**——沿用"前端不缓存整卷"的既有约定。
4. **门禁语义不弱化**——"导出的一定是看过的"是安全约束，重构只改**表达方式**，不改判定逻辑。
5. **明确不做**：不迁移到 shadcn/Radix（重写成本极高、收益低）；不引入 Redux；不做移动端专门优化；不做所见即所得公式编辑器（MathLive，PRD P2-1 已缓）。

### 4.2 架构方案

#### 4.2.1 目录结构：从"按类型"转向"按 feature"（渐进）

```

├── app/                      # 应用外壳（原 App.tsx/router.tsx/main.tsx 归位）
│   ├── App.tsx  router.tsx  providers.tsx  ErrorBoundary.tsx
│   └── navigation.ts         # 导航定义（含分组元数据）
├── features/                 # 按业务域切分（核心改动）
│   ├── search/               # pages/SearchPage + hooks/useSearch + 筛选逻辑
│   ├── builder/              # pages/PaperBuilderPage + components/{PaperPanel,PaperSwitcher,...}
│   ├── export/               # pages/ExportPage + components/{ExportDrawer,PreviewViewer} + hooks/useExportGate
│   ├── question/             # pages/QuestionDetailPage + components/{QuestionEditor,FormulaEditor,VersionHistory}
│   ├── review/               # knowledge + formula 两个复核页
```

**迁移策略**：先建 `features/` 骨架，**按页逐个搬迁**（一次一页，搬完即回归），不一次性移动全部文件。搬迁期允许旧路径 re-export 过渡。

#### 4.2.2 状态管理：保留 zustand，做减法

- 保留三 store 分层，**不引入新状态库**。
- `uiStore` 的**门禁状态**（`previewFresh` 等 6 个字段，`uiStore.ts:99-140`）建议**内聚到 `useExportGate` 的 store slice**或独立 `exportGateStore`，使 `uiStore` 回归"纯 UI 偏好"。理由：门禁是安全关键路径，独立后更易单测与审查。
- 消除 `eslint-disable exhaustive-deps`（6 处）——重构时补全依赖或用 ref/`useEvent` 模式。

#### 4.2.3 数据层收敛

- 新增 `lib/api/queryKeys.ts`：**集中定义全部 queryKey 工厂**（`qk.search(params)`、`qk.paper(id)`、`qk.exportData(id,mode,tpl)` …），mutation 失效统一走工厂。消除"新增 key 漏失效"。
- 新增 `lib/api/errors.ts`：集中后端 `code` → 用户文案映射（`40001-6/40401-8/40901-3/40904/40905/50001`），页面不再各自 `if (code===...)`。
- 抽 `features/search/hooks/useQuestionFilters.ts`：封装"关键词防抖 + URL 同步 + queryParams/facetsParams"，**检索页与组卷页共用**，消除 §1.6 的 80 行重复。
- 抽 `features/shared/constants.ts`：`ANSWER_MODES`/`TEMPLATES`/`DIFFICULTIES` 单一来源（消除 §1.6 三处重复）。

#### 4.2.4 路由重构（含登录态守卫，为线上版预留）

```
createHashRouter([
  { path: '/login', element: <LoginPage/> },              // 新增（线上版启用）
  { path: '/', element: <RequireAuth><App/></RequireAuth>, children: [
      { index: true, element: <Navigate to="/builder"/> }, // ★ 默认落地页改为「组卷」
      { path: 'builder', ... },  { path: 'search', ... },
      { path: 'export', ... },   { path: 'question/:id', ... },
      { path: 'manage', element: <ManageLayout/>, children: [  // 治理分组

          { path: 'sources', ... }, { path: 'stats', ... },

      { path: 'settings', ... },
  ]},

```

- `RequireAuth`：本地版为**恒真透传**（无登录）；线上版校验会话后放行，否则跳 `/login`。用**一个开关**（构建期环境变量 `VITE_DEPLOY_MODE=local|online`）切换，避免两套代码。
- **默认落地页从 `/search` 改为 `/builder`**（`router.tsx:40` 现为 search）：对齐"老师最高频是组卷"，减少一次跳转。

### 4.3 设计系统 / 组件库方案

#### 4.3.1 现状判断

- 组件 UI **90%+ 走 MUI `sx`**；Tailwind **0 使用**（§1.7）；`theme.ts` 与 `tailwind.config.js` **token 重复且都无消费方**。
- 因此"MUI + Tailwind 混用割裂"的实质是：**Tailwind 是冗余依赖，而非真实混用**。

#### 4.3.2 推荐方案：**统一到 MUI 主题化，移除 Tailwind**

| 维度 | 内容 |
|---|---|
| **推荐** | 以 `theme.ts` 为**唯一设计 token 来源**，扩充 token（颜色/间距/字号/圆角/阴影），全部组件通过 `sx`/`styled` 消费；**移除 Tailwind 依赖**（`package.json`、`postcss.config.js`、`tailwind.config.js`、`index.css` 的三段 `@tailwind`） |
| **理由** | ① 现状 0 工具类使用，移除**零样式回归**；② 消除双 token 源；③ 减少构建步骤与依赖；④ MUI 主题已支持暗色/主色（`SettingsPage` 已消费） |
| **迁移代价** | **极低**（半天）。风险：需确认无隐藏 Tailwind 类（已 grep 确认为 0）；`index.css` 仅保留 KaTeX/公式相关样式 |
| **不推荐** | 引入 shadcn/Radix：需重写全部 MUI 组件（Button/Chip/Select/Dialog/Table/Accordion…），成本数周，收益仅为"样式更可控"，**不成比例** |

| `zod` | 后端响应/表单运行时校验，防契约漂移（§3.4） | 高 |
