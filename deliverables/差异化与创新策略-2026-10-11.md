# 差异化与创新策略：本项目 vs 市面成熟方案

> 2026-10-11 ｜ 配套：`deliverables/对标产品调研-知识库与教案库-2026-10-11.md`
> 前提：本项目 = 约 10 名中学教师（首科初中物理）的**私有题库**，输入是**教师自有 DOCX**，输出是**公式可编辑的成品试卷**。

---

## 0. 一句话定位

> **商业平台卖的是「题库订阅」，本项目做的是「自有资料的资产化」。**

对老师的说法：

> **"把你压箱底的旧卷子，变成能搜、能查重、能重组的活题库；导出来的卷子，公式还能直接改。"**

对学校/教研组的说法：

> **"不买题库，也不换工具——把你自己的资料变成资产，数据留在自己手里。"**

---

## 1. 先划边界：这五个战场坚决不打

差异化不是"哪里都更强"，而是**主动放弃**打不赢的战场。

| 不打 | 原因 |
|---|---|
| **海量题库供给** | 学科网/菁优是千万级题量 + 1000 人更新团队，10 人团队不可能赢 |
| **在线考试 / 扫描阅卷** | 需要答题卡、扫描仪、阅卷引擎、监考，是完全不同的产品线 |
| **学情分析 / 个性化报告** | 依赖考试数据闭环；本项目不做考试就没有数据源 |
| **移动端 App / 小程序** | 交付物是纸质试卷，移动端收益低、维护成本高 |
| **平台级资源分发** | 涉及版权、审核、运营，是平台生意不是工具生意 |

**结论**：正面比"题多"必输。必须在**别人的题库打不到的地方**建立优势。

---

## 2. 差异化根基：三份「别人拿不到」的资产

这是全部差异化逻辑的源头——不是技术，是资产。

| 资产 | 为什么别人拿不到 | 本项目的用法 |
|---|---|---|
| **校本存量试卷语料**<br>209 份真实卷 / 7945 题 / 17771 公式 | 商业平台只有公共题库，**没有你学校历年自编卷**；且教师资料本就不外传 | 建库、跨卷查重、变式聚类 |
| **教研组的默会知识**<br>哪个题难、考什么、哪年出过 | 平台没有你的老师 | 人工在环标注，把经验固化成元数据 |
| **真实的交付形态**<br>纸质试卷 = 可编辑 DOCX | 商业产品交付的是网页 / 它们的 PDF / 它们的排版 | 直接产出 Word 成品 |

### ⚠️ 必须先纠正一个自我误判

**核心技术（MTEF→LaTeX）不是护城河。** 理由：

- `mtef-py` 是 **Apache-2.0 开源库**，别人也能用；
- **Pandoc 走的就是 LaTeX → 原生 OMML 同一条路线**（已独立佐证）。

所以真正的壁垒是：**"你拥有这份语料 + 这套教研流程"**，而不是"你会写这段代码"。
**这决定了策略重心：把力气花在"资产化 + 工作流"，而不是"炫技式转换率"。**

## 3. 六个创新点

每个创新点按「是什么 → 别人为什么不做 → 现有底座 → 产品化表达 → 怎么验证」拆开。

### 创新 1 · 存量资料资产化引擎（Upload → Bank）

| 项 | 内容 |
|---|---|
| **是什么** | 把一份普通 DOCX 试卷（含旧式 MathType 公式、图片、答案）**一次性**转成结构化题库：题目、公式（LaTeX）、图片、答案、解析、来源全要素入库 |
| **别人为什么不做** | 商业平台不需要"读你的卷子"——它们自己就是题库源头；开源项目（Moodle/xzs/SurveyKing）的题目入口是**结构化录入或纯文本导入**，没有"从真实排版 DOCX 反向抽取（含旧式 MathType 公式对象）"的能力 |
| **现有底座** | ✅ 已实现：`pipeline/`（209/209 成功、98.91% 转换率、65 秒）；`bank/importer.py`（幂等 + 单文件原子事务） |
| **产品化表达** | 界面上的动作叫 **「导入旧卷」**，不叫"数据预处理"。落地页一句话：**"拖一份卷子进来，30 秒后它就在题库里了。"** |
| **怎么验证** | 让一位老师**在不看文档的情况下**导入 3 份他自己的卷子，计时并记录卡点 |

> **这是本项目最独特的能力**：市面上的方案都是"从结构化到结构化"，只有这里是"**从排版成品反向工程出结构化资产**"。难度最高，也最不可替代。

### 创新 2 · 跨卷查重 + 题源溯源

| 项 | 内容 |
|---|---|
| **是什么** | 出卷时自动提示："这道题和你 **2023 年期中卷** 第 12 题重复度 92%"；每道题都能追溯到**来自哪个文件、原题号是多少** |
| **别人为什么不做** | 商业平台的查重是**公共题库内部**查重，管不到你的自编卷；而你的自编卷恰恰是最容易自我重复的地方（隔年复用、教研组之间重复出题） |
| **现有底座** | ✅ 部分具备：`bank/textutil.py::content_hash`（题目内容指纹）、`source_files` 表（来源文件 + 原题号）、`bank/query.py`（bigram + FTS5 + bm25） |
| **需要补的** | ① **公式指纹**（公式已是 LaTeX，可归一化后哈希）；② 组卷时的实时查重拦截；③ 溯源 UI（点题目 → 看来源卷） |
| **产品化表达** | **「防撞题」**——组卷右栏常驻提示："本卷与历史卷重复 3 题" |
| **怎么验证** | 用现有 7945 题跑全量两两查重，人工抽检 20 组判定准确率；**必须构造反例**（改了数字的变式题不该判为重复） |

> 这是**只有语料所有者才能做的功能**，也是最容易让老师"哇"一下的功能。

### 创新 3 · 自有题库内的变式题聚类（举一反三）

| 项 | 内容 |
|---|---|
| **是什么** | 选中一道题 → 找出**自有题库里**考同一知识点、结构相似的题，一键加进试卷做成"变式训练组" |
| **别人为什么不做** | 学科网确有"举一反三"（其开放平台 API 明确列出），但推的是**它的公共题库**；本项目推的是**你自己的题**——老师更信任、更贴教学进度、且已经讲过 |
| **现有底座** | ⚠️ 半成品：`bank/query.py` 的 bm25 检索可用作基线；`formulas` 表可做公式级相似 |
| **需要补的** | 公式指纹 + 文本 TF-IDF/向量 的混合相似度；聚类阈值需人工校准 |
| **产品化表达** | 题目卡片上的 **「找同类型题」** 按钮 |
| **怎么验证** | 抽 30 道题，人工判断推荐结果 Top5 是否"同类型"；**准确率不到 70% 就不该上线**（宁可没有，不可误导） |

### 创新 4 · 试卷快照 = 命题版本控制（可复现）

| 项 | 内容 |
|---|---|
| **是什么** | 已生成的试卷**冻结**为快照：即使原题后来被修改（v1→v2）、被下架、被重新标注，**去年发出去的那份卷子仍然能一字不差地重新打印出来** |
| **别人为什么不做** | 商业平台里"试卷"通常只是**对题的引用**，题变了卷子就变了；它们不承诺"历史可复现" |
| **现有底座** | ✅ **已实现且已验证**：`bank/paper.py::snapshot_json` 在加题时把 text + formulas + images + source **全量拷贝**；实测改题 v1→v2 后，已出卷仍取 v1 的原公式原图 |
| **产品化表达** | **「试卷版本」**——像文档的版本历史，可以对比"今年这卷 vs 去年这卷改了哪几题" |
| **怎么验证** | 已有反证成立（改题后旧卷不变）；补一条：**跨学期**导出同一份卷子，字节级比对 |

> 这是本项目**技术上已经跑通、但完全没被产品化表达**的能力。价值主张很强：**命题可追溯、教学证据链**。

### 创新 5 · 教研组共建 + 人工在环标注

| 项 | 内容 |
|---|---|
| **是什么** | ① 老师把认可的题加入**教研组精选题库**并署名（学菁优网"云端精选题库"）；② 把"知识点/难度/考查点"的标注做成**协作工作流**，而不是自动推断 |
| **别人为什么不做** | 平台的标注是**算法批量打的**（且常不准）；本项目的立场是 **"源数据没有的，绝不编造"**（`difficulty` 当前刻意保持 0% 而非瞎猜） |
| **现有底座** | ✅ 已有骨架：`bank/review.py`（待复核队列 196 条）、`bank/labels.py`（`review_items()` / `preview_decision()`）、`bank/edit.py`（`save_question()` 留版） |
| **需要补的** | ① **贡献者字段**（当前 `asset_manifest` 的 author 全是"待补充"，是明确缺口）；② 标注任务分配与进度看板；③ 标注结果的**一致性检查**（两位老师标同一题是否一致） |
| **产品化表达** | **「集体备课」**——不是"数据治理"，是"把老教师的经验留下来" |
| **怎么验证** | 让 2 位老师独立标注 20 题，测一致率；一致率过低说明标注口径需要先定义 |

> 商业平台做不到这件事，因为**它们没有你的老师**。这是最难被复制的资产。

### 创新 6 · 可编辑 DOCX 交付 + 零公式授权依赖

| 项 | 内容 |
|---|---|
| **是什么** | 导出的试卷在 **Word 和 WPS 上都能直接双击改公式**；不依赖 MathType 授权、不依赖任何付费插件 |
| **别人为什么不做** | 学科网的 Word 导出**压倒性使用 MathType 对象**（其目录 DSMT4 达 11,845 个）——**拿到卷子的人必须装 MathType 才能改**；开源方案多用网页渲染，根本不给 DOCX |
| **现有底座** | ✅ **已实现并经双端实测**：`bank/export.py` 输出原生 OMML（`word/embeddings=0`，非图片冒充）；实际改字符→保存→重开→比对通过 |
| **产品化表达** | 不当作"技术指标"讲，而是讲 **"拿到卷子的老师不用装任何东西就能改"** |
| **怎么验证** | 已有；补一条：让**没装过 MathType 的老师**在自己电脑上改一道题并保存 |

> 这一条的**成本结构**与商业产品根本不同：别人是"每台机器一份 MathType 授权"，本项目是"零边际成本"。

## 4. 差异化定位矩阵

| 维度 | 学科网/菁优（商业） | 国家平台/OER（公益） | Moodle/xzs/SurveyKing（开源） | 知识库（Outline/语雀） | **本项目** |
|---|---|---|---|---|---|
| 内容来源 | 平台供给 | 平台供给 | 手工录入 | 手工撰写 | **自有存量 DOCX** |
| 核心动作 | 选题 → 在线组卷 | 浏览 / 下载 | 建课 → 在线测验 | 写文档 | **旧卷入库 → 查重 → 组卷 → 导出** |
| 交付形态 | 网页 / 它们的 PDF / MathType Word | 下载课件 | 在线答题 | 网页文档 | **可编辑 DOCX（Word+WPS）** |
| 公式 | MathType（需授权）/ 图片 | 多为静态 | 网页渲染 LaTeX | 无 | **原生 OMML，零授权** |
| 自有语料价值 | 不涉及 | 不涉及 | 不涉及 | 弱 | **★ 核心资产** |
| 查重 | 公共题库内 | 无 | 无 | 无 | **★ 跨自有卷查重** |
| 试卷可复现 | 弱（引用式） | — | 弱 | — | **★ 快照冻结** |
| 用户规模假设 | 万级 | 全国 | 校级以上 | 团队 | **10 人小团队** |
| 成本结构 | 订阅费 / 授权费 | 免费 | 自建运维 | 订阅 | **零授权 + 自运维** |

## 5. 产品化表达：换个说法，价值才被看见

同样的能力，说法不同，感知差十倍。**当前项目最大的浪费是：把"资产化"说成了"预处理"，把"命题版本控制"说成了"快照"。**

| 现状说法（技术口径） | 建议说法（教师口径） |
|---|---|
| 数据预处理 / 导入 | **「导入旧卷」** |
| 快照锁定 / snapshot_json | **「试卷版本」**（去年那卷还能原样打出来） |
| 知识点标签 / 元数据补全 | **「集体备课标注」** |
| 查重 / content_hash | **「防撞题」** |
| 变式题检索 | **「找同类型题」** |
| 原生 OMML / 公式转换率 99.69% | **「导出的卷子，公式直接能改」** |
| 私有部署 / 零依赖 | **「资料不出校门」** |

> 项目已有 `frontend/src/lib/glossary.ts` 作为术语唯一来源，且已实现"原始技术字段默认不渲染"。**差异化叙事应当写进这套术语体系**，而不是停留在文档里。

## 6. 落地路线

### P0 · 把已有的能力讲清楚（0 开发，最高性价比）
1. **术语与文案改造**：按 §5 表格替换前端话术（改 `glossary.ts` + 页面文案，注意同步 `tests/preview-and-theme.test.cjs`）。
2. **「试卷版本」可见化**：导出页展示"本卷冻结于 X 时间 / 基于 v1 版本"。
3. **溯源可见化**：题目详情页展示来源卷名 + 原题号（数据已在 `source_files`，只差展示）。

### P1 · 把独有能力做出来（中成本，高差异）
4. **公式指纹 + 跨卷查重**：组卷时实时"防撞题"提示。
5. **变式题聚类**：题目卡片"找同类型题"（准确率 <70% 不上线）。
6. **共建机制**：贡献者字段 + 精选题库 + 标注任务看板。

### P2 · 结构性补课（不做则团队化落地无望）
7. **认证与权限**（当前 `webui/` 零认证代码）——10 人共用的前提。
8. **异地访问**（当前只绑 `127.0.0.1`）——硬要求，也是当前最大阻塞。
9. **数据分发**（`bank.db` 62MB 不分发）。

> ⚠️ **顺序很重要**：P0/P1 是"差异化"，P2 是"能不能用"。**差异化不能替代可用性**——一个访问不了的系统，差异化等于零。

## 7. 风险与反方论证（必须诚实）

| 风险 | 说明 | 应对 |
|---|---|---|
| **资产化是"一次性收益"** | 209 份卷做完就没了；若老师不持续把新卷入库，价值会衰减 | 把"导入旧卷"做到 **5 分钟内完成**，并做成考后习惯动作 |
| **价值不被感知** | 老师不会主动点"查重"；不提示等于没有 | 所有差异化功能必须是**主动推送式**（组卷时自动提示），不能藏在按钮里 |
| **技术护城河不存在** | `mtef-py` 是开源库，Pandoc 走同样路线 | 不把资源投在"提升转换率"，投在"资产 + 工作流" |
| **🔴 最大的未验证假设** | 项目已验证**技术可行**（30 题三路径、双端可编辑），但**从未验证"老师愿意用"** | **必须做一次真实教师试用**：给 2–3 位老师，让他们完成"导入一份卷子 → 组一套卷 → 导出打印"，观察卡点。**这一步的价值高于任何新功能** |
| **小团队无运维能力** | 10 人教研组不可能配 IT 运维 | 保持"一键启动"（已有 `editions/local/启动题库.bat`）、零外部依赖 |
| **反方观点** | 也许老师根本不在乎"公式可编辑"，只要卷子能打印、看着对 | 这正是上一条试用要回答的问题；**不要在没验证前继续加大技术投入** |

---

## 8. 一句话总结

> **不要和学科网比题多，要和它比"谁更懂你手上的卷子"。**
> 差异化不在"转换率 99.69%"，而在 **"你的卷子只有你能给我"**——
> 资产化（创新 1）+ 自有语料洞察（创新 2/3）+ 命题可复现（创新 4）+ 经验固化（创新 5）+ 零成本交付（创新 6）。
> **而这一切的前提，是先让老师真的用起来（P2 + 试用验证）。**
