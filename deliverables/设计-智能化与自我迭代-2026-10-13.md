# 设计：让应用更懂老师，并具备自我迭代能力

**日期**：2026-10-13
**性质**：**设计文档（不含实现）**。四部分对应你提的四个方向，每部分给出**实现思路 + 预期效果 + 诚实边界**。
**前置**：本设计的所有判断都建立在**对现有交付库的实测**上（见 §0），不是通用 AI 愿望清单。

---

## 0. 先说实话：现在可学的东西**几乎为零**

任何"从使用中学习"的方案，第一步都不是算法，而是**数据**。实测本项目的现状：

| 资产 | 实测 | 能不能学 |
|---|---|---|
| `question_labels` | **38,588 行**（知识点 32,936 / section 3,989 / chapter 1,663），`review_status` **全部是「待复核」** | ❌ **人工标签 = 0** |
| `paper_questions` | **33 行**（≈2 份卷） | ❌ 组卷历史 ≈ 0 |
| `question_versions` | 7,962 行，但 `change_source` **7,929 行为空** | 🟡 有版本、**没有"为什么改"** |
| `review_queue` | 196 行（公式复核队列） | 🟡 有队列，**处理结果未回流** |
| 行为日志（检索词/点击/加入/移除） | **后端、前端都没有埋点** | ❌ **完全没采** |

**三个直接结论**：
1. **"持续学习"目前无燃料**——必须先让数据产生，且**采集成本要低**；
2. **最大的监督信号被"工作量"堵死**：38,588 项逐条复核（约 772 页 × 50）**人工不可行**，
   所以"老师确认过标签"这件事**从未发生**。→ **让复核变得可行，是智能化的第一块地基**；
   ⚠️ **口径必须写清**（本项目铁律：指标要用 SQL 核实真实含义）：
   统计页显示的 **32,936 只算「知识点」命名空间**，而 **38,588 是全部命名空间**之和。
   两个数都对，**但含义不同**——引用时必须带口径，否则会得出错误的"工作量"估计。
3. **n≈1 个用户、n≈2 份卷** → **任何 ML / 协同过滤都是过度工程且不可解释**。

## 1. 设计原则（本项目特有，冲突时按序号优先）

| # | 原则 | 含义 | 反面（禁止） |
|---|---|---|---|
| **S1** | **可解释** | 每条推荐/学习结论都要能说出**理由**，老师能当场反驳 | 「系统觉得你需要这道题」 |
| **S2** | **可关、可清** | 每类信号**单独开关**；一键「别再推这类」；一键清空学习数据 | 学了什么、怎么学的都看不到 |
| **S3** | **永不挡主路** | 智能层是**叠加**：推荐失败 = 没有推荐，**不是报错** | 学习数据坏了就打不开应用 |
| **S4** | **不写交付库** | 学习数据放 `outputs/webui/learning.db`（与 `auth.db`/`client_state.db` 同级） | 往 `bank.db` 加表 |
| **S5** | **先够用，再聪明** | 数据不足时**只给规则、不给"个性化"**，并在界面**如实说明** | 用 2 份卷的数据假装懂老师 |

## 2. 第一部分：智能推荐与个性化适配

**按数据量分三层解锁**——这是本设计最核心的结构，因为"一上来就个性化"在 n=2 时必然是假的。

### L0 · 冷启动层（**0 份卷就能用**，不依赖任何学习）

不叫"推荐"，叫**智能默认**——全部由题库结构**当场算出**：

| 能力 | 怎么算 | 为什么有用 |
|---|---|---|
| 章节题量分布 | `count(*) group by chapter` | 老师一眼看到"哪些章节有料"，而不是空手翻 |
| 与已选题**相关性重排** | 同章节 / 同已确认标签 / 同来源 → 加权上提 | **边组卷边找题**时，下一题通常就在附近 |
| **"本次未用过"过滤** | 排除当前卷已含的题 | 避免重复，这是最低级的错但最常见 |
| 覆盖提示 | 当前卷的章节/题型分布 | 一眼看出"电学偏多、力学偏少" |

**预期效果**：**第一份卷子就有用**。这是唯一不依赖历史的一层，也是"够用就好"的底线。

### L1 · 结构复用层（**≥1 份卷即可用**，收益最直观）

> **核心洞察**：老师出卷的"教学风格"，**主要不体现在某道具体题，而体现在卷面结构**——
> 几个大题、每大题几道、题型怎么排、分值怎么给、要不要答案、用什么模板。

**实现：卷面结构指纹**（`paper_sections` + `paper_questions` 已经能算出来）

```
指纹 = 大题划分（名称/顺序/描述）
     + 每大题题数 + 题型分布（选择题 12 / 填空 6 / 计算 3…）
     + 分值方案（每题分值 / 总分 / 是否含答案与解析）
     + 模板 + 答案模式
```

**用法**：新建试卷时给两个入口——「**按《上次那卷》的结构开始**」「**按某份历史卷的结构**」。
选中后**自动建好大题骨架与分值**，老师只需往里填题。

**预期效果（可度量）**：`结构复用使用率`、`建卷到首题加入的耗时`。
**为什么这条优先**：它把"学习"落在**老师本来就反复在做的事**上，而不是猜他想搜什么。

### L2 · 题目推荐层（**≥3 份卷**才解锁，且**不用 ML**）

可解释的**加权打分**，每个信号**可单独关闭**：

| 信号 | 来源 | 权重 | 理由标签（给老师看） |
|---|---|---|---|
| **共卷共现** | 历史卷中同卷出现 | 最强 | 「和上次一起出过」 |
| 同章节 / 同标签 | 题库结构 + `question_labels`（**只取已确认的**） | 强 | 「同章节」「同知识点」 |
| **难度配比模仿** | 老师自己 `set_difficulty()` 标过的 | 中 | 「你标过"难"」 |
| 来源偏好 | 历史卷的来源文件分布 | 中 | 「你常从这份资料取题」 |
| 新鲜度 | 最近导入 / 编辑 | 弱 | 「最近导入」 |
| **回避** | 最近 N 份卷用过 → 降权；**被移除过 → 强降权** | 负向 | （不显示） |

> ⚠️ **难度这条必须诚实**：库里 `difficulty` 覆盖率 **0%**（源数据没有标注，
> 研究结论是"难度是事后实测属性"）。所以难度信号**只用老师自己标过的**，
> **绝不从题面猜难度**——那是编造。

### 个性化默认值（任何层都可用的低风险收益）

导出参数（答案模式/模板/分栏）、默认模板、常设分值 → **取最近一次**，
并在界面上显示"**为什么是它**"（「上次你用的是《考试》模板」）。

## 3. 第二部分：对教师行为与偏好的持续学习

### 3.1 采集什么（**本地、最小、可关、可查看**）

| 信号 | 采集点（现有代码位置） | 强度 | 用途 |
|---|---|---|---|
| **检索词 → 点击/加入的题** | `routers/search.py` + 前端点击 | 强 | 相关性学习 |
| **移除的题** | `papers` 移除接口 | **强（负信号，最有用）** | 回避列表 |
| **编辑题干/答案/解析** | `edit.save_question()`（`change_source` 已有） | 强 | **抽取质量诊断** |
| 难度标注 | `edit.set_difficulty()` | 强 | 难度配比 |
| **标签复核决定** | `labels.set_review_status()`（机制已有，**0 条使用**） | **最强（监督）** | 标签自学习 |
| 关闭的提示 | 前端 dismiss（`uiStore`） | 中 | 提示自动收敛 |
| 导出参数 / 筛选组合 | export / search | 中 | 默认值 + 常用筛选 |

### 3.2 **明确不采集**（写出来是为了防止"什么都记"）

- ❌ **停留时长、鼠标轨迹**——弱信号、极易误读，收益不抵隐私成本
- ❌ **题干原文进日志**——只记 `question_id` 与统计量
- ❌ **任何离开本机的数据**——默认**零外传**（§4 的诊断包需显式确认）

### 3.3 怎么学（**不用 ML**）

| 机制 | 做法 | 可解释性 |
|---|---|---|
| 共现统计 | 同卷出现的题对 → 计数 | 「它们一起出现过 3 次」 |
| 加权打分 | 各信号归一化后加权（权重可在设置页看到） | 每条推荐给理由标签 |
| 筛选组合记忆 | 记录"筛选条件 → 使用次数" | 「你用过 5 次这个组合」 |
| **标签词表自学习** | 老师**确认**的标签 → 抽该题特征词 → 扩充关键词表 | 「因为出现过『浮力』『排开』，所以标了『浮力』」 |

> **标签词表自学习是唯一"真正在成长"的一条**：它不是统计历史，而是**把老师的判断变成规则**，
> 让**后续自动标注更准**——而且完全可解释、可撤销。

## 4. 第三部分：基于使用数据的自动优化机制

这里必须区分**两件完全不同的事**（很多方案会混为一谈）：

### (A) 针对**这个老师**的优化 → 本地自动

见 §2/§3。全部在 `learning.db` 本地完成，**不联网**。

### (B) 针对**产品本身**的优化 → **必须诚实：本地单机应用没有云端遥测**

所以产品级改进只能走**人肉闭环**：

```
诊断包导出（老师主动、显式确认）
   → 回传开发者 → 改规则 → 版本更新 → 老师升级
```

**诊断包必须**：
- 列出**将导出哪些字段**（不是"导出日志"一句了事）
- 提供「**不含题干原文**」选项（只导统计 + 字段级差异类型）
- **绝不自动上传**——没有后台上传通道

> ⚠️ 任何声称"应用会自动从所有老师的使用中学习"的说法，在**单机离线应用**上都是**假的**。
> 本设计不写这种话。

### 本地自动优化（**真·自我迭代，不需要人**）

| # | 机制 | 触发条件 | 输出 |
|---|---|---|---|
| 1 | **抽取质量自诊断** | 同一来源文件的题**反复编辑同一字段**（尤其公式/答案） | 标记该来源为「**需重新解析**」+ 证据（改了 N 次、哪些题） |
| 2 | **标签阈值自调整** | 同一个词被**否决 ≥3 次** | 该词降权（保守，且可见可撤销） |
| 3 | **提示自动收敛** | 同一提示被**关闭 ≥3 次** | 默认不再显示（"安静的状态"的自动化） |
| 4 | **检索排序微调** | 点击/加入加权 | BM25 + 个性化权重层，**可一键回退纯 BM25** |

**预期效果**：抽取缺陷从「**老师发现后反馈**」变成「**系统先发现并提示**」；提示噪音随时间下降。

## 5. 第四部分：支撑自我迭代的反馈闭环

```
① 采集（本地 · 最小 · 可关 · 可查看）
        ↓
② 推断（可解释的计数/共现/加权 —— 不用黑箱）
        ↓
③ 应用（推荐 / 排序 / 默认值 / 阈值 / 提示收敛）
        ↓
④ 验证与回收（老师看到"你学到了什么" → 纠正 → 清除；并度量采纳率）
```

### 闭环能转起来的**四个必要条件**

| 条件 | 具体做法 | 不做的后果 |
|---|---|---|
| **看得见** | 设置页新增「**你学到了什么**」：每条偏好 + 证据 + 一键删除 | 黑箱 → 老师不信任 → 关掉全部 |
| **能纠正** | 每条推荐带「不感兴趣」；每类信号独立开关 | 推荐错了没法说 |
| **反脆弱** | 学习数据为空/损坏 → 智能层**自动降级为 L0 规则** | 学习层一坏，主流程就废 |
| **冷启动诚实** | 数据不足时界面明说「**还在学（已 2/3 份卷）**」 | 用 2 份卷假装懂老师 |

### 🔴 让闭环**真正能转起来**的第一块地基：**复核必须变得可行**

现状：`question_labels` 全命名空间 **38,588 项**（知识点 **32,936**）**全是「待复核」**，按 50 条/页约 **772 页**。
**UI 设计评审**（`deliverables/UI设计评审与优化方案-2026-10-13.md` §3 上轮对账 #17）已指出「32,936 项逐条人工不可行」。**这就是为什么「从反馈学习」至今是空的。**

**做法（主动学习思路，三步）**：
1. **不确定性优先**：只挑**系统最没把握**的（如"词典命中但章节标题没命中"、命中词很少的）
2. **批量确认**：按**词**确认（"『浮力』这个词在这批题里都对"），而不是逐题
3. **抽样**：给"抽 50 条快速过一遍"的入口，**明确告知这是抽样**

**预期效果**：复核从「**不可能完成**」变成「**200 项一次坐下能过完**」→ 监督信号开始产生。

### 比"猜你想搜什么"更值得做的一条

研究（`第5章-未言明的隐性需求`）的结论是：**决定长期使用的是「被看见 / 可传承」，不只是省时**。
据此，我认为**智能化的最高价值不在推荐题目**，而在：

| 能力 | 做法 | 为什么比推荐更重要 |
|---|---|---|
| **命题意图记录** | 组卷时可选填一句话「为什么选这道题」→ 沉淀为**个人命题经验库**，同类卷子可复用 | 把老师的**经验**变成资产，而不是猜他的偏好 |
| **署名与贡献可见** | 这套卷用了谁的题、改了多少 | 直接对应研究的"被看见"开关 |
| **修改回流题库** | 老师改过的答案/解析**回流**（经确认）→ 下次不必再改 | 每次使用都让**题库更准**，这是真正的"自我迭代" |

## 6. 分期落地（**按"先让数据产生"排序**，不是按技术难度）

| 期 | 内容 | 依赖 | 为什么这个顺序 |
|---|---|---|---|
| **P0** | ① 埋点（`learning.db`，本地可关）② **复核可行性**（抽样 + 批量确认 + 不确定性优先）③ **L0 智能默认** | 无 | **没有 ①②，后面全是空转**；③ 让第一份卷就有用 |
| **P1** | **结构指纹 + 结构复用**（L1） | ≥1 份卷 | 收益最直观，直接对应"教学风格" |
| **P2** | L2 题目推荐 + 「你学到了什么」页面 | ≥3 份卷 | 有数据才解锁；先给"看得见"再给"推得准" |
| **P3** | 抽取质量自诊断 + 标签词表自学习 | P0 埋点 | 真·自我迭代，但依赖长期数据 |
| **P4** | 诊断包导出（产品级人肉闭环） | P3 | 让**开发者**能改进规则 |

## 7. 技术选型与体积影响

| 项 | 选型 | 理由 |
|---|---|---|
| 存储 | **`outputs/webui/learning.db`**（独立 SQLite） | 遵循 S4：**绝不往交付库 `bank.db` 加表**；且学习数据可整库删除 |
| 算法 | **计数 / 共现 / 加权打分**；排序复用现有 BM25 | n=1 用户时 ML 不可用也**不可解释** |
| 新依赖 | **0**（不引 sklearn / torch） | 便携版 65.5 MB 保持不变（与外壳依赖同理，**不参与打包**） |
| 性能 | 全是本地小表（万级行）+ 缓存 | **不做在线训练**；推荐查询目标 < 50ms |
| 隐私 | 本地；导出需显式确认 + 字段清单 | 单机应用**没有上传通道** |

## 8. 明确不做（反面清单）

- ❌ **深度学习 / 协同过滤**——n≈1 用户，协同过滤无意义；黑箱不可解释
- ❌ **云端遥测**——单机离线应用，隐私与合规成本高，且**做不到就别说**
- ❌ **停留时长 / 鼠标轨迹**——弱信号、易误读
- ❌ **自动改题库内容**——**只提议，不代改**（老师必须确认）
- ❌ **把未确认标签当监督信号**——38,588 全是"待复核"，当真就是错的
- ❌ **用 2 份卷的数据做"个性化"**——诚实地说"还在学"

### ⚠️ 最大风险：**推荐变成噪音**

**对策（四道）**：① 可关闭（按信号）② 可解释（带理由）③ 度量**采纳率** ④
**采纳率低于阈值就自动停用该信号**（例如 <30% 连续 20 次推荐 → 自动关闭并告知）。

## 9. 预期效果（诚实版）

| 指标 | 现状（实测） | 目标 | 怎么测 |
|---|---|---|---|
| **复核可行性** | 逐条不可行（知识点 32,936 / 全命名空间 38,588；**实际完成 0**） | 抽样 200 项**一次能过完** | 完成率 |
| 组卷耗时 | **未测**（工具侧 9.17s，**手工基线未测**） | **先测基线**再谈提升 | 计时（研究第1章的硬指标） |
| 结构复用使用率 | 无此功能 | ≥50% 的新卷使用 | 埋点 |
| 推荐采纳率 | 无推荐 | ≥30%（**低于则自动停用**） | 埋点 |
| 抽取缺陷发现 | 靠老师反馈 | **系统先发现** | 自诊断命中数 |
| 提示噪音 | 未知 | 被关 3 次即收敛 | 关闭次数 |

### **不承诺**（这些无法归因，写了就是编造）

- ❌ 提升教学质量 / 提高学生成绩
- ❌ "越用越懂你"这类**无期限、无指标**的话
- ❌ 任何**没有基线就宣称的"节省 X%"**

## 10. 一句话总结

> **智能化的第一步不是加算法，是让数据产生**——
> 而当前最紧的瓶颈是「**38,588 项复核人工不可行**」，它堵死了**唯一的高质量监督信号**。
> 所以顺序是：**先让复核可行 → 再采行为 → 才有推荐**。
>
> 而**真正贴合这个项目的"智能化"**，可能不是猜老师想搜什么，
> 而是**把老师的命题经验变成可复用、可传承的资产**——这与研究里
