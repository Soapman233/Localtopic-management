# 知识库对标调研与借鉴点

**日期**：2026-10-13
**本项目**：私有题库管理系统（约 10 名中学教师 · 初中物理 → DOCX 抽题 → 建库检索 → 组卷 → 导出**公式可编辑**试卷 → 本地/异地 Web）
**说明**：本报告聚焦「**知识库**」这条线；K12 题库/组卷赛道的对标见另一份既有调研（见 §8 说明）。信息来自公开官网/仓库/评测，访问时间 2026-10-13。

---

## 📌 结论速览

| 判断 | 结论 |
|---|---|
| **本项目不是知识库** | 它是「**题库 + 组卷 + 保真导出**」。知识库解决"知识怎么被找到和复用"，本项目解决"**我自己的题怎么变成一张能交出去的卷子**"。硬套知识库范式会跑偏 |
| **2026 知识库的胜负手已换** | 从"存得下、找得到" → **"答得出，且给得出证据链"**。行业共识：**没有引用出处的 AI 答案是负资产** |
| **本项目最大的**未产品化**优势** | 题库自带**出处**（`source_files` + 题目来源 + `snapshot_json`）——这是绝大多数知识库要额外建索引才能有的东西，本项目**天然就有，却没做成"点一下就回到原文"** |
| **最大的能力缺口** | 检索只有 **bigram + FTS5 + bm25，零向量、零重排**（已 grep 确认 `bank/`、`webui/` 无任何 embedding/vector/reranker 代码） |
| **最该警惕的替代威胁** | **国家中小学智慧教育平台「AI 组卷助手」完全免费、全学科、10 秒出卷**。本项目必须回答"老师为什么不用免费的" |
| **最该抄的一条** | **引用溯源 + 数据健康度**（都是"少建新东西、把已有数据用起来"，符合本项目现状） |

## 1. 先说清楚：本项目在知识库坐标系里的位置

```
              「存」 ←──────────────────────────→ 「用」
              文档库            知识库           生产力引擎
              │                 │                │
个人/团队     Wiki.js          Notion/语雀      NotebookLM
              Outline          Obsidian/思源    AI 知识库(Dify…)
              │                 │                │
K12 教育      ────             ────             学科网/菁优网/组卷网
                                                ★ 本项目在这里 ★
```

**关键差异**：本项目的产出物不是"页面/答案"，而是**一份能打印、能在 Word/WPS 里继续编辑的 DOCX 试卷**。所以对标时要区分两类借鉴：

- ✅ **可借鉴**：内容组织、检索、权限、数据治理、维护机制
- ❌ **不适用**：在线答题、协同编辑、AI 问答替代人工、音视频形态

## 3. 逐个列举：好在哪

### A 类 · 通用协作知识库

#### A1. 飞书知识库 —— **权限跟着组织架构走**（最值得学的一条）
- **好在哪**：知识库不是独立产品，而是与 IM / 审批 / 会议深度打通；**权限可以按组织架构自动继承**——新人入职自动获得对应可见范围，转岗自动调整。
- **代价**：数据在厂商云上；不用它的 IM 就吃不到协同红利；私有化版本成本明显更高。
- **对本项目**：本项目鉴权只有 `viewer / editor / admin` 三级（`webui/auth.py`），**没有"按教研组/班级隔离"**。而本项目的 `source_files` 天然就是授权单元——见 §5-P1。

#### A2. 语雀 —— **编辑体验与结构化最好，但权限粒度偏弱**
- **好在哪**：文档编辑体验在国内口碑最好，Markdown 友好、结构清晰，价格亲民。
- **弱点（原文）**：数据在公有云；**权限粒度偏"空间/文档"级**，很难做到同一篇文档对不同岗位差异化可见。
- **对本项目**：说明**"编辑体验好"与"权限控得住"是两件事**。本项目属"小团队 + 自有数据"，优先补权限而非编辑体验。

#### A3. Confluence —— **插件生态与权限模型成熟，但贵且重**
- **好在哪**：权限模型细致、插件生态成熟、IT 团队最熟。
- **弱点（原文）**：云版数据在海外、国内访问慢；自建版需专门运维；**中文搜索与中文 AI 能力一般**。
- **对本项目**：**中文检索**恰好是本项目已经做对的地方（bigram + FTS5 + bm25，而非 trigram）。Confluence 的中文短板反证了这条路线的价值。

#### A4. Notion / Outline / BookStack / Wiki.js —— **渐进披露与内容组织**
- **好在哪**：Notion 的**渐进披露**（页面里嵌数据库、展开才加载）与 **Outline/Wiki.js 的极简层级**是"信息架构不压迫用户"的范式。
- **对本项目**：本项目 10-12 已做过一轮"导航 10 项 → 4 项"的降权改造，方向一致。可继续借鉴**"一屏一个主角"**。

### B 类 · 个人知识管理（PKM）

#### B1. 思源笔记（SiYuan）—— **块 ID 全局唯一且持久**
- **好在哪**：**块是引用最小单元**；思源的**块 ID 全局唯一且持久，即使移动块位置也不失效**（Obsidian 的块 ID 依赖手动维护或插件生成）。
- **对本项目**：这是**最容易被忽略但最相关**的一条。本项目用 `snapshot_json` 解决"改了源题，已出卷不漂移"——**语义完全一致**。思源的经验说明：**引用要指向"持久身份"，而不是"位置"**。可用于校验本项目的快照/版本机制是否有"位置漂移"隐患。

#### B2. Obsidian —— **本地优先 + 双向链接**
- **好在哪**：纯本地 Markdown 文件、零锁定；反向链接让"提到过"自动变成"关联到"。
- **对本项目**：本项目**已经是本地优先**（SQLite 单文件 + 本机服务），这是**优势而非待补项**。可借鉴的是**反向链接视图**：知识点是「提及」口径（平均 4.26 标签/题），天然适合做"同知识点关联题"的反查。

#### B3. Logseq / Trilium / AFFiNE / AppFlowy
- **好在哪**：Logseq 的大纲式双链、Trilium 的树形本地库、AFFiNE/AppFlowy 的开源 Notion 替代。
- **对本项目**：无直接可借鉴点，**不建议投入**。

### C 类 · AI 知识库 / RAG（**最值得深挖的一类**）

#### C1. Google NotebookLM —— **"有边界的资料库" + 内联引用回查**
- **好在哪**（2026 现状）：
  1. **来源边界清晰**——只在你上传的资料范围内回答，不引入外部噪声；
  2. **每条回答带内联引用，可一键回查原文出处**；
  3. 在此之上生成**学习指南、测验、音频概览**。
- **对本项目**：这是**形态最接近本项目需求**的 AI 知识库——"把资料整理成有边界的库 → 可回查引用 → 再生成测验"。本项目的**题库就是天然的"有边界资料库"**，而"生成测验"本来就是本项目的核心动作。**差距只在"引用回查"没做。**

#### C2. Dify / FastGPT / MaxKB / Coze —— **检索质量有实测数字**
- **好在哪**（同一份 500 页技术手册、50 个问题的实测召回率）：

  | 方案 | 召回率 | 关键能力 |
  |---|---|---|
  | FastGPT | **92%** | QA 拆分模式，客服场景命中率高 |
  | Dify | **88%** | **Hybrid Search（关键词 + 向量）+ Reranker**，开箱即用 |
  | MaxKB | **85%** | **原生 PaddleOCR**，扫描件 PDF 直接吃；**开源里唯一原生信创适配** |
  | Coze | 80% | 黑盒，调不动 |
  | 自研 RAG | 上限最高 | 需持续工程投入 |

- **原文点出的根因**：差距主要在「**分块策略**」和「**检索 reranker**」。
- **对本项目**：本项目**零向量、零重排**。这是**唯一一处"别人有的基础能力我没有"**。但——**不要因为别人都有就上**，见 §5-P0-2 的量化前提。

#### C3. 企业 AI 知识库的三条行业共识（原文提炼）
1. **数据不出域是底线不是加分项** → 本项目**已经满足**（本地 SQLite + 本机服务），这是本项目相对所有 SaaS 的结构性优势。
2. **问答必须带证据链**："要的不是 AI 生成的漂亮答案，而是'**哪份文件、哪一页、怎么说的**'"。
3. **权限粒度要到岗到角色**。
- 另有一条**失败归因**：**"90% 失败项目败在没人维护，半年后内容全过期"**。

### D 类 · 教育题库 / 组卷（**直接同赛道**）

#### D1. 国家中小学智慧教育平台「AI 组卷助手」—— **免费 + 全学科 + 10 秒**
- **好在哪**：教育部官方、**完全免费、无使用次数限制**；文本出题（**约 10 秒**生成含题目/出题思路/解析的完整卷）、文档出题（上传教学文档 → 结构化导读 + **知识点思维导图** → 勾选考点一键出题）、试卷分析三大入口；覆盖基础教育 + 高等教育全学科。
- **对本项目**：🔴 **这是最需要正面回答的替代威胁**。它免费、出得快、覆盖广。本项目唯一站得住的答案只能是两条：**① 进的是"我自己的存量资料"而不是公共题库；② 出的是"公式可在 Word/WPS 里继续编辑的 DOCX"，不是平台里的在线卷。** 这两条必须成为产品的第一句话。

#### D2. 学科网 · 组卷网 / 题库管理系统 —— **校本题库是一级卖点**
- **好在哪**：内容分层维度完整（学段 → 学科 → **教材版本** → 章节 → **知识点** → 题型 → 难度 → 年份/地区）；**"校本题库自主导题"被明确列为一等卖点**；提供 OAuth 嵌入 / API / SaaS 三种合作模式。
- **对本项目**：**印证"私有题库"这个定位成立**；内容分层维度可直接照搬（本项目 `grade` 17.6% / `textbook` 17.5% / `chapter` 35.4% 覆盖不足，是**数据问题不是设计问题**）。

#### D3. 菁优网 · 校本题库 —— **共建共享的云端精选题库**
- **好在哪**：**每位老师可把认可的优质试题加入共享库**——这是 10 人教研组最需要的机制；"全解全析"把答案与解析绑定到题。
- **对本项目**：本项目已有 `answers.py`（答案 3,973 / 解析 4,639）和 `labels.py` 的三态复核。**缺的是"把'我认可的题'沉淀成共享库"的产品表达**。

#### D4. 商业 AI 组卷工具（飞象老师 / 星火智慧教育 / 考试星 / 知云题库）—— **流程可借鉴，能力别硬拼**
- **好在哪**：飞象老师做**互动课件 + A/B 卷知识点对等拆分**；星火智慧教育**与学校教务系统打通**做分层卷；考试星**规则引擎驱动**（按知识点/难度/题型自定义规则）。
- **实测效率数据**：AI 出卷 **10 秒**，人工审核微调 **15 分钟**，原本 2.5 小时的出卷压缩到 **25 分钟**；126 位受访教师中 **89% 表示"真香"**。
- **⚠️ 但原文同时点明**：AI 出的题是"**优质毛坯**"，**必须教师审核**——"那是'审核'而非'创作'"。
- **对本项目**：可借鉴**"规则引擎"**（按知识点/难度/题型自动选题）——本项目已有 `paper.py` 的组卷能力，加一层"规则化组卷"是自然延伸。

#### D5. 智学网 / 在线考试系统 —— **本项目刻意不做**
- 走"考完 → 学情分析 → 错题专练"的数据闭环。**本项目不做考试端**，不适用。

## 5. 借鉴点清单

### 🔴 P0 — 建议优先（都是"把已有数据用起来"，不新建能力）

#### P0-1. 引用溯源：把"题从哪来"做成可点击的证据链
- **抄谁**：NotebookLM 的内联引用 + 企业 AI 知识库的"哪份文件、哪一页、怎么说的"。
- **本项目怎么落地**：本项目**已经存了** `source_files`（209 份）、题目的来源文件与章节、`snapshot_json`（含 source）。缺的只是在题目卡片 / 详情页 / 试卷预览里，把来源做成**可点击回查**（跳到该来源文件、该题在原文件中的位置）。
- **为什么是 P0**：这是**竞品要额外建索引才能有、本项目天然就有**的东西。且**零新依赖、零模型成本**。
- **验收**：任取一题，能从详情页点回其来源文件；导出件（可选）带题源脚注。

#### P0-2. 检索升级：**先量化，再决定**要不要上向量
- **抄谁**：Dify 的 Hybrid Search + Reranker（召回 88%）；FastGPT 的分块策略（92%）。
- **⚠️ 前提（必须做）**：本项目现在**没有任何检索质量基线**。在引入向量前，先构造 **50–100 条真实教师查询**，测当前 bm25 的命中率/首位命中率。**如果 bm25 已经够用，就不上**——原文的实测差距（88% vs 92%）主要在"分块策略"和"reranker"，不在"有没有向量"。
- **若确实要上**：优先**分块策略 + 轻量重排**（本地、无外部 API），而非直接引入向量库；向量可选 `sqlite-vec` 或本地 Ollama 嵌入，保持"数据不出域"。
- **验收**：升级前后同一查询集**逐条比对**（项目铁律：性能/检索优化必须验证结果集逐条一致或明确改善）。

#### P0-3. 数据健康度：把散在 4 页的治理信息收成 1 个入口
- **抄谁**：知识库共性（覆盖率/待维护/过期提醒）。
- **本项目怎么落地**：已有 `enrich.coverage()` + `review.summary()` + `labels.review_items()`，但分散在检索页 / 知识点页 / 公式页 / 统计页。收成**一个「数据健康度」圆环 + 下钻**。
- **为什么是 P0**：行业归因说 **90% 失败项目败在没人维护**；本项目 32,936 条待复核、难度 0%、`textbook` 17.5% —— **同一个病，且没有单一入口让教研组看见**。
- **⚠️ 口径红线**：知识点是「**提及**」口径不是「考查」；覆盖率**必须排除「未标注/待补充」取值**。健康度面板不能把这些混为一谈。

### 🟠 P1

#### P1-1. 权限：从"三级角色"升级到"按来源文件/教研组授权"
- **抄谁**：飞书（权限跟组织架构走）；语雀的反面教材（权限只到"空间/文档"级）。
- **本项目怎么落地**：`source_files` 是天然的授权单元——「这份卷子只给初二物理组看」。10 人教研组场景下，"按文件/按组"比"按角色"更贴近真实需求。
- **注意**：本项目**当前鉴权仅访问控制级**（无用户/角色体系时单机全权），升级前先确认是否需要。

#### P1-2. 维护责任到人：给来源文件/知识点指定责任人 + 复核时效
- **抄谁**：知识库的"内容负责人 / 过期提醒"机制。
- **本项目怎么落地**：`source_files` 加责任人与复核时间；待复核队列按"超期"排序。
- **数据支撑**：菁优网有 **1000+ 位老师组成的资源更新团队**每日更新——共享库能活靠的是**有人负责**，不是靠功能。

#### P1-3. 共建共享：把"我认可的题"沉淀成教研组共享库
- **抄谁**：菁优网"云端精选题库"（每位老师可把认可的优质试题加入共享库）。
- **本项目怎么落地**：已有 `labels` 三态复核（待复核/已确认/已否决）和 `review_queue`。把"已确认"的题聚成一个**组内共享精选**视图即可，**零 schema 改动**。

#### P1-4. 导入前置预检：别把乱文档原样搬进去
- **抄谁**：知识库迁移共识——"**迁移前先梳理目录和权限，别把乱文档原样搬进去**"。
- **本项目怎么落地**：DOCX 导入（在 `workbuddy/main-14dd9452` 分支上，**未合入 main**）之前加一步**预检 + 分类建议**（学段/教材/章节/题型），而不是直接入库再补。

### 🟡 P2

#### P2-1. 规则化组卷（借鉴考试星的"规则引擎"）
按"知识点 / 难度 / 题型 / 题量"声明式规则自动选题成卷，而不是纯人工点选。本项目 `paper.py` 已有组卷能力，加一层规则是自然延伸。
**⚠️ 前提**：`difficulty` 覆盖率 **0%** —— 按难度组卷**现在做不到**，必须先有人工标注。

#### P2-2. 反向链接视图（借鉴 Obsidian / 思源）
知识点是「提及」口径，天然适合做"同知识点关联题"的反查视图。**注意口径说明必须随行**（"这是搜索线索，不代表本题考这个知识点"）。

#### P2-3. AI 生成"优质毛坯" + 强制人工审核（**可选**）
实测：AI 出卷 10 秒 + 人工审核 15 分钟 → 2.5 小时压到 25 分钟；89% 教师认可。
**⚠️ 三条红线**：
1. 生成内容**必须标 `needs_review`**，不得冒充已核对（项目已有此机制）；
2. **必须产出 LaTeX/OMML**，否则违反"公式图片不算达标"的硬指标；
3. 既有调研已明确：**"能拍照录题""错题本""举一反三"都不是差异化**（学科网开放平台 API 已明确列出）——**别再当创新点提**。

## 6. 明确**不要抄**的

| 不要抄 | 为什么 |
|---|---|
| 在线答题 / 阅卷 / 学情分析（智学网、考试星） | 本项目刻意不做考试端；做了会稀释"导出可编辑试卷"这条主线 |
| 实时协同编辑（Notion / 飞书） | 10 人教研组不是实时协同场景，投入产出比极低 |
| 音视频概览（NotebookLM Audio Overview） | 与本项目交付形态（可编辑 DOCX）无关 |
| 换成 SaaS / 上公有云 | **本项目价值就在"数据不出域"**，SaaS 化会摧毁定位（企业知识库共识：私有化是底线不是加分项） |
| 换组件库 / 重做设计系统 | 10-12 设计评审已论证：零组件库迁移 |
| 通用"AI 问答助手" | 本项目用户要的是**一张卷子**，不是一个聊天框 |

## 7. 结论：本项目真正要回答的问题

对标下来，本项目的问题**不是"功能比别人少"**，而是三个更根本的问题：

1. **差异化没有说出口**。本项目真正独有的只有两条：**① 进的是教师自己的存量 DOCX；② 出的是公式在 Word/WPS 里能继续编辑的卷子**。而面对**免费、全学科、10 秒出卷的国家平台 AI 组卷助手**，这两条必须成为产品的第一句话——现在没有任何一处这样表达。
2. **有数据、没产品化**。来源、出处、快照、三态复核、覆盖率——**数据层都做完了**，但用户看不到"证据链"。这是投入最小、收益最大的一块。
3. **没人维护就会死**。32,936 条待复核 + 难度全空 + 教材覆盖率 17.5%——**行业归因说 90% 的知识库项目败在这里**。

**建议顺序**：P0-1（引用溯源，零依赖）→ P0-3（健康度入口）→ P0-2（检索先量化）→ P1。
