## 一、移除 Tailwind（挂名依赖）

### 1.1 为什么是「挂名」

我独立复核（不是沿用旧结论）：

```bash
# Tailwind 工具类使用 —— 0 命中
grep -rn 'className="[^"]*\(flex\|grid\|p-[0-9]\|m-[0-9]\|text-\|bg-\|w-\|h-\|rounded\|shadow\)' src/ | grep -v lp-
```

全库 19 种 `className` 全部是 `lp-*`（livePreview 自定义 CSS）与 `katex-inline`。
`tailwind.config.js` 里的 token 与 `theme.ts` 的 `tokens` **重复，且两者都无消费方**。

### 1.2 移除清单

| 文件 | 改动 |
|---|---|
| `package.json` | 移除 `tailwindcss` 依赖 |
| `package-lock.json` | 依赖子树清空（**−675 行**） |
| `tailwind.config.js` | **删除** |
| `postcss.config.js` | 去掉 `tailwindcss` 插件，**保留 `autoprefixer`** |
| `src/index.css` | 删除 3 段 `@tailwind` 指令；**保留** `html/body/#root`、`body` 字体、`.katex-inline`、`.qb-katex-fallback`、`.katex-display` |

> ⚠️ **为什么保留 autoprefixer**：去掉它会改变 CSS 产出（浏览器前缀），
> 让「零视觉变化」这个判断失去基准。保留它 → 产出可比对。

### 1.3 实测收益

| 指标 | 前 | 后 |
|---|---|---|
| CSS 产物 | 35,987 B | **32,834 B（−8.8%）** |
| CSS 中 `--tw-` 出现次数 | 118 | **0** |
| `@tailwind` 指令 | 3 | **0** |

## 二、设计 token 单一来源（`src/theme.ts`）

### 2.1 迁移表

| 原 `tailwind.config.js` | 现 `theme.ts` | 挂载到 MUI |
|---|---|---|
| `colors.primary` | `tokens.primary` | `palette.primary` |
| `colors.difficulty`（易/中/难） | `tokens.difficulty` | **`palette.difficulty`** |
| `colors.badge`（复核/已确认/已否决/缺失） | `tokens.badge` | **`palette.badge`** |
| `spacing` 8/16/24/32 | `tokens.space[1..4]` | 不覆写（MUI 默认即 8px 栅格） |
| `borderRadius.card` 10px | `tokens.radiusScale.md` | `shape.borderRadius`（保持 10） |
| —（新增） | `tokens.radiusScale` / `tokens.fontSize` 5 档 / `tokens.shadow` 3 档 | `theme.designTokens` |

### 2.2 一条刻意的克制

**没有覆写 MUI 的 `typography` 各 variant 字号与 `theme.spacing`。**

原因：覆写会把 `1.25rem` 改成 `20px` 这类等价但**不等值**的字面量，
在 CSS 层产生真实差异 —— 而阶段 2 的目标是**零视觉变化**。
字号/间距档位以 `tokens` 提供，页面按需通过 `useTheme().designTokens` 消费。

`buildTheme()` 的既有行为**逐项保留**（都是修过的坑）：`MuiPaper.backgroundImage: none`、
`MuiButton.disableElevation`、`shape.borderRadius: 10`、历史非法主色安全回退、深色模式配色。

## 三、四态规范

### 3.1 新增组件

| 组件 | 用途 | 要点 |
|---|---|---|
| `LoadingState` | 首屏加载 | 全站统一尺寸；`role="status"` |
| `EmptyState` | 空结果 / 无数据 | 图标 + 标题 + 说明 + **可选主行动按钮**（禁止裸「暂无数据」） |
| `ErrorState` | 查询失败 | 文案走 `describeApiError()`（教师可读）+ **重试**；原始堆栈**仅在 `?debug=1` 下可见** |
| `ProgressStages` | 长任务（导出/预览 3–8 秒） | **阶段列表 + 当前阶段 + 已用时长 + 上限预期** |

> `LoadingState` 是 worker 主动补的第 4 个组件 —— 没有它就无法在代码层保证
> 「同一场景全站一种呈现」。这是个好判断。

### 3.2 统一规范

| 场景 | 用什么 |
|---|---|
| 首屏加载（无数据） | `LoadingState` |
| 后台刷新（有数据） | 保留行内小 spinner（**不闪空**） |
| 查询/集合为空 | `EmptyState`（尽量给行动按钮） |
| 查询失败 | `ErrorState`（可重试） |
| 长任务进行中 | `ProgressStages` |
| **横幅类**（覆盖率 / 降级 / 快照过期 / 内容守卫 / toast） | **保持 `Alert`** |

### 3.3 替换范围（14 个文件）

`StatsPage`、`SourcesPage`、`FormulaReviewPage`、`KnowledgeReviewPage`、`QuestionDetailPage`、
`SettingsPage`、`SearchPage`、`ExportPage`、`PaperBuilderPage`、`ExportDrawer`、`PaperPanel`、
`VersionHistory`、`PreviewViewer`、`LivePreviewPanel`。

### 3.4 刻意未改（如实声明）

| 位置 | 原因 |
|---|---|
| `PaperSwitcher` 的「还没有试卷」 | 在 `Select` 的 `MenuItem` 内，**结构上放不下块级空态** |
| `QuestionEditor` 的「暂无知识点标签」 | 在标签 Chip 行内，块级空态会**破坏横向布局** |
| 导出作业的细粒度阶段 | `useExportGate` 未上报阶段，`ProgressStages` 用中段索引做**粗粒度**提示（已在注释标明） |

### 4.1 视觉回归结果（**本阶段最关键的一步**）

因为 Tailwind 是**零使用**，移除它**理论上应当产生零视觉变化** —— 若出现差异，说明改动引入了副作用。

| 页面 | 平均像素差 | >32 像素占比 | 判定 |
|---|---|---|---|
| builder | 0.00 | 0.00% | 无可见变化 |
| **export** | 3.36 | 1.11% | **有可见差异（已确认为预期改进）** |
| manage-formula-review | 0.00 | 0.00% | 无可见变化 |
| manage-knowledge | 0.63 | 0.46% | **轻微差异（已确认为预期改进）** |
| manage-sources | 0.00 | 0.00% | 无可见变化 |
| manage-stats | 0.00 | 0.00% | 无可见变化 |
| search | 0.06 | 0.04% | 无可见变化 |
| settings | 0.00 | 0.00% | 无可见变化 |

**度量自校验**：同一张图自比恒为 0.0000（确保度量本身没写错）。

**两处差异经「渲染出来看」确认为预期改进**（不是回归）：

- `export`：旧的裸 `Alert`「点击「生成预览」后在此展示 A4 分页预览…」
  → 新的 `EmptyState`（图标 + 「还没有像素预览」+ 说明 + **「生成预览」按钮**）。
- `manage-knowledge`：旧的裸 `Alert`「请从左侧选择一个知识点标签…」
  → 新的 `EmptyState`（图标 + 「请选择一个知识点标签」+ 说明）。

**结论**：**6/8 页零可见变化，2 页为预期的空态改进，无任何非预期回归。**
