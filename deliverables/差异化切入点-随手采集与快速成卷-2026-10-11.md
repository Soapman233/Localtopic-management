# 差异化切入点：随手采集 → 快速成卷

> 2026-10-11 ｜ 配套：`deliverables/差异化与创新策略-2026-10-11.md`、`deliverables/对标产品调研-知识库与教案库-2026-10-11.md`
> 触发：老师反馈"希望随时随地拍照/下载 PDF/Word，把好题便捷存进**属于自己的**知识库；当遇到某个学生正好需要某道题时，能快速定位并做成一份完整练习"。

---

## 0. 需求还原：把老师的话翻译成产品语言

老师原话包含三段，其实是三个不同的诉求，混在一起容易被做歪：

| 老师说的 | 产品语言 | 本质 |
|---|---|---|
| "随时随地拍照、下载 PDF/Word" | **多源采集** | 采集入口要**零门槛** |
| "存入到属于自己的知识库" | **私有沉淀** | 强调"**属于自己**"——归属权是核心诉求 |
| "遇到某个学生正好曾经遇到的题…快速定位…做成完整练习" | **学生驱动的检索 + 快速成卷** | 检索的**触发条件是"学生"**，不是"知识点" |

**合起来是一条链**：`多源采集 → 私有沉淀 → 学生驱动检索 → 一键成卷 → 可编辑交付`

---

## 1. 先泼冷水：这三件事都不是差异化

在找差异化之前，必须先排掉"看起来像创新、其实是标配"的东西——否则会把资源投在错误的地方。

| 候选差异化 | 实际情况 | 结论 |
|---|---|---|
| **"能拍照录题"** | **学科网已有"拍照录入"**：据第三方教程，其外部题目导入支持五种方式，其中第二种即"拍照录入（OCR 识别图片题并校验）"⚠️ 第三方来源，建议以官方核实 | ❌ **不是差异化** |
| **"错题本"** | 市面已有成熟产品：状元错题本、ReviewNotes 等，具备拍照录题、智能归类、同类题推荐、PDF 打印 | ❌ **不是差异化** |
| **"同类题推荐（举一反三）"** | 学科网开放平台 API 明确列出"智能推题、**举一反三**、试题搜索" | ❌ **不是差异化** |

> **结论**：这个切入点能不能成立，**不取决于"能不能拍"，而取决于"拍完进哪里、以什么形态进、之后能不能被找回并重组"**。

---

## 2. 差异化定位：三句话

> **① 进的是「你的库」，不是「平台的库」。**
> **② 进的是「可编辑的题」，不是「一张图片」。**
> **③ 进的时候带上了「教学现场」，所以事后找得回。**

这三句话分别对应**归属权、形态、索引**——恰好是商业产品结构上做不到的三件事：

- **归属**：学科网的校本题库是它平台的一部分，绑定它的账号、它的组卷、它的导出格式；本项目的库是一个**可整库导出、可迁移、可离线**的本地文件（`bank.db`）。
- **形态**：学科网的 Word 导出**压倒性使用 MathType 对象**（其目录 DSMT4 达 11,845 个），拿到卷子的人**必须装 MathType 才能改**；错题本 App 存的是**图片**。本项目落**原生 OMML**，Word/WPS 双击即可改。
- **索引**：错题本 App 的索引是"科目/知识点"；学科网的索引是"章节/知识点/难度"。**没有一家以"哪个学生"作为一等检索维度**（智学网的错题本依赖它自己的考试数据闭环）。

---

## 3. 差异化链条：只有本项目能端到端打通

```
多源采集          结构化            私有库           学生驱动检索        成卷            交付
拍照/PDF/Word → 文本+公式+图 → bank.db(自有) → 按学生找错题 → 变式题补足 → 可编辑 DOCX
                      ↓
                识别失败降级为「图片题」+ 标记待补录（不冒充已识别）
```

### 四类竞品对照（采集入口维度）

| 能力 | 学科网/菁优（商业） | 错题本 App | 扫描/Mathpix 类工具 | Notion/语雀（知识库） | **本项目** |
|---|---|---|---|---|---|
| 拍照采集 | 具备 | 具备 | 具备 | 具备 | **具备** |
| 采集结果形态 | 平台结构化题（公式为 MathType/图片） | **图片为主** | 文本 + LaTeX（**不成题**） | 富文本 | **结构化题 + 原生 OMML** |
| 归属 | 平台库 | 个人（但锁定在 App 内） | 无库 | 个人/团队库 | **私有本地库，可整库导出** |
| 学生维度索引 | 弱（依赖其考试闭环） | 学生/家长自用 | 无 | 无 | **★ 老师手动关联，不依赖考试系统** |
| 一键成卷 | 具备 | 打印错题（**非重组**） | 无 | 无 | **具备** |
| 导出可编辑公式 | 部分（需 MathType） | 图片，不可编辑 | 可复制 LaTeX，但**不落 DOCX** | 无 | **★ 原生 OMML，零授权** |
| 数据自主 | 否 | 否 | 否 | 部分 | **是（私有部署）** |

> **护城河不是任何单点，而是这条链的完整性**：商业产品有前两段（采集 + 平台库），错题本 App 有第一段，扫描工具有第一段的一半。**没有人把"采集 → 私有沉淀 → 学生维度 → 重组 → 可编辑交付"串起来。**

## 4. 关键设计：三个"必须"

### 必须 1 · 采集即埋标签（否则事后永远找不回）

**这是整个切入点的命门。** 老师想"找到某个学生曾经遇到的题"——如果拍照时只存了题目，**"谁做错过"这个信息事后无法补**。

因此采集环节必须（且只需）记录：
- **时间**（自动）
- **来源**（照片/哪份 PDF/哪个文件，自动）
- **场景标签**（可选：`错题@学生A` / `作业@初二3班` / `周测`）

设计原则：**默认自动填好，标签一键跳过**。绝不能因为"要填标签"而增加采集负担。

### 必须 2 · "识别-确认"卡片（让老师当审核员，不当录入员）

采集流程不是"拍完直接入库"，而是：

```
拍照 → 识别 → 【确认卡片】→ 入库
                 ├─ 文本/公式识别结果（可改）
                 ├─ 原图对照（左右并排）
                 └─ 标签（可跳过）
```

- 老师只需**扫一眼 + 点确认**，约 3 秒；不对就改一处。
- 复用项目已有底座：`bank/review.py` 的复核队列、`bank/labels.py` 的 `review_items()` / `preview_decision()`。

### 必须 3 · 允许降级，但必须标记（不冒充）

识别不出来时**不要硬凑**——降级为"**图片题**"，打上 `needs_review` 标记，原图保留。

这符合项目一贯的诚实原则（参考 `difficulty` 字段：源数据没有就**刻意保持 0%**，绝不编造）。降级是允许的，**冒充才是错的**。

## 5. 学生维度：最锋利的差异点

### 为什么这是关键
老师的原话里，"**某个学生**"是检索的**触发条件**。这意味着题库需要多一个维度：不是"题属于哪个知识点"，而是"**哪个学生和这道题有关系**"。

### 市场现状
- **智学网的错题本**：基于**它自己的考试/阅卷数据**，不接入外部题，且必须先有考试闭环。
- **错题本 App**：面向学生/家长，题目是**图片**，不能重组、不能改公式、不能出成卷。
- **学科网**：有"错题管理"，但同样是平台内的闭环。

**没有一家支持"老师自己采集的题 + 自己关联学生 + 自己重组出卷"。**

### 聪明的 MVP：复用现有 `labels` 表，零 schema 改动
把"学生"先做成一类标签（如 `错题@张三`），复用已有的 `labels` / `question_labels` 表：
- 采集时可选打标签
- 出卷时按标签筛选

**代价几乎为零，但立刻打通了"按学生找题"。**

### 长期演进
学生最终应成为**独立实体**（`students` 表 + 掌握度时间线 + 错题状态流转），但那是 P1/P2，不必一次到位。

## 6. 技术选型：拍照 → 结构化

这是本切入点的**主要工程量所在**，必须分清难度层级——**不是所有内容都值得做识别**。

| 内容类型 | 难度 | 建议方案 |
|---|---|---|
| **中文印刷体文本** | 低 | 多模态大模型 / PaddleOCR |
| **印刷体公式** | 中 | 多模态大模型（Qwen-VL 类）优先；开源兜底：`pix2tex`（LaTeX-OCR）、PP-FormulaNet |
| **版面/题目切分** | 中 | PaddleOCR PP-Structure 类版面分析 |
| **图表 / 电路图 / 实验图** | 高 | **不做识别，直接保留原图**（图本来就该是图片） |
| **手写体** | 很高 | **不承诺**，降级为图片题 |

### 推荐架构：混合三档
```
① 云端多模态大模型（质量优先，需联网）
        ↓ 失败/离线
② 本地开源模型（隐私优先，pix2tex / PaddleOCR）
        ↓ 仍失败
③ 降级为图片题 + needs_review 标记（不阻塞采集）
```
**关键**：三档都**必须产出 LaTeX**（不能是公式图片），否则违反项目硬要求（公式图片不算达标）。

## 7. 🔴 硬依赖：不解决这个，这个需求根本做不了

老师要"**随时随地**拍照"——意味着**手机必须能打开这个系统**。

**好消息**：底层其实已经具备，不需要大改——

- `webui/config.py` 的 `DEFAULT_HOST = "127.0.0.1"`（第 54 行）只是**默认值**；
- `webui/edition.py` 支持环境变量覆盖：`QB_HOST` 优先，或 `QB_EDITION=online` 直接取 `0.0.0.0`；
- **已有鉴权机制**：设置 `QB_AUTH_TOKEN` 后 `/api/*` 启用 Bearer 鉴权（⚠️ 仅访问控制级，**无用户/角色体系**）。

**缺口**在于：
1. **移动端体验未验证**——前端有断点适配（`PaperBuilderPage` 在 <1200px 折叠右栏），但**没有移动端优先设计**，手机上打开可能是"能看不能用"；
2. 组卷/检索等重交互页面在窄屏下的可用性未知；
3. 公网暴露需要安全加固（当前鉴权只有单 token）。

| 方案 | 覆盖场景 | 成本 | 建议 |
|---|---|---|---|
| **局域网**（`QB_HOST=0.0.0.0` 或 `QB_EDITION=online` + 手机连同一 WiFi） | "在学校办公室/教室拍" | 极低（改环境变量） | ✅ **先做这个** |
| **公网**（内网穿透 / 云服务器 + `QB_AUTH_TOKEN`） | "在家、出差随时拍" | 中（需安全加固 + 真实鉴权） | 视验证结果再上 |
| **微信小程序 / 公众号** | 覆盖最广 | 高 | 暂不考虑 |

> ⚠️ **这个切入点的优先级判断**：它听起来很吸引人，但**强依赖"手机能访问且好用"**。如果先做拍照识别而没解决移动端可用性，老师打开手机看到排版错乱或按钮点不到，功能再好也是零。
> **正确顺序：先让手机能打开且能用 → 再让手机能拍照 → 再让拍完能用。**

---

## 8. 落地路线

### P0 · 最小闭环（验证"老师真的会用"）
1. **局域网访问**（`QB_HOST=0.0.0.0` + 手机浏览器）——前置条件
2. **手机拍照上传**（`<input type="file" accept="image/*" capture="environment">`，无需原生 App）
3. **识别-确认卡片**（文本 + 公式 + 原图对照 + 标签可跳过）
4. **降级路径**（识别失败 → 图片题 + 标记）

### P1 · 打通"学生 → 成卷"
5. **学生标签**（复用 `labels` 表）+ 采集时一键关联
6. **按学生检索**（"张三的错题"）→ 加入组卷池
7. **错题成卷模板**（错题 + 变式题 = 针对性练习）

### P2 · 规模化
8. **变式题聚类**（见 `差异化与创新策略` 创新 3）
9. **PDF/Word 批量导入**（复用已有 `pipeline/`，PDF 需额外解析）
10. **剪贴板/浏览器插件**采集

## 9. 验收指标（可实测，不靠感觉）

| 指标 | 目标 | 为什么是这个数 |
|---|---|---|
| **单题采集耗时**（拍照 → 入库） | **≤ 30 秒** | 超过这个数，老师会回到"抄在本子上" |
| 文本识别准确率 | ≥ 98% | 低于此值，校对成本 > 录入成本 |
| 公式识别准确率 | ≥ 90% | 允许有校对，但不能每道都改 |
| **学生错题 → 成卷耗时** | **≤ 3 分钟** | 老师面对学生的场景，超过就失去意义 |
| 降级率（图片题占比） | < 15% | 过高说明识别不可用 |

> ⚠️ **必须在真实设备上实测，不能用桌面浏览器模拟**。手机拍照的画质、光照、倾斜度与桌面截图差异巨大。

## 10. 风险与反方论证

| 风险 | 说明 | 应对 |
|---|---|---|
| **🔴 采集门槛 > 收益** | 如果"拍一道题要 30 秒 + 校对"，老师不会用，需求就落空 | **P0 必须实测单题耗时**；不达标就不进入 P1 |
| **识别准确率不达标** | 尤其手写、复杂公式、图表 | 明确**不承诺手写**；图表一律保留原图 |
| **采集量爆炸后检索失效** | 题库从 7945 涨到几万，bm25 排序质量下降 | 采集时强制埋标签（必须 1），用结构化维度兜底 |
| **学生隐私** | 涉及真实姓名、成绩 | 建议用**化名/学号**；私有部署是天然优势，但公网方案必须加密+鉴权 |
| **又一次"未验证假设"** | 与上一轮结论一致：项目验证了技术，**从未验证教师采用意愿** | 这条反馈本身就是**用户主动提出的需求**，比凭空设想可信度高——**但仍需实测** |
| **反方观点** | 老师可能只是"想要"，真用起来还是嫌麻烦 | 正是 P0 要回答的问题：**先做最小闭环测采用率，再投入识别精度** |

---

## 11. 一句话总结

> **这个切入点的差异化不在"能拍照"，而在"拍完之后的四件事"**：
> **进你的库**（归属）、**是可编辑的题**（形态）、**带上了学生和现场**（索引）、**能一键重组成卷**（闭环）。
>
> 学科网有前两段，错题本 App 有第一段，扫描工具有第一段的一半——**没有人把这条链串起来**。
> 但**前提是先让手机能打开系统**，否则一切归零。
