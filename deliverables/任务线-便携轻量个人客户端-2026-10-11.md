## 一、总目标与验收红线

**目标**：把现有系统从"需要 Python/Node/editor_sdk 的开发态"，改造成**绿色免安装、双击即用、~100 MB、公式可编辑**的个人客户端。

**四条验收红线（全过才算立住）**：
1. **打包**：干净 Windows 机上解压即用，**不装 Python/Node/WorkBuddy**；
2. **导出**：**无 `editor_sdk`** 也能导出公式可编辑 DOCX；
3. **生成**：**无 Office** 也能生成（Office 仅用于打开查看）；
4. **便携**：同一份包拷到第二台机器照常工作。

> **红线未全过之前，不投入任何其他功能开发。**

## 四、角色队伍与职责

| 角色 | 代号 | 职责 | 不做什么 |
|---|---|---|---|
| **研究员** | **R** | 只读调查（符号频次统计、现状盘点） | 不写实现 |
| **架构师** | **A** | 方案设计、**G1 契约冻结**、任务拆分 | 不写业务实现 |
| **导出内核开发** | **D1** | LaTeX→OMML、DOCX 生成、版式坑修复 | 不碰导入/打包 |
| **导入闭环开发** | **D2** | pipeline 抽函数、Web API、前端导入页 | 不碰导出内核 |
| **打包便携开发** | **D3** | 依赖瘦身、PyInstaller、空库、便携路径、备份 | 不碰业务逻辑 |
| **测试** | **T** | **独立验证**（G3）：双端可编辑、干净机器、净时间实测 | **不复用 D 的实现思路** |
| **审查** | **V** | 挑毛病、查夸大、核对契约 | 不修改产出 |

### 协作方式（铁律）

1. **交接文档制**：每个角色产出 `outputs/handoff/<角色>-<主题>.md`，含「我做了什么 / 产出物 / **可执行**验收标准 / 我没做 / 遗留风险」。
2. **下一个角色只读交接文档 + 代码**，不依赖上一角色的对话。
3. **三个硬门禁**：
   - **G1 契约冻结**（A 之后）：端点、字段名、错误码一旦冻结，不得擅自改；
   - **G2 证据门槛**（D 之后）：必须给**实测证据**（命令输出、数值、渲染截图），"已实现"不算；
   - **G3 独立性门槛**（T/V）：**不复用开发者思路**，"结构上覆盖"不算通过。
4. **所有跨角色信息流经主控中转**。

### 本次已有的关键教训（必须复用）

| 教训 | 来源 |
|---|---|
| 验证"可编辑性"的动作**必须等价于真实用户动作**（`Characters(i).Text` 而非 `Range.Text`） | 本轮探针 |
| **"结构上覆盖"不算验证通过**（build 绿 ≠ 行为正确） | 项目既有 |
| 数据改动前**必须备份** + `verify_backup(原库, 备份)`（**参数顺序：原库在前**） | 项目铁律 |
| **写入类验证必须用副本**；但**运行期功能会写生产库**，纪律覆盖不到 | 本轮 V 审查 |
| 结论必须标注**证据强度**，不得升格 | 本轮 R→P→V 链 |

## 五、Git 机制（分支 / 提交 / 同步）

### 5.1 分支

| 项 | 值 |
|---|---|
| **当前分支** | `workbuddy/main-14dd9452` |
| 远程 | `origin` = `https://github.com/Soapman233/Localtopic-management.git` |
| 远程现有分支 | 仅 `main` |
| **策略** | **推送当前分支到远程同名分支**（不污染 `main`，符合 worktree 语义） |

**建立同步（一次性）**：
```bash
git push -u origin workbuddy/main-14dd9452
```
之后该分支即拥有 upstream，后续 `git push` 即可。

### 5.2 提交方式

- **按阶段提交**（一个阶段或一个可独立验收的子任务一次提交），**不做巨型提交**。
- **commit message 沿用项目现有规范**（Conventional Commits + 中文正文）：
  ```
  feat(export): LaTeX→OMML 转换器（覆盖符号频次 Top-30）
  test(export): 双端可编辑验证——10 题样例改字符重开
  chore(pack): PyInstaller 打包，实测体积 108 MB
  ```
- **每次提交前必须**：① 跑相关测试；② 确认未污染交付库（`bank.db` sha256 不变）。
- 使用 `/commit` 命令执行（含 git 安全检查与 HEREDOC 格式化）。

### 5.3 同步机制

| 触发时机 | 动作 |
|---|---|
| 每完成一个**可独立验收的子任务** | `commit` → `push` |
| 每个 **Phase 结束** | `commit` → `push` → 向用户汇报（含证据） |
| 阶段交接（角色切换） | 交接文档随代码一并提交 |
| 开始新阶段前 | `git pull --rebase` 保持与远程一致 |

**实时同步保障**：
- 分支建立 upstream 后，`git push` 无需再指定参数；
- 若远程有新提交，先 `git pull --rebase` 再 push；
- **不强制推送**（`--force`），除非用户明确要求。

### 5.4 需要注意的两点

1. **`.gitignore` 现状**：`/outputs/**` 忽略除 `*.md` 外的文件 → `outputs/handoff/*.md` **会被跟踪**（符合预期）；`/*.pdf` 只忽略根目录 PDF，**`deliverables/*.pdf` 会被提交**（约 4 MB，需确认是否接受）。
2. **交付库 `bank.db` 不在本 worktree**（在主仓库），不会被误提交 ✅。
