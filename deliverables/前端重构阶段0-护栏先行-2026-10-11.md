## 一、四项交付

### 1. vitest 组件测试基座（**最高价值**）

| 文件 | 作用 |
|---|---|
| `frontend/vitest.config.ts` | jsdom + globals；`include` **限定** `tests/unit/**` |
| `frontend/tests/unit/setup.ts` | 注册 jest-dom、每例 cleanup、补齐 jsdom 缺失 API |
| `frontend/tests/unit/testUtils.tsx` | `renderWithTheme`（用真实设计令牌包裹） |
| `frontend/tests/unit/*.test.tsx` | 组件行为测试 |

**`npm test` 现在同时跑两套**：`node --test`（26 项旧测试，原样保留）+ `vitest run`（49 项新测试）。

**补齐的 jsdom 缺失 API（实测发现，非猜测）**：`matchMedia`（MUI `useMediaQuery` 强依赖）、
`ResizeObserver`、`IntersectionObserver`、`document.fonts`。缺任一项组件挂载即崩。

> ⚠️ **关键约束**：`include` 必须限定在 `tests/unit/**`。`tests/*.test.cjs` 是 `node:test` 语法，
> 交给 vitest 会直接报错。这一点已在 `vitest.config.ts` 注释中显式说明。

### 2. 页面级错误边界

**修复的问题**（方案 §2.2 P1-2）：全站**没有 ErrorBoundary**，任一页面渲染抛错（例如后端返回了
意外结构、某字段为 undefined）都会让**整个 SPA 白屏**，且用户没有任何恢复入口。

**实现**：`components/ErrorBoundary.tsx`（react-error-boundary v6），双层包裹：

| 层 | 位置 | 兜住什么 |
|---|---|---|
| 顶层 | `main.tsx` 包住整个应用 | 应用外壳（主题构建 / 路由）自身异常 |
| 页面级 | `App.tsx` 包住 `<Outlet/>` | 单个页面的渲染异常 |

**关键设计**：
- `resetKeys={[location.pathname]}` → **切换页面自动重置**，用户能自行脱困（不会卡在错误页）；
- 兜底界面为**中文教师语言**（"这个页面出错了…其它页面不受影响"），
  技术细节**默认折叠**在"给技术人员的信息"里 —— 呼应 P0-1「术语外泄」的修复方向。

### 3. 统一反馈底座（notistack）

**修复的问题**（方案 §2.2 P1-3）：反馈机制有 **4 种并存**（各页自建 `Alert` / `Snackbar` /
`saveMsg` state / 页内提示），位置、时长、样式各异，错误易被滚动位置淹没。

**实现**：

| 文件 | 作用 |
|---|---|
| `lib/feedback.ts` | `useNotify()`（组件内）+ 全局 `notify`（组件外） |
| `components/NotifierBridge.tsx` | 把 notistack 的入队函数桥接到模块级单例 |
| `main.tsx` | `SnackbarProvider` + `MutationCache.onError` 全局兜底 |

**两个真实消费方**（避免"建了底座没人用"）：
1. **检索页**：加入试卷失败 → `notify.errorFrom(err)`（替换原先的页内 `Alert` + `toast` state）；
2. **全局兜底**：`MutationCache.onError` 对**没有本地 `onError` 的 mutation** 自动弹提示
   （有本地处理的则跳过，**避免重复提示**）。

**安全设计**：全局 `notify` 在未绑定通知器时是**安全空操作**（不抛错）——否则组件外调用会直接崩。

### 4. 契约收敛

| 文件 | 作用 |
|---|---|
| `api/errors.ts` | 错误码常量 + `describeApiError` / `errorCodeOf` / `errorDataOf` / `isContentGuardError` / `isNotFoundError` / `isConfirmationRequired` / `isUnauthorized` |
| `api/queryKeys.ts` | `qk` 工厂：全部 queryKey 的唯一来源 + 各域前缀（供失效用） |

**收敛范围（全量，非部分）**：
- **11 个文件的内联 queryKey 全部迁移**到工厂，`grep "queryKey: \["` 在 `src/` 下**残留 0**；
- 4 处错误码硬编码判断（`useExportGate` / `QuestionDetailPage` / `ExportDiagnostics` /
  `PaperBuilderPage`）改为**语义函数**（如 `isContentGuardError(err)`），
  消除「改一处漏一处」。

## 四、踩坑记录（务必复用）

1. **`vitest` 必须用 2.x**。5.x 的 peer 依赖要求 `vite>=6`，本项目是 `vite@5`，直接 ERESOLVE 失败。
2. **`vitest.config.ts` 的 `include` 必须限定**在 `tests/unit/**`，否则会去收集 `tests/*.test.cjs`
   （`node:test` 语法）并报错。
3. **notistack 容器是懒渲染的**：没有提示时 `.notistack-SnackbarContainer` **不在 DOM 里**。
   我最初的冒烟断言写成"容器是否存在"→ 误判为失败。**要验证反馈，必须真的触发一次提示**。
4. **jsdom 缺 4 个 API**（`matchMedia` / `ResizeObserver` / `IntersectionObserver` / `document.fonts`），
   MUI 组件挂载即崩 —— 必须在 setup 里补桩，且要**实测缺什么补什么**。
