# 前 4 阶段验收报告与 10 人团队适用性评估

- 验收对象：阶段1 预处理管线（`pipeline/`）、阶段2 题库（`bank/`）、阶段3 组卷、阶段4 导出
- 验收方式：三路独立对抗性测试（功能正确性 / 边界与异常 / 非功能），全部结论由实测支撑
- 测试环境：Windows + Python 3.13 + 本地磁盘 + SQLite（`journal_mode=delete`）
- 测试基线：`python -m unittest discover -s tests` → **172 项通过**
- 数据保护：所有写入类验证均在 `bank.db` **副本**上进行，`outputs/bank.db` 全程未被污染

---

## 一、总体结论（先说结果）

| 维度 | 结论 | 一句话依据 |
|---|---|---|
| **功能正确性** | ✅ **可信** | 三路实测：公式转换、检索、快照锁定、导出映射均正确；172 项基线 + 对抗用例通过 |
| **功能完整性** | ⚠️ **部分达标** | 单机 CLI 主链路走通，但**无界面、无用户、无协同、无分享、无法编辑题目** |
| **稳定性** | ✅ **达标** | 幂等、可续跑、完整性 ok、5 个备份均可用；强杀后无损坏、无半成品 |
| **性能** | ⚠️ **部分达标** | 组卷 26–67ms、导入 96s 可接受；但**裸检索 8–18s、导出 82–165s/份** |
| **并发** | ❌ **不达标** | 单机短写可排队，但**共享/网络盘会损坏**，无 WAL 读写不能真并行 |
| **权限管理** | ❌ **不达标** | 代码中**零权限、零审计**；文件权限过宽（Authenticated Users 可改） |

### 结论

> **当前系统未达到「可供 10 人小团队日常使用」的标准。**
>
> 它是一个**单机 CLI 工具**：核心链路稳定、数据正确、组卷快、导出成品可用（公式在 Word/WPS 双端均可编辑）。
> 但**距离"10 人日常使用"还差 5 个阻塞项**（见第七节）——这些不是 bug，而是**架构与形态上的缺失**。

**关键区分**：
- 「**做的东西对不对**」→ ✅ 对。核心功能经对抗性测试确认正确，无数据正确性缺陷。
- 「**能不能给 10 个人用**」→ ❌ 不能。缺界面、缺权限、缺异地访问，且共享数据库有损坏风险。

**正常处理（✅）**

| 用例 | 实际行为 |
|---|---|
| 空目录 / 0 题 JSON | 无报错 |
| 0 字节 / 坏 JSON / list / null | 该文件 ERROR，**批次不中断** |
| 空串 / 纯空白题干 | 正常入库 |

| 标题 1000 字 / emoji / 换行 | 建卷成功 |

| 用例 | 实际行为 | 判定 |
|---|---|---|

| 章节号 `0` / `999` / 负数 / 非数字 | `0`→None、`999.999`→题999、`-1.2`→1.2 | ⚠️ 轻微 |

## 四、异常处理问题：静默吞掉清单（重点）

> **静默吞掉是这类系统最危险的问题**——它不报错，但会让用户拿到错误结果却以为是正常的。

| # | 位置 | 行为 | 风险 |
|---|---|---|---|
| 1 | `importer.import_file` | **全捕获却不 `rollback()`** | 单文件失败留半截行，被后续 commit 落盘 |
| 2 | MTEF 中文 `[U+xxxx]` | 记 `OK` 不进复核 | 数据表示不规范（**导出正确**，见 M1） |
| 3 | `_load_media_hashes` | `except → {}` | DOCX 损坏时图片 sha256 静默丢失 |
| 4 | `_equation_native` | `except → None` | 公式静默降级 `NO_STREAM` |
| 5 | `import_path` 路径不存在 | 0 文件 0 错误 | **静默空跑**，用户以为导入成功 |
| 6 | `search` 的 `limit=-1` / `offset=-1` | 静默改写为全量 / 0 | 参数被悄悄改写 |
| 7 | `build_document_plan` | 有公式无占位符 → 静默不渲染 | 内容丢失且无提示 |
| 8 | `_item_dict` / `_paper_dict` | `snapshot_json`/`meta` 损坏 → 静默置空 | 条目静默丢内容 |
| 9 | `EditorBridge.close()` | 吞 `ExportError` | 可接受 |
| 10 | `convert_many` 的 `per_chunk_timeout`/`chunk_size` | **死参数，从未使用** | `--timeout` 实际无效（恒 4s） |

## 六、非功能评估（实测数据）

### 6.1 稳定性 ✅ 达标

| 项 | 实测 |
|---|---|
| 幂等 | 二次导入 0 新增全跳过；题/式/图计数不变（7945/17771/7102） |
| **中断恢复** | 导入 6s 强杀 → 已提交 3,062 题/82 文件，`integrity=ok`、`fk=0`、无 `-journal` 残留；**续跑补至 7945，无重复无丢失** |
| 导出中断 | 15s 强杀 → **无半成品 docx**，`bank.db` mtime 不变 |
| 完整性 | `integrity_check=ok`、`foreign_key_check=0` |
| 备份 | 5 个 backup 经 `verify_backup(原库,备份)` **全部 ok=True** |
| 大批量 | 阶段1 全量 358 文件 192s 全 OK |

### 6.2 性能 ⚠️ 部分达标

| 操作 | 实测耗时 | 评价 |
|---|---|---|
| 检索 裸「浮力」818 命中 | **~8.4s** | ❌ 慢 |
| 检索 裸「压强」1753 命中 | **~16–18s** | ❌ 慢 |
| 检索 带筛选 818 命中 | ~0.7s | ✅ |
| 检索「重力势能」35 命中 | ~0.31s | ✅ |
| 建卷 / 加 10/50/100 题 | 26–67ms | ✅ 快 |
| 导出学生版（10题24式） | **~82s** | ❌ 慢 |
| 导出解析版（10题65式） | **~165s** | ❌ 慢 |
| 全量导入 209 文件 | ~96s | ✅ 一次性可接受 |
| 阶段1 全量 358 文件 | ~192s | ✅ 一次性可接受 |

**两个瓶颈**：

1. **导出 82–165s/份** —— `EditorBridge` 每次 `call()` 都 `subprocess.run` **新起一个解释器进程**（每段文字/公式/图片各一次），数百次进程启动。**每导一份卷就要等 1.5–3 分钟。**
2. **裸关键词检索 8–18s** —— 查询计划劣化（`SCAN idx_q_source` + `TEMP B-TREE`，约 10ms/命中）。**加任一筛选即降到 <1s**，说明是索引/计划问题而非数据量问题。

### 6.3 并发 ❌ 不达标

- `journal_mode=delete`（**非 WAL**，代码中无 WAL 设置）、`synchronous=FULL`、`busy_timeout=5s`
- **两写并发**（A 持锁 8s，B 晚 1s）：B 等 5.49s 后报 `database is locked`，**数据无损坏**
- 写持 `RESERVED` 时读立即成功（0.00s）；写持 `EXCLUSIVE` 6s 时读阻塞 4.99s
- 真实 CLI：10 进程同写 → 10/10 成功（1.89s）；50 进程 → 50/50（11.92s）
- 写入期产生 `-journal` 回滚文件

> **致命风险**：若把 `bank.db` 放在**共享盘/网络盘**，SQLite 的文件锁**不可靠**，配合回滚日志**会导致数据库损坏**。这对「10 人共用一份库」是不可接受的。

### 6.4 权限管理 ❌ 不达标

- **代码中零权限机制**：精确检索「登录/会话」「权限/角色」「密码/鉴权」「审计」四个维度，**全部 0 处命中**（仅 `created_by` 字段默认「待补充」）
- **文件权限过宽**：`icacls` 实测 `Authenticated Users:(I)(M)`、`Users:(I)(RX)` —— **本机任何登录用户都可修改/删除 `bank.db`**
- **共享单文件风险**：无并发写保护（网络盘易损坏）、人人可写（误删/覆盖/篡改）、**无审计**（谁改了无从查）、无权限分级、恢复仅靠手工备份

## 七、10 人小团队适用性结论

### 明确结论：**未达标**

### 5 个阻塞项（不做就不能给 10 人用）

| # | 阻塞项 | 为什么阻塞 |
|---|---|---|
| **1** | **无 Web / 图形界面** | 10 位老师**不可能都敲命令行**。这是最直接的阻塞 |
| **2** | **无用户 / 权限 / 审计** | 谁都能改、改了没记录、误删不可恢复；无法区分"谁做了什么" |
| **3** | **无异地访问**（阶段5 未开始） | 老师**在家无法使用** |
| **4** | **共享单库在网络盘有损坏风险** | SQLite 文件锁在网络盘不可靠 + 回滚日志 → **可能整库损坏** |
| **5** | **导出 82–165s/份** | 每导一份卷等 1.5–3 分钟，日常使用体验差 |

### 可接受的现状（不必现在改）

| 项 | 说明 |
|---|---|
| 单机 CLI 核心链路 | 稳定、数据正确、组卷快 |
| 导入耗时 | 96s 全量，一次性操作 |
| 阶段1 重跑 | 192s，离线操作 |
| 数据完整性 | 幂等、可续跑、备份可用 |
| 题库规模 | 7,945 题 / SQLite 单文件 64MB，**10 人规模完全够用**，无需换数据库 |

## 八、建议路线（按优先级）

### 第一优先级：修正确性缺陷（工作量小，风险高）

1. **H1 事务原子性**：`import_file` 失败路径加 `rollback()`
2. **M2 `formula_ids` 类型校验**：非 list 直接报错，不逐字符迭代
3. **M3 路径不存在明确报错**：不要静默空跑
4. **P1 CLI 异常处理**：捕获 `ValueError`/`OSError` 给友好提示
5. **P4 分值校验**：确认语义后决定是"加校验"还是"明确文档化为设计如此"
6. **R1 `refresh_snapshots` 限制为按试卷**：避免误刷全库

### 第二优先级：修数据表示（为后续消费方铺路）

7. **M1 规范化 LaTeX 存储**：入库时把 `[U+xxxx]` 还原为真字符（导出已有该逻辑，可复用），使 `formulas.latex` 成为可直接消费的形式
8. **M4 `$` 包装统一**：统一是否带 `$` 定界符

### 第三优先级：解决阻塞项（决定"能不能给 10 人用"）

9. **性能优化**（投入产出比高）：
   - 检索：修查询计划（避免 `SCAN` + `TEMP B-TREE`），预期可降到 <1s
   - 导出：复用桥接进程 / 批量插入，预期可从 82–165s 降到可接受区间
10. **并发与部署形态**：若要多人使用，**不要共享 SQLite 文件**。建议：
    - 短期：**单机 + 每人本地库 + 导出文件共享**（最省事，规避网络盘风险）
    - 中期：**服务端 + 数据库**（阶段5 异地访问一并解决）
11. **用户/权限/审计**：至少做到"能区分谁改了什么 + 误操作可恢复"
12. **Web 界面**：让老师不需要敲命令行

> 阶段1-4 的功能正确性经对抗性测试确认**可信**（公式在 Word/WPS 双端 65/65 可编辑、快照锁定有效、检索防注入、导入可续跑）。
> 但当前形态是**单机 CLI 工具**，距「10 人小团队日常使用」还差：**界面、权限、异地访问、并发形态、导出性能**这 5 个阻塞项。
>
> 建议：**先修 6 个正确性缺陷（工作量小），再优先做性能优化与服务端形态**——后者才是决定"能不能给 10 人用"的关键。
