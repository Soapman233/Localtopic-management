### P-01 · 端到端净时间对照实测
- **需求描述**：我要能一眼看到"用这套工具比手工 Word 组卷到底省了多少分钟"。
- **对应主张**：C01（强实证；属推论，本需求自带验证——见 §七 7.6）
- **验收标准**：
  1. 存在可执行计时脚本，对"导入 N 份 DOCX → 检索选题 → 组卷 → 导出 DOCX"全链路计时，重复 ≥3 次，输出**原始秒数**与中位数。
  2. 同一份试卷（≥10 题）由 **≥2 名教师用 Word 手工组卷**并计时，记录原始秒数。
  3. 产出对照表：`T_tool`、`T_manual`、净节约分钟数；**判定：`T_tool < T_manual` 且净节约 > 0**。
  4. 证据：原始计时日志文件（含每条记录时间戳）+ 汇总表。
- **优先级**：**P0**。理由：强实证 + 报告"第一性设计原则"；它是 C03 门禁的判定基准，也是"是否值得做"的唯一硬指标。**验证方案**：本需求的验收本身即端到端实测，等价于对 C01（属推论）的验证。
- **前置依赖**：无（可用交付样例卷 #1，10 题）。

### P-02 · 素材沉淀标注覆盖率提升
- **需求描述**：我要能按年级/教材/章节找到题，而不是"按年级筛只看到 1,396 题"。
- **对应主张**：C05、C06（合并：均为"素材沉淀"方向的数据缺口）
- **验收标准**：
  1. SQL 覆盖率检查（非空且非"待补充"），基线为 grade 17.6% / textbook 17.5% / chapter 35.4% / qtype 70.0%：
     `SELECT ... FROM questions` 目标 **grade ≥90%、textbook ≥90%、chapter ≥95%、qtype ≥98%**。
  2. 抽样 **30 题**人工核对标注正确率 **≥95%**。
  3. 按年级筛选返回题数从 **1,396 提升至 ≥7,000**（与 C13 漏题问题联动）。
  4. 证据：SQL 输出 + 抽样核对表。
- **优先级**：P1。理由：专业共识 + 差距明确；但补录依赖教研投入而非纯工程，且 C08 已承认源卷结构性缺失。
- **前置依赖**：教研补录数据源；P-10 评审。

### P-03 · 元数据维度扩展与知识点口径修正
- **需求描述**：我要能按"认知层级/内容领域"等维度描述题目，且知识点是"考了什么"而不是"提没提过"。
- **对应主张**：C10
- **验收标准**：
  1. 数据模型存在 `cognitive_level`、`content_domain` 字段；`SELECT count(*) FROM questions WHERE cognitive_level IS NOT NULL` 可执行。
  2. 界面提供标注入口；标注后 SQL 可检索。
  3. **导入不因这些字段缺失而失败（字段可空）**，不新增强制录入（满足 C24）。
  4. 知识点口径从"提及"（`term in text`）升级为"考查"：至少对抽样 50 题，由教研给出"考查"标签并与"提及"结果对照，差异可量化。
  5. 证据：schema 输出 + 界面操作截图 + SQL + 口径对照表。
- **优先级**：P1。理由：专业共识；但"认知层级/内容领域"的标注成本与 C24 存在张力，须先确认字段口径（见冲突 1）。
- **前置依赖**：P-10；字段口径需教研确认。

### P-04 · 难度检索维度可用
- **需求描述**：我要能按"难度"筛题。
- **对应主张**：C14（行业观察；附验证方案=假设 G）
- **验收标准**：
  1. `SELECT count(*) FROM questions WHERE difficulty IS NOT NULL AND difficulty <> ''` **> 0**（基线 0）。
  2. 检索 API 按 `difficulty` 筛选，返回结果集与等价 SQL 的 `id` 列表**逐条一致**。
  3. 界面难度筛选项可用，未标注题显示灰色"未标注"徽章（**不隐藏**）。
  4. 证据：SQL + API 返回 JSON + 界面截图。
- **优先级**：P1。理由：行业观察（须先验证"教师真的会按难度筛题"，见假设 G）。
- **前置依赖**：**P-07（难度回填）**——无回填则此需求不可用。

### P-05 · Web 零培训首次产出（DOCX 导入入口）
- **需求描述**：我要在网页上拖一个 DOCX 就能建库、检索、组卷、导出，不用碰命令行、不用培训、不用登录、断网也能用。
- **对应主张**：C02、C22、C26、C27（合并：同为轴 7"首次产出/便利条件"，且四条均为强实证）
- **验收标准**：
  1. Web 界面存在 **DOCX 导入入口**，全程无需 CLI；导入 1 份 DOCX 后题目即可检索。
  2. 招募 **≥3 名未受训教师**，仅凭界面完成"导入 → 检索 → 组卷 → 导出"，全程无 CLI、无人工协助；**首次产出可用试卷 ≤ 10 分钟**（阈值待 P-01 基线确认后定稿）。

- **优先级**：**P0**。理由：4 条强实证（含红线 C22/C26）+ 最大体验缺口；直接决定"首次使用能否快速产出结果"。
  - **验证方案（V5 规则补丁）**：C02/C22/C26/C27 均属"推论"（第 1 章核心推论、第 4 章 §六"对产品的推论"），按补丁须附验证——本需求的验证即**假设 A（谁建库、频率）**；在假设 A 未定前，P-05 的**规模**不得全额锁定。
- **前置依赖**：**假设 A 验证**（谁建库、频率，决定本需求的规模与形态）；P-10 评审。

### P-06 · 物理规范图示行内位置保真
- **需求描述**：我要导出的试卷里，受力图/电路图/光路图/v-t 图像和原卷一样，位置不跑。
- **对应主张**：C11、C07、C12（合并：同为轴 2 图示保真缺口；C11 为"保真门槛声明"、C07/C12 为"具体元素能力"，二者口径统一后指向同一交付物）
- **验收标准**：
  1. 构造含矢量箭头、单位、量纲、条件标注、受力图、电路图、光路图、v-t 图像的测试卷并导出。
  2. 用 **Word 与 WPS** 打开，逐图与源卷对照：位置（行内/居中）、尺寸一致；**渲染 diff 无失真**。
  3. 公式节点为可编辑公式（OMML/MathType）而非图片：解析 `document.xml` 判定公式节点类型（复用 `export.verify_cross_client`）。
  4. 证据：双端渲染截图 + diff 报告。
- **优先级**：P1。理由：行业观察（须先小成本验证图示失真的真实影响面，见假设 E；研究员观察 1 亦建议对轴 2 单独本地实测）。
- **前置依赖**：无（可本地实测）。

### P-07 · 难度实测回填流程
- **需求描述**：考完试我要能把实测难度填回题目，并且以后能查到当初填的值。
- **对应主张**：C09（专业共识；属推论，验证方案见下）
- **验收标准**：
  1. 提供回填入口（界面或批处理）；回填后 `questions.difficulty` 更新。
  2. 每次回填在 `question_versions` 生成记录（`change_source` 标记，如 `difficulty_backfill`），**历史值 SQL 可查**。
  3. 前后 SQL 对照：`SELECT id,difficulty FROM questions WHERE id IN (...)` 变化可见，旧值可追溯。
  4. 证据：SQL 前后对照 + 版本表记录。
- **优先级**：P1。理由：专业共识 + 与 C08 的结构性现实一致（难度事后才可得）。**验证方案**：验收 1/3 即"回填+留痕可查"的实测。
- **前置依赖**：无（`set_difficulty` 已存在）。

### P-08 · 跨年级继承与结构化复用
- **需求描述**：我要能把八年级的题直接拿来组九年级的卷，原题归属不变。
- **对应主张**：C15（行业观察；附验证方案=假设 F）
- **验收标准**：
  1. 从跨年级/跨册库调用题目组卷成功；引用后原题 `source_id`/贡献者**不变**。
  2. 快照锁定：组卷后修改原题，已组卷内容不变（SQL 核对 `snapshot_json`）。
  3. 证据：SQL + 界面操作步骤。
- **优先级**：P1。理由：行业观察（须先验证跨年级复用需求，见假设 F）。
- **前置依赖**：P-09（归属字段）。

### P-09 · 贡献者署名与组织归属〔本次由 P0 降为 P1〕
- **需求描述**：我要知道每份卷、每道题是谁建的，贡献能被统计和署名。
- **对应主张**：C13、C17（合并：同为轴 6"归属明确"能力缺口）
- **验收标准**：
  1. 试卷与题目均有创建者/贡献者字段（**非"待补充"**）；导入时**自动记录来源贡献者，不要求手工填写**（满足 C24）。
  2. `SELECT created_by, count(*) FROM papers GROUP BY created_by`（及题目级同理）**可统计**。
  3. 界面展示创建者/贡献者。
  4. 证据：SQL group by 输出 + 界面截图。
- **优先级**：**P1**〔原 P0，本次下调〕。理由：**证据强度必须与投入匹配**——C13/C17 经 §七 复核，其真实强度为**行业观察/推论**（出自报告 §3.5"对产品的推论"且报告自我降级），按铁律"行业观察 → 最多 P1 且须先小成本验证"，**不得进 P0**。
  - **验证方案**：新增**假设 I**（组织级归属/贡献统计是否为 10 人组真实刚需）。若假设 I 成立（≥50% 教师认为组织级归属"必要或很重要"），P-09 可回升 P0；否则维持 P1 或退化为"仅来源文件级归属"。
- **前置依赖**：**身份标识方案**（免登录场景下"用户"如何定义，需 A 确认——单机默认账号 vs 来源文件归属）；**假设 I 验证**。

### P-10 · 功能成本-收益评审门禁
- **需求描述**：（内部）每个新功能都要能说清省了多少分钟，说不清的不做。
- **对应主张**：C03
- **验收标准**：
  1. 存在功能立项模板，必填字段：**预计省时分钟数、证据来源（主张编号）、验证方式、优先级理由**。
  2. 抽查最近 3 个候选功能，模板齐全；**无量化省时的功能标记为"待质疑"，未进入 P0/P1 排期**。
  3. 证据：模板文件 + 3 份填写记录。
- **优先级**：P1。理由：强实证；但属流程门禁（元要求），非直接用户功能，且应作为所有需求立项的前置约束先行落地。
- **前置依赖**：无。

### P-11 · 答案/解析覆盖提升〔V 修正新增（V8）〕
- **需求描述**：我要导出的试卷（含答案解析版）里，每道题都有答案和解析，不是"近半题目导出后没答案"。
- **对应主张**：报告 §2 论据一（`:116`"编写试题与参考答案"为命题流程环节、成品卷组成部分）＋ **R2 实测缺口**（answer 3,973/7,945=50.0%、analysis 4,639=58.4%）。
  - **注**：此条为 V 审查点名的遗漏（V8），**非 R1 的 C01–C33**，单独编号登记。
- **验收标准**：
  1. SQL 覆盖率：`answer` 非空率、`analysis` 非空率，基线 **50.0% / 58.4%**，目标分别 **≥90%**。
  2. 抽样 **30 题**人工核对答案/解析正确性 **≥95%**。
  3. 导出"答案解析版"试卷时，缺答案/解析的题目**显式标记欠账**（不静默留空）。
  4. 证据：SQL 输出 + 抽样核对表 + 导出样张。
- **优先级**：P1。理由：答案/解析是"可编辑试卷"交付物的组成部分（报告 §2 命题流程含"编写参考答案"），实测缺口明确且过半。**未升 P0 的理由**：补录答案依赖源 DOCX 是否携带答案与教研投入，属数据缺口（与 P-02 同类）；报告未给覆盖率数字、亦未要求产品自动生成答案。
- **前置依赖**：源 DOCX 答案可用性核查；若源文件普遍无答案，则退化为"显式标记欠账 + 教研补录"。

## 三、冲突与张力及裁决

> 逐条列出主张间的冲突/张力（含研究员已指出的 C24 vs C10），并给出裁决与理由。

### 冲突 1 · C24「零额外录入」 vs C10「元数据标注」 vs C29「命题意图记录」（**核心冲突**）
- **张力**：C24 要求"不得要求额外录入、直接复用自有卷库"（行业观察）；C10 要求高质量元数据/分类标注（专业共识）；而 C08 指出源 DOCX 普遍不带标注。二者如何兼得，报告未给路径。
- **裁决**：**以"系统预填 + 人工只做确认"调和。**
  1. 可自动推断的字段（年级/教材/章节/题型/知识点）由系统预填，人工仅在复核界面**确认/纠正**，不要求从零录入——复用已实现的知识点三态复核（待复核/已确认/已否决）。
  2. 难度走"实测回填"（C09，考后自然产生），非前置录入。
  3. **凡无法自动预填、又必须人工从零录入的字段一律不做**（如命题意图 C29 → 转入假设 C，不投入）。
- **理由**：C24 是行业观察但被报告列为"红线 3"，与 C22/C26 强实证同向；C10 是专业共识。两者不可牺牲其一，唯一可行解是**把录入成本从"人"转移到"系统预填"**。

### 冲突 2 · C20「三级集体审议+迭代闭环」 vs C19「无管理员、不依赖制度」 vs C18「低摩擦」
- **张力**：C20 要求内置三级审议流程与迭代闭环；C19 指出 10 人小组无专职管理员、无 IT、无制度抓手；C18 要求低摩擦。
- **裁决**：**不采纳三级审议。** 以**轻量复核**（单人确认 + 可选第二人抽检）替代。
- **理由**：C20 证据为"校本案例"（弱实证），报告自述正向案例仅 1 例且未经独立复核；而 C19/C18 虽是理论推断，但"10 人无管理员"是项目已确认的客观事实。三级审议与低摩擦红线直接冲突，成本收益不成立。

### 冲突 3 · C17「归属=组织资产」 vs C28「署名=情感需求」（理论推断）
- **张力**：同一"归属明确"概念被报告同时用于组织资产（C17）与情感需求（C28，理论推断）两个层面（研究员观察 3 已指出）。
- **裁决**：**拆分评估，不得用强实证为理论推断背书；亦不得用理论推断冒充强实证。**
  - 组织资产层面（谁建的、贡献可统计）→ 按 C17（**经 §七 复核为行业观察/推论**）进 **P1（P-09）**，**须先验证（假设 I）**，不进 P0。
  - 情感/"被看见"层面（C28/C30/C31/C32）→ 按理论推断进**待验证假设 B，本期不投入开发**。
- **理由**：证据强度不同，落地节奏必须不同；混用会让"理论推断"搭"强实证"的便车，或让"推论"搭"强实证"的便车（原稿即犯了后者，见 §七）。

### 冲突 4 · C01/C03「省时是唯一硬指标」 vs C17/C28「归属/署名难量化省时」
- **张力**：C03 要求"说不清省多少分钟的功能应被质疑"；但归属、溯源、署名这类治理功能几乎算不出省时，按 C03 会被全盘否决。
- **裁决**：**门禁按功能类别区分。**
  - **效率类功能**（素材沉淀、组卷、导出）→ 用 C01 省时指标验收。
  - **组织治理类功能**（归属、溯源）→ 用"资产可管理性/可统计性"指标验收（如 SQL 可 `GROUP BY`、贡献可反查、版本可回溯），**不强行套省时**。
- **理由**：C13（经复核为行业观察/推论）把"归属明确"与"可检索/可复用/可追溯"并列为增量价值四点，说明其价值不以省时衡量；机械套用 C03 会自相矛盾。

### 冲突 5 · C25「避开学情数据分析」 vs C09/C14「难度数据」
- **张力**：C25（强实证）要求核心避开教师最弱环节、不以学情数据分析为主打；而难度标注/难度检索是否属于"学情分析"？
- **裁决**：**C25 约束的是"主卖点"，不是"功能禁令"。** 难度标注是服务于**选题**的素材元数据，不是学情分析主打 → **允许做（P-04/P-07），但不作为核心卖点/首页主打**。
- **理由**：研究员观察 5 已提示此边界；C25 原文限定"而非把学情数据分析作主打"，未禁止相关功能存在。

### 冲突 6 · C13「归属明确是增量价值之一」 vs C24「零额外录入」
- **张力**：归属明确需要记录贡献者，是否构成额外录入？
- **裁决**：**贡献者由系统自动记录**（导入时记录来源文件/操作者），不要求手工填写；单机免登录场景下以"来源文件 + 可选账号"作为归属标识。
- **理由**：与冲突 1 同解——把录入成本转移到系统。

### 冲突 7 · C05「优先版式保真」 vs C01「省时硬指标」
- **张力**：版式保真难直接量化省时，与 C01 冲突。
- **裁决**：**版式保真是质量门槛（C11），不进"省时"核算**；C01 的省时指标仅适用于"素材沉淀 + 组卷"环节。
- **理由**：C11 明确保真是"硬性门槛而非加分项"，门槛用通过/不通过判定，不用省时判定。

## 四、必须先验证的假设

> 证据为"行业观察/理论推断/弱实证"但产品影响大的主张，一律转为待验证假设。**理论推断不得包装成用户需求。**

### 假设 A · 建库动作的归属与频率【最该先验证】
- **假设陈述**：题库的导入/建库动作需要**每个教师各自、频繁地**完成（→ Web 导入必须 P0），还是一次性由**少数人**完成、其余人只读（→ CLI 一次性建库即可）。
- **为何重要**：若每人频繁建库 → P-05（Web 导入）按 P0 全额投入；若一次性 → P-05 降级为"管理员一次性建库 + 教师只读"，可省下大量前端与上传端点工作量。这是**最大一笔 P0 投入的规模判据**。
- **验证方案**：对 10 名教师做**工作流访谈 + 1 周真实操作观察**（谁出卷、多久一次、是否愿意自己导）；指标：每人每月新增/导入 DOCX 次数、愿意自己导入的比例。**判定阈值：若 ≥50% 教师每月至少导入 1 次 → 按 P0 全额；否则降级。**
- **验证成本**：**低**（10 人访谈 + 1 周观察）。研究员观察 4 亦明确建议"在工程排期前先补一次 10 人组内真实工作流访谈"。
- **关联**：P-05 的验证方案（§七 7.6）。

### 假设 B · "被看见/可传承"影响采纳（C28/C30/C31/C32）
- **假设陈述**：署名、贡献统计、经验沉淀等"专业价值确认"显著影响教师采纳与长期贡献率。
- **为何重要**：若成立 → 轴 9 是差异化关键，需新建（P-09 从"组织资产"扩展到"情感层"）；若不成立 → 只做组织归属的资产层面，不做情感层。
- **验证方案**：小规模 A/B：2 组各 5 名教师，一组用含署名/贡献统计版本、一组不含，观察 **4 周**贡献率（主动上传/复用次数）与留存。**判定阈值：含署名组贡献率显著更高（如 +30%）→ 成立。**
- **验证成本**：**中**（需 4 周 + 两个版本）。

### 假设 C · 命题意图/考点映射可顺带记录（C29）
- **假设陈述**：教师愿意在出题时顺带记录命题意图/难度判断/考点映射，且不视为负担。
- **为何重要**：若成立 → C29 可做（须与 C24 调和）；若不成立 → 不做，避免违反零录入红线。
- **验证方案**：10 人问卷 + 3 人原型试用；指标：愿填写比例、平均单题额外耗时。**判定阈值：≥70% 愿填 且 单题额外 ≤15 秒 → 可做。**
- **验证成本**：**低**。

### 假设 D · 归档规范与三级审议有效（C20/C21）
- **假设陈述**：结构化归档规范 + 三级集体审议 + 迭代闭环能提升入库率/复用率。
- **为何重要**：若成立 → 需建流程；若不成立 → 只做轻量复核（当前裁决方向）。
- **验证方案**：10 人组内试点 2 种模式（轻量复核 vs 三级审议）各 2 周；指标：入库率、复用率、教师负担评分。**判定阈值：三级审议的入库率显著更高 且 负担可接受 → 采纳。**
- **验证成本**：**中**。

### 假设 E · 物理图示失真的真实影响面（C07/C12，行业观察）
- **假设陈述**：图片行内位置未还原导致的图示失真，实际影响教师使用（是硬伤而非可容忍）。
- **为何重要**：若成立 → P-06 升 P0；若不成立 → 保持 P1。
- **验证方案**：本地实测：构造 20 道含受力图/电路图/光路图/v-t 图的题，导出后请 **3 名教师**核对"是否可用/是否需手工重排"。**判定阈值：>30% 需手工重排 → 升 P0。**
- **验证成本**：**低**（本地渲染 + 3 人核对）。

### 假设 F · 跨年级复用需求真实（C15，行业观察）
- **假设陈述**：教师有真实的跨年级/跨册复用需求。
- **验证方案**：10 人访谈，统计过去一学期跨年级调题次数。**判定阈值：≥50% 教师每学期 ≥1 次 → 做 P-08。**
- **验证成本**：**低**。

### 假设 G · 难度检索需求真实（C14，行业观察）
- **假设陈述**：教师会按难度筛题（而非只看知识点）。
- **验证方案**：10 人访谈 + 现有检索行为数据（若有）。**判定阈值：≥50% 教师会用难度筛选 → 做 P-04。**
- **验证成本**：**低**。

### 假设 H · 情感需求决定成败（C33，理论推断综合）
- **假设陈述**：工具成败不取决于算法智能，而取决于"降净时间 + 回应情感认同"。

### 7.7 修正 2 · C11 与 C12 判定矛盾的处理（V4）
- **矛盾**：原稿把 C11（"排版保真是硬性质量门槛"，`:24`）判为**已满足**，却把同族的 C12（"支持物理特有排版元素…规范图示"，`:25`）判为**体验缺口 P1**。
- **核对 C11/C12 实际内容**：
  - **C11** 是一个**门槛声明**：明确写"原生可编辑公式**与图示不失真**"是硬性门槛，**同时包含公式与图示两半**。
  - **C12** 是**具体元素能力清单**：矢量箭头/单位/量纲/受力图/电路图/光路图/v-t 图等。
- **核对现状（R2）**：公式可编辑 ✅（Word/WPS 双端改字符验证通过）；**图片行内位置未还原（统一居中附题干后）→ 图示位置失真**。
- **结论**：C11 的门槛中"图示不失真"这一半**未达标**，故 C11 **不能判"已满足"**。C11 与 C12 **不是两件事对立，而是"门槛—实现"关系**：C11 提出门槛，C12 是门槛下的具体元素。
- **修正**：**C11 由"已满足"改为"体验缺口（部分满足：公式✅、图示位置❌）"**，优先级 **P1**，与 C07、C12 **合并进 P-06**（口径统一）。差距分布：已满足 8→7、体验缺口 8→9。
- **区分依据（若 V 追问"C11/C12 是否两件事"）**：即便视作两件事，C11 的门槛声明**显式覆盖图示**，而图示现状失真——**只要 C11 包含图示，其判定就必须与 C12 一致**，不存在"公式满足即整体满足"的空间。
