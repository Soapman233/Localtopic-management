## 一、五类历史版式坑：逐项结论

任务线 Phase 1.4 要求逐项复现并解决 5 类历史坑。**全部处理完毕**：

| # | 历史坑 | 结论 | 证据 |
|---|---|---|---|
| 1 | **`<a:graphicData>` 缺 `uri`** → WPS 容忍但 **Word 报错打不开** | ✅ **设计即避开** | 显式写入 `uri="{...}/picture"`；`TestImageGraphicDataUri::test_graphic_data_has_uri` 守护 |
| 2 | **TAB 控制字符** → 桥接拒绝、曾致整卷导出中断 | ✅ **根因消除** | 自研不走桥接，**直接写 `<w:tab/>`**；哨兵 `U+E000` 方案整体不再需要；测试断言无残留 |
| 3 | **HTML 实体残留**（`\Delta`→`&Delta;`） | ✅ **天然避开** | 转换器直接输出 Unicode（`Δ`）；实测产物非标准实体 **0 个** |
| 4 | **缺显式制表位** → 选项对齐不准 | ✅ **本轮修复** | 补 `<w:tabs>`（版心 1/4、1/2、3/4 左停靠）；实测 7 段 × 3 点 = 21 个停靠点 |
| 5 | **题号双重渲染** | ✅ **Phase 1.3 已修** | 根因：`build_document_plan` 已把题号写入 `stem_lines` 首段；渲染层不再重复添加 |

### 本轮唯一新增修复：显式制表位

**审计发现**：产物中有 9 个 `<w:tab/>` 但 **0 个 `<w:tabs>`** → 依赖 Word 默认停靠点（每 0.5 英寸），四选项题对齐会不准。

**修复**（`bank/docx_writer.py`）：
* 新增 `_avail_twip()`：版心宽 = A4 宽 − 左右页边距 − 装订线
* 新增 `_tab_stops()`：在版心 1/4、1/2、3/4 处各设一个左停靠点
* `_p()` 中检测到 `runs` 含 `<w:tab/>` 时自动附加 `<w:tabs>`

与原桥接实现（`bank/export.py::_set_explicit_tab_stops`）口径一致（同为版心 1/4 分点）。

## 二、关于「图片行内位置」——**用数据决定不做**

R2 在代码能力盘点中指出「图片行内位置未还原（统一居中附题干后）」。本轮做了**量化评估**，结论是**当前不做**，理由有二：

### 理由 1 · 当前需求为 0（实测）

扫描全部试卷的 `content_blocks`：

```
试卷中图片总数: 19
  段落中间（同一段落有前后文本）: 0
  独立/段末（前后无同段文本）  : 19
  → 需要 run 级行内定位的比例: 0.0%
```

**19 张图片全部是独立/段末图**，段落级交错已经完全够用。

### 理由 2 · 数据粒度不支持，代价不成比例

`pipeline/docx_scan.py:181`：
```python
images.setdefault(rels[rid]["target"], paragraph_index)
```

**图片只记录到「段落索引」粒度，没有 run 偏移。** 要做 run 级行内定位，必须：
1. 改 `pipeline/docx_scan.py` 记录 run 偏移；
2. **重跑 209 份 DOCX 的预处理**（而 `outputs/preprocess_final/` 项目明令「**勿重新生成**」）；
3. 重建题库（`bank.db`，需备份 + `verify_backup`）。

**为 0% 的需求付出「改管线 + 重跑 + 重建库」的代价，不成立。**

### 段落级交错**已实现且已验证**

`bank/export_content.py:145-158` 按源文档段落顺序交错构造 blocks（含 `_paragraph` 索引），`docx_writer._render_blocks` 按该顺序渲染。渲染证据：试卷 #1 第 1 页中，**脚印图正好位于题干之后、选项之前**——顺序正确。

> **建议**：此项列为「**按需触发**」——若将来出现真实的段中图需求（可从 `content_blocks` 统计监控），再评估。已在本文件留下判定依据。
