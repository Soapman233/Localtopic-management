## 五、硬性约束（**违反会造成数据损坏或回归**）

### 5.1 数据安全（最高优先级）

1. **`outputs/bank.db` 是交付数据**。导出/预览/检索必须**只读**（用 `db.connect_readonly()`）。
2. **写入类验证必须复制到临时目录用副本**，**绝不污染原库**。
3. **改库前必须备份** → `outputs/bank.backup-<时间戳>.db`，并用 `bank/enrich.py::verify_backup(original, backup)` 验证。**注意参数顺序：原库在前、备份在后**。
4. **迁移必须幂等**（参考 `bank/answers.py::ensure_answer_columns()` 风格）。
5. **不要重新生成 `outputs/preprocess_final/`**。

### 5.2 公式领域约束

1. 公式中的中文必须写成 `\text{额}` 形式，否则乱码。
2. **替换 `[U+xxxx]` 必须在已有 `\text{}` 内部**：`{\text{[U+6c34]}}` → `{\text{水}}`；套成 `\text{\text{水}}` 会让渲染器报错。
3. **判定"公式可编辑"必须实测**：改公式内部字符 → 保存 → 重开 → 比对。**不能用"有 OMML 节点"或"能打印"代替。**
4. **OMML 是唯一不依赖第三方软件、Word/WPS 双端可编辑的格式。**

### 5.3 代码约定

1. **`webui/` 只调用 `bank/` 的函数，不复制业务逻辑。**
2. **冻结文件**（改动需明确授权）：`bank/db.py`、`bank/importer.py`、`bank/paper.py`、`bank/export.py`、`bank/cli.py`；`bank/query.py`、`bank/labels.py` 只允许**新增函数**。
3. **改 `.py` 交付资产后**：同步重嵌文件头注释 + 重建 `outputs/metadata/asset_manifest.json/md`。
4. **前端改动后必须跑** `npx tsc --noEmit`（0 错误）+ `npm run build`（产物写入 `webui/static/`）。
5. **中文注释与中文界面文案。**
6. **统一响应** `{code, data, message}`；不得让异常裸奔成无信息的 500。
7. **`.bat` 文件必须保持 CRLF 换行。**

## 六、工程方法要求（**这些是项目踩过坑总结的，务必遵守**）

| 要求 | 原因 |
|---|---|
| **改排版/导出后必须渲染出来看** | 单元测试测不出视觉缺陷（曾出现"题号连续"通过但导出件有双重题号） |
| **验证"修复类改动"要用反证** | 不是"跑个测试通过"，而是确认修复前确实有问题 |
| **对照实验必须用当前代码新导出的产物** | `outputs/export/` 有多个历史版本，用旧文件当基准会得出错误结论 |
| **性能优化必须同时验证结果集逐条一致** | 改 join/查询计划极易破坏正确性 |
| **指标必须用 SQL 核实真实含义** | 知识点「提及」曾被当成「考查」汇报 |
| **给用户的时间承诺必须与实测相符** | 曾写"3–6 秒"而实测 7.4 秒 |
| **不要用低分辨率截图下关键结论** | 曾把「6．」看成「8．」误判为题号重复 |
| **不确定的行为先写探针验证** | 参考 `spike/` 的做法，不要在生产代码上试错 |
