## 2. 六个必验项（逐条：实测结果 + 结论）

### 必验项 1：能否按 A4 高度分页 —— ✅ 能，且与真实 A4 页数一致

- 实测（`metrics.json`，A4）：考试·学生版 **6 页**、测验·学生版 **6 页**、作业·学生版 **4 页**、考试·答案解析版 **8 页**、学生版 ×5（**50 题**）**23 页**。
- 真实 A4 导出（新）：考试·学生版 **6 页**、测验·学生版 **6 页**、作业·学生版 **4 页**、考试·答案解析版 **9 页**。
- 结论：**可精确按 A4 高度分页**；学生版**页数与真实导出完全相同**。

### 必验项 2：能否做到「题目不跨页」 —— ✅ 能

- 做法：**一道题（题干 + 配图 + 【答案】/【解析】）= 一个原子块**；大题标题 `keepWithNext`（与后一题同页）。与后端 `keep_together` / `keep_with_next` 语义对应。
- 实测：学生版全部配置 `溢出页 = 0`。
- 证据：`06_detail_page1.png`（第 1 页 = 卷头 + 大题标题 + 第 1、2 题；第 3 题整体到第 2 页）。
- 结论：**题目不会被拦腰截断**（唯一例外：单题本身高于一页，见 §4）。

### 必验项 3：图片高度未知怎么办（**重点**） —— ✅ 有确定性解法

- 关键：**图片显示尺寸是纯函数**——后端 `bank/export.py::fit_image_size` 用「原始像素宽高 + 可用宽度」按比例表算出显示宽高。探针把该规则搬到前端（`src/spec.ts`），并在导出数据时记录图片**原始像素宽高**。
- 于是 `<img>` **预写 width/height**：**解码前即占位，加载完成不回流**，分页稳定。
- 兜底：缺尺寸则等 `onload` 后测量，并用 `ResizeObserver` 监听测量层，高度一变即重排。
- 实测：8 张图片全部命中预置尺寸；`08_compare_real_vs_spike.png` 中图片位置/大小与真实 A4 一致。
- 结论：**「图片异步高度」可彻底消解**。

### 必验项 4：KaTeX 公式渲染后的高度 —— ✅ 同步定高

- `katex.renderToString()` **同步**返回 HTML，插入 DOM 同帧定高；唯一异步因素是 **KaTeX 字体**加载（需 `await document.fonts.ready`，否则 FOUT 抖动）。
- 结论：**公式高度可同步确定，只需等字体就绪**。

### 必验项 5：性能 —— ✅ 远优于预算

| 配置 | 题数 | 首次测量（含一次回流） | 基准（30 次平均，每次含回流） |
|---|---|---|---|
| 考试·学生版 A4 | 10 | 0.1–0.2 ms | 0.020 ms |
| 考试·答案解析版 A4 | 10 | 0.1 ms | 0.020 ms |
| 学生版 A4 ×5 | **50** | 0.3 ms | 0.053 ms |

- 复杂度 O(N) 块 × 1 次 `getBoundingClientRect`（唯一强制回流）+ O(N) 装箱。
- 结论：**单次重算 < 0.06 ms（50 题）**，**防抖 200–300 ms 有 3 个数量级余量**。

### 必验项 6：不同模板 / 设置的影响 —— ✅ 自动重算，且与真实一致

- 模板：考试/测验/作业的页边距、字号、是否标分、是否大题分页均不同 → 切换即重算；**三模板学生版页数与断页点均与真实 A4 一致**。
- 答案模式：同卷 A4 下 学生版 6 页 → 答案解析版 8 页（真实 9，差因见 §4/§6）。
- 结论：**模板/答案模式变化 → 分页自动重算**。

## 3. 各路线对比（A / B / C）

| 维度 | 路线 A：CSS 分栏分页 | **路线 B：JS 测量 + 手动分页（推荐）** | 路线 C：B + ResizeObserver |
|---|---|---|---|
| 原理 | `column-width` + `break-inside:avoid` | 隐藏层逐块测量 → 手动装箱 | 同 B + 监听回流 |
| 实测页数（学生版 A4） | 6（**需手动加 `break-before:column`/`break-after:avoid` 才对齐**） | **6** | 6 |
| 被拆分的块 | 无（本次数据） | 无 | 无 |
| 页数如何得知 | **仍要 JS**（量 `scrollWidth` 反推栏数） | 直接来自算法 | 同 B |
| 逐页卷头/页脚 | **做不到**（无「每栏」DOM 钩子） | 可以（每页独立 DOM） | 可以 |
| 单块高于一页 | 无法避免拆分 | 可标记「溢出页」并给策略 | 同 B |
| 依赖 | 无 | 无 | 无 |
| 结论 | 可跑通，但没省掉 JS、缺逐页能力 | **推荐** | 并入 B |

- 证据：`07_routeA_css.png`。
- **推荐路线 B**：控制精确、可渲染逐页卷头/页脚、页数确定。

## 4. 最大的坑（务必知道）

1. **Word「多倍行距」≠ CSS `line-height`（本项目最关键的一处，v1 曾因此差 1 页）**
   - Word「1.5 倍行距」= 1.5 × **字体自然行高**（宋体 12pt ≈ 15.5pt）≈ **23.2pt**；CSS `line-height:1.5` = 1.5 × **字号** = **18pt**（低 **29%**）。
   - 实测真实 A4 PDF 正文相邻行距众数 = **≈23.2pt**，与 1.5×15.47pt 吻合。
   - **修正**：引入系数 `WORD_SINGLE_LINE_FACTOR = 1.29`（`src/spec.ts`），`lineHeight = 字号 × 行距 × 1.29`。修正后**学生版页数与断页点与真实完全一致**。**这是本次探针最重要的落地结论。**
2. **`transform: scale()` 污染测量**：`getBoundingClientRect()` 返回**视觉变换后**尺寸，测量层必须放在任何 `transform` 容器**之外**（探针踩到过：同配置页数 5→3）。
3. **图片不预置尺寸 → 加载后回流必乱**（解法见必验项 3）。
4. **单题高于一页**：真实 Word 会拆分该题，前端若坚持「整题不拆」就会溢出、页数少 1（见 §6）。需明确策略：溢出 + 提示，或对超页题降级允许拆分。
5. **卷头 `keepWithNext` 链**：卷头（标题→信息行→大题标题→首题）会被连成一组，首题很长时第 1 页可能整组溢出。

## 7. 风险与建议（含页数显示）

**最大风险**：当存在**单题高于一页**（多见于答案解析版的长解析题）时，真实导出会拆分该题、探针不拆 → 页数差 1。这是「不截断」与「页数精确」的天然冲突点。

**建议（推荐落地）**：
1. **落地路线 B**，并**如实修正行距系数 1.29**——这是页数能否对上的关键。
2. **页数显示：可以显示**，建议用「**约 N 页**」并加一句 tooltip：
   - 依据：**学生版三模板页数与断页点已与真实 100% 一致**；
   - 但**答案解析版**在「单题超页」时会差 1 页，故用「约」更稳妥；若能检测到「存在超页题」，则**降级为「约 N 页（含长题，最终以导出为准）」**。
   - 即：**从 v1 的「不显示页数」调整为「显示约 N 页」**（结论因基准修正而放宽）。
3. 对**超页题**给明确策略：默认「整题溢出到下一页并提示」（保"不截断"），或在用户勾选时允许拆分该题（与真实导出对齐）。
4. 页脚文案与真实导出对齐（`第 N 页 共 M 页`）。
5. 优先做**只读结构预览**，再逐步开放预览内编辑（对应设计 §10-3）。
6. 若**不落地**：替代方案是「结构预览只做单栏流式（不分页）」——会丢掉「所见即所得」的一半价值，不推荐。
