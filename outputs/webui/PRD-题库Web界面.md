## 1. 产品定义

### 1.1 产品目标（一句话）

> **让一位初中物理老师不敲命令行，在浏览器里用十几秒完成「找题 → 组卷 → 导出」，并能在界面上顺手修错题、补元数据、清公式欠账。**

三个正交目标：

1. **可用**：把现有 CLI 主链路（检索/详情/组卷/导出）1:1 搬到图形界面，非技术用户零学习成本。
2. **可治理**：把题库已知的数据欠账（元数据缺失、难度全空、知识点口径、196 条待复核公式、答案 50%）**显式暴露 + 可操作**，而不是让老师误判题库质量。
3. **可修正**：支持在线编辑「文字 + 元数据 + 公式」，且每次编辑**底层自动留旧版**（不做回滚界面）。

### 1.2 目标用户与场景（初中物理老师的一天）

| # | 场景 | 用户故事 |
|---|---|---|
| 1 | **课前组一份随堂练习** | 早上 7:50，李老师想用「浮力」章节出 8 道题当堂测。她在检索页搜「浮力」，左侧筛选栏勾选章节，结果卡片上直接点「加入试卷」，右栏实时看到试卷全貌和总分，5 分钟后导出学生版 DOCX 打印。 |
| 2 | **出带解析的作业** | 下午，她要在作业里附答案与解析。组卷时发现右栏提示「本卷 10 题中 4 题无答案」，于是她挑了几道**带答案**的题替换，导出预览里确认解析版每题后都附了【答案】【解析】，再导出。 |
| 3 | **发现错别字就地修** | 晚上，她在详情页看到一道题题干有错别字——**以前只能重导 DOCX**。现在她直接点「编辑」，改完保存，题干即时更新，检索也能搜到新文本；旧版自动留底，她能展开看但**不提供回滚按钮**。 |
| 4 | **清知识点复核欠账** | 教研组要求确认知识点。她进入「知识点复核」页，按标签汇总看到「压强 2,378 条待复核」，逐条看题干片段点「确认/否决」，或导出 CSV 离线批量填。 |
| 5 | **补元数据 / 清公式** | 她想按年级筛题，却发现只有约 1,342 题有年级。界面明确提示「年级仅 17% 有值」，她改从「待补充」桶里筛出缺元数据的题，逐题补上；顺手把「待复核公式队列」里的 196 条过一遍。 |

## 3. 关键交互

### 3.1 双栏组卷怎么用（P3）

```
┌───────────────────────────────────────────────────────────────┐
│  组卷页   试卷：[初二物理周末练习 ▾] [+ 新建]     总分 42  题数 12  │
├──────────────────────────────┬────────────────────────────────┤
│  左栏：题库（含筛选）           │  右栏：试卷                     │
│ ┌──────────────────────────┐ │ ┌────────────────────────────┐ │
│ │ 🔍 搜题…        [严格模式] │ │ │ 一、选择题                  │ │
│ ├──────────────────────────┤ │ │  1. 关于浮力…   [3分] ⋮↕✕  │ │
│ │ 章节 ▾  题型 ▾  答案 ▾   │ │ │  2. 下列说法…   [3分] ⋮↕✕  │ │
│ ├──────────────────────────┤ │ │ 二、计算题                  │ │
│ │ ┌──────────────────────┐ │ │ │  3. 一个物体…   [6分] ⋮↕✕  │ │
│ │ │ 题 3753 浮力…  [有答案]│ │ │ │  ⚠ 本题无答案               │ │
│ │ │ [加入]  [详情]        │ │ │ └────────────────────────────┘ │
│ │ └──────────────────────┘ │ │  未设分 0 题 ｜ 无答案 2 题      │
│ │ ┌──────────────────────┐ │ │  [ 导出 → ]                     │
│ │ │ 题 3754 密度…  [无答案]│ │ └────────────────────────────┘ │
│ │ └──────────────────────┘ │                                │
│ └──────────────────────────┘                                │
└──────────────────────────────┴────────────────────────────────┘
```

- **加入方式**：① 结果卡点「加入」（P0，落到右栏末尾或当前选中大题）；② 拖拽卡片到右栏指定位置（P1）。
- **右栏操作**：上/下移与拖拽排序（对应 `move`，题序 1..n 连续自动重排）；设分值（0–1000，允许 0.5 等小数，未设=不计入总分）；移除；大题分组（`一、选择题` 等）。
- **实时汇总**：题数、总分（未设分题单独计数、**不当作 0**）、**无答案/无解析题数预警**。
- **快照锁定语义的 UI 表达**：右栏题一旦加入即锁定版本；若之后在详情页编辑了该题，右栏需提示「该题在题库中已更新，本卷仍用加入时的版本」并提供「刷新该题到最新版」按钮（对应 `refresh_snapshots` 按卷刷新）。**不做静默变更**。

### 3.2 在线编辑入口与保存方式（含「底层留版」如何体现）

**编辑入口**：单题详情页右上角「编辑」→ 进入编辑态（同一页面切换，不跳走）。可编辑三类：

| 类别 | 字段 | 说明 |
|---|---|---|
| 文字 | 题干 `text`、答案 `answer`、解析 `analysis` | 题干中的 `⟦Fn⟧` 占位符保留不动 |
| 元数据 | 题型 `qtype`、章节 `chapter`、难度 `difficulty`、知识点标签 | ⚠️ **年级/教材是「文件级」字段**（见下） |
| 公式 | 每条公式的 LaTeX | 见 3.4 |

> ⚠️ **关键产品约束（必须告知用户）**：`grade` / `textbook` 存在 `source_files`（**文件级**），改一道题的年级 = 改**该来源文件下全部 N 道题**的年级。UI 上这两个字段编辑时必须二次确认，文案示例：「年级/教材属于**来源文件**级字段，修改将影响该文件下全部 **128** 道题」。若用户只想过改单题，需要新增「题目级覆盖」列（列入待确认 Q3）。

**保存方式**：显式「保存」按钮（不自动保存），保存时后端执行：

1. 若题干有改动 → 重算 `plain_text`、`content_hash`、`char_length`，并**同步更新 FTS 索引**（`question_fts`）。
2. **留旧版**：保存前把**当前版本**的题干（`text` / `plain_text` / `char_length`）写入 `question_versions`（`version + 1`），再更新 `questions`。
3. 公式改动 → 更新 `formulas.latex`，并重置该公式的 `needs_review` / `review_queue` 状态。

**「底层留版」在 UI 上如何体现**：

- 详情页「版本历史」区域列出 `v1 / v2 / …`，每条显示**时间 + 字数 + 内容摘要**。
- 点开可**只读**查看某一版题干（及可展开的 diff 对比，P2）。
- **不提供「恢复到此版本」按钮**（用户已确认不做回滚界面）。
- 文案明确：「系统会自动保留每次编辑前的旧版，仅供查看，不提供一键回滚。」

> ⚠️ **现有表结构缺口（重要）**：`question_versions` 目前**只存题干文本**（`text/plain_text/char_length`），**不含公式、答案、解析**。用户要求「编辑公式也留旧版」，这与现有表结构**冲突**——需扩展该表或新增版本表（列入待确认 Q1）。

### 3.3 导出预览展示什么（P4）

先预览、后导出。预览区模拟 A4 分页，展示：

- **卷头**：按模板渲染（考试模板含 班级/姓名/学号/成绩；测验含 班级/姓名；作业含 姓名/班级）。
- **大题标题 + 分值说明**（各题同分写「每题 X 分，共 Y 分」，否则只写「共 Y 分」）。
- **题号**：按全卷**连续重新编号**后的样子（原卷题号已剥离）。
- **题干 + KaTeX 公式 + 图片**（图片居中附于题干后——与导出行为一致）。
- **答案区**：学生版不含；仅答案版附【答案】；答案解析版附【答案】【解析】。
- **无答案题显式标注**：如「⚠ 本题库中无答案/解析，解析版将只显示题干」。
- **页脚汇总**：总题数、总分、页数。

> 预览定位：**近似排版**，用于确认内容与结构；最终以导出的 DOCX/PDF 为准（保真度要求列入待确认 Q7）。

### 3.4 公式：既要渲染又要能编辑 —— 交互方案

**渲染（展示态）**：
- 题干中的 `⟦Fn⟧` 占位符 → 后端给出 `latex_list`（按 `fid` 精确映射，非出现顺序），前端用 **KaTeX** 就地渲染成真公式。
- 图片沿用 `media_path`，从源 DOCX 包内取出。

**编辑（编辑态）—— 推荐方案 A「源码 + 实时预览」**：
1. 点击某条公式 → 弹出**公式编辑浮层**。
2. 浮层左侧 = **LaTeX 源码输入框**（预填当前 `formulas.latex`）；右侧 = **KaTeX 实时预览**（输入即渲染）。
3. 「确定」→ 写回 `formulas.latex`，题干结构（占位符与 fid）**不变**——只改公式内容。
4. 若渲染失败（KaTeX 报错）→ 阻止保存并高亮错误位置；**不静默写入**。
5. 保存后该公式 `needs_review` 复位，并提示「已加入待复核队列」以便二次确认。

**为什么不做所见即所得公式编辑器**：WYSIWYG 公式编辑器（MathLive 类）集成与调试成本极高，且老师改公式多为「改一个符号/数字」，源码 + 实时预览已足够（可视化编辑器列为 P2-1）。

| 文字 | 主 `#1F2329` / 次 `#646A73` / 弱 `#8A8F99` | 三级层次 |
| 圆角 | 卡片 `12px`、按钮 `8px`、标签/徽章 `999px` | 圆润、亲和 |
| 间距 | 8px 栅格：卡片内 `16–20px`，卡片间 `12–16px`，区块间 `24px` | 呼吸感 |
| 字体 | 系统字体栈；题干正文 `15px/1.7` | 长文可读 |

**组件用法**

- **筛选栏**：左侧固定，宽约 `240px`；每个筛选项为可折叠分组，选项后带**计数**，多选为圆角 chip。
- **结果卡**：白卡，顶部一行元信息（题号/题型/章节，灰色小字），中部题干预览（2–3 行截断），底部一行**状态徽章**（有答案/无答案、难度、待复核）+「加入」「详情」按钮。
- **徽章**：`有答案` 绿底浅色、`无答案` 灰底、`待复核` 橙底、`未标注`（难度）灰描边。
- **右栏试卷**：卡片内按大题分区，每题一行，行内 `⋮` 菜单（上移/下移/移除/设分）。
- **空状态**：友好插画 + 引导文案（如「还没有试卷，点右上角新建」）。
- **提示条（Banner）**：用于覆盖率提示与无答案预警，**橙色**但**非阻塞**，可关闭。

## 5. 数据与状态的处理（本 PRD 最需产品判断的部分）

> 背景（实测）：7,945 题；有答案 3,973（50%）、有解析 4,639；**年级 82%、教材 82%、章节 64% 为「待补充」**；**难度 100% 为空（未标注）**；知识点为「**提及**」口径（平均 4.26 标签/题，最多 33）；待复核公式 **196 条**（UNSUPPORTED 185 / EMPTY 7 / FAIL 4）；题库目前**只读**。

### 5.1 元数据缺失 82% → 筛选器怎么表现？

**建议方案：显式暴露「待补充」桶 + 覆盖率提示 + 默认不预选。**

- 左侧筛选栏**每个维度的选项后显示计数**，并**单列一个「待补充 (n)」选项**（如 `年级：八年级下册 (420)`、`待补充 (6,549)`）。老师可主动筛出"缺元数据"的题去补。
- 每个维度旁显示**覆盖率徽标**，如「年级 17%（1,342/7,945）」，悬浮说明：「缺失元数据的题仍可被关键词检索命中，只是无法按此维度筛出。」
- **默认不预选任何值**（= 全库 7,945），避免老师误以为题库只有 1,342 题。
- 提供快捷开关「只看元数据完整 / 不完整」。

**理由**：达标报告明确指出「按年级筛选只能看到 1,342/7,945 题，**会漏题**」。若筛选器只列出有值的选项、隐藏缺失，老师会**系统性低估题库规模并漏掉 82% 的题**。把缺失显式化成「待补充」桶，等于把"数据欠账"转成"可操作任务"——而补元数据正是报告建议的下一步重点。**这是把风险变成入口，而不是掩盖风险。**

### 5.2 难度 100% 为空怎么表现？

**建议方案：显式「未标注」徽章 + 人工标注入口，绝不自动推断、绝不留白。**

- 难度筛选器显示为「全部（未标注 7,945）」；**不提供任何自动推断值**。
- 卡片/详情页难度位置显示**灰色「未标注」徽章 + 「标注」按钮**，而**不是空白**——空白会被误读为"简单/无难度"。
- 提供**单题标注 + 多选批量标注**入口（对应 P1-4）。
- 批量标注时弹出统一档位选择（档位标准见 Q5）。

**理由**：`bank/README.md` 明确「难度需教研组人工标注，系统只负责留空」，并已用回归测试锁死「不产生非未标注值」。产品上必须让"空"是**可见且可操作**的：渲染成空白或省略，老师会默认题"没有难度概念"；渲染成"未标注 + 可标注"，才既诚实又推动治理。

### 5.3 知识点「提及」口径要不要说明、怎么说才不误导？

**建议方案：必须说明，用大白话 + 反例；并给三态 + 严格模式开关。**

- 筛选栏该维度标签写作「**知识点（提及）**」而非「知识点」；悬浮说明：「系统自动识别题干中**出现过**的知识词，**不代表**本题在**考查**它（平均 4.26 个/题，可能误标）。」
- 详情页知识点标签**区分三态**：已确认（实心色）/ 待复核（描边 + 问号）/ 已否决（划掉或隐藏）。
- 提供「**仅看已确认知识点**」开关（对应 `--kp-confirmed-only`），**默认关闭**（否则复核完成前检索不可用），开关旁显示「已确认 x / 待复核 y」。
- 在知识点评审页给出**反例提示**：「例如一道『原子结构』题因选项出现『太阳系』被打上『太阳系』标签。」——让老师直观理解「提及 ≠ 考查」。

**理由**：README 反复警告「口径必须分清，否则会误导」，并给出真实误标（题 id=4）。把「提及」直接当「考查范围」筛选，会系统性误伤。措辞（加"提及"二字）+ 三态可视化 + 严格模式开关，三者缺一不可：**措辞**防误读，**三态**让治理进度可见，**开关**让"要严谨"和"要能用"两种需求各得其所。

### 5.4 196 条待复核公式如何呈现？

**建议方案：独立页面 + 全局可见但不阻塞的计数提示 + 可清零的处理动作。**

- **待复核公式队列页**按状态分 tab：`UNSUPPORTED 185` / `EMPTY 7` / `FAIL 4`。
- 每条展示：**预览图**（`preview`）、所属题干上下文、来源文件、状态与原因（`reason`）。
- 全局（首页统计卡 / 侧边栏）显示「待复核 **196**」，点击直达队列——**可见但不弹窗阻塞**。
- 处理动作：「标记已处理」（回写 `review_queue.resolved`）或「跳到该题修公式」（进详情页编辑态）。
- 统计页显示「已处理 / 待处理」进度。

**理由**：196 条是报告判定的「**中**」级问题——不阻塞主链路，但影响公式正确性。它必须**可见、可清零、可追踪进度**，而不是埋在日志里。分 tab 是因为三类原因（不支持 / 空 / 失败）处理方式不同。

### 5.5 答案覆盖 50% 如何呈现？

**建议方案：徽章化 + 可筛选 + 组卷/导出两处主动预警。**

- 检索结果卡与详情页用**徽章**显示「有答案 / 无答案」「有解析 / 无解析」。
- 筛选栏提供「**仅看有答案 / 有解析**」开关（组卷选带答案的题时用）。
- **组卷右栏**：汇总区显示「无答案 N 题」；当答案模式选了「答案解析版」而卷中仍有缺答案题时，给橙色 Banner 预警。
- **导出预览**：逐题标注「⚠ 本题无答案/解析，解析版将只显示题干」。
- 统计页显示答案/解析覆盖率（3,973 / 4,639 / 7,945）。

**理由**：50% 覆盖率是硬事实，且导出侧行为已确定（**库中无答案的题不硬造**，解析版只显示题干）。老师出解析版时**必须在组卷阶段就知道哪些题缺答案**，否则导出后才发现、返工。徽章化 + 两处预警，把"事后发现"变成"事前可见"。

## 6. 待确认问题（不要自己拍板）

| # | 问题 | 影响 |

| **Q1** | **「留旧版」的存储机制**：现有 `question_versions` 只存题干文本，**不含公式/答案/解析**。用户要求编辑公式也留旧版 → 是**扩展该表**（加 `formulas_json`/`answer`/`analysis` 快照列）还是**新增 `formula_versions` 表**？ | 直接影响 schema 迁移与编辑功能工作量（最大风险项） |

| **Q5** | **难度分级标准**：几档？命名（易/中/难 三档？还是 5 档？）需教研组定义 | 影响标注入口与筛选器 |

| **Q7** | **导出预览保真度**：需与最终 DOCX 像素级一致，还是近似即可？ | 影响预览实现成本（前端排版引擎） |

## 7. 工作量提示（供排期参考）

我认为工作量最大的 3 项：

1. **在线编辑的「留版」机制（P1-1/2/3/11）** —— 需扩展 schema（现表不含公式/答案快照）、重算 `content_hash`/`plain_text`、同步 FTS、处理唯一约束冲突。**产品复杂度 + 工程复杂度双高**，且强依赖 Q1/Q3/Q4 的决策。
2. **公式「渲染 + 编辑」双模（P1-5 / 3.4）** —— `⟦Fn⟧` 与 `fid` 的精确映射渲染、KaTeX 实时预览、LaTeX 写回与错误处理、`needs_review` 复位，前后端一致性要求高。
3. **双栏组卷的实时状态同步（P0-6/7/8/9）** —— 加入/拖拽/重排/分值/大题分组/实时总分，且要把「快照锁定」这一底层语义**如实**映射到 UI（题目更新但试卷不变 + 手动刷新），状态管理最复杂。

> 次要但影响面广的是 **P0-13 数据状态可见性体系**：单个组件工程量不大，但贯穿所有页面，需统一设计徽章/覆盖率/预警组件。
